## 目标

**把 `docs/` 下每一份文档都过一遍，让它们与"当前的代码与事实"一致，并且彼此不打架。**

这个项目反复栽在"**同一件事有两个数字/两处权威**"上（实测记录）：
- `主题设计大纲.md` 里素材数有 **319 / 344 / 355** 三个数字
- "**单次动效 ≤400ms**"这条约束**在仓库里找不到出处**（全文搜只搜到一处无关的 `400ms`）
- `UI控件清单.md` 把 `btnCanSniffer` 记在连接页（实际在 `fragment_pid.xml`）
- `CHANGELOG` 里 v1.20.8 的标题曾被 v1.20.9 覆盖掉

所以这次的目标不只是"更新数字"，而是**建立"哪份文档对什么负责"的秩序**。

---

## 要做四件事

### 1 · 逐份体检
对 `docs/` 下**每一份**文档，回答：
- **它还准吗？**（版本号 / 控件数 / 素材数 / 文件数 / 行数 / 路径 —— 与代码实测核对）
- **里面的"待做"还有效吗？**（有些已经做完了；有些已经放弃了；有些是别人的地盘）
- **里面的"已完成"还成立吗？**（有没有回归）
- **链接/路径还对吗？**（⚠️ **ICarUI 改名后 `tools/theme-studio/` 的引用要全部更新**）
- **它引用的别处还在吗？**

⚠️ **不许改历史**：`CHANGELOG.md` 的历史条目、带版本号的历史叙述（如大纲 §2.24/§2.29/§2.45）
**保留原样** —— 那是事实记录，不是错误。

### 2 · 跨文档一致性
- 同一个数字在几处出现 → **只留一处权威，其余指向它**（或写"见 X"）
- 同一件事在几处描述 → 同上
- **列一张"权威表"**：`主题设计大纲.md` 对什么负责 · `UI控件清单.md` 对什么负责 ·
  `UI样式与排版总表.md` 对什么负责 · `FILE_MAP.md` 对什么负责 · ……
  **避免两份文档都声称自己对同一件事有最终解释权**

### 3 · 补上缺口
- **新建一份 `docs/README.md`（文档索引）**：**我该看哪份？**
  （按角色分：接手的人 / 改 UI 的人 / 做主题的人 / 上车验证的人 / 找历史的人）
  —— 现在 `docs/` 有几十份文档，**新人不知道从哪开始**
- 把散落在各处的"**已知但没做**"汇总成一处（很多已经记在 `迭代清单.md` / `控件库优化建议.md` /
  `知识库审校.md` / `下一步-*.md` 里，需要**合并去重**）
- ⚠️ **已被证伪/已放弃的方向要明确标注"已放弃 + 原因"**（如"实时调参"那条：
  单位 bug + 用户否掉），否则下一个 agent 会再踩一次

### 4 · 收尾核对
- `FILE_MAP.md` 的文件数/行数**与实测一致**（含 ICarUI 改名后的路径）
- `迭代清单.md` 的版本表**与 `git log` 一致**
- 所有 `下一步-*.md` 里**已经做完的**要标"已完成"或合并进 CHANGELOG

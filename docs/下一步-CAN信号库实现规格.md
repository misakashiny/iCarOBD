## 1. 已定决策（原来的 6 个待定项）

| # | 项 | **决定** | 理由 |
|---|---|---|---|
| 1 | 执行顺序 | **S1 → S2 → S3 → S4**，S5 独立可插队 | S1 零运行时风险且立刻能用；S2 让值不骗人；S3/S4 依赖前面建立的字段；S5 独立 |
| 2 | 轮换参数 | **8 段（`0x000`~`0x700`）× 每段 10 秒**，一轮约 **90 秒**（含换段 AT 开销） | 10 秒能让 2.1 Hz 的信号采到 ~20 帧、1 Hz 采到 10 帧；再短会漏掉慢周期报文。要更快另做「快速 5 秒」模式 |

| 4 | 候选默认 | **已确认 → `enabled=true`；候选 → `enabled=false`** | 候选进监听会制造噪音（P10-1 刚修过同类问题）；而且"未验证的值显示在仪表上"正是"被骗"的来源。已知代价：往返会丢"这条被手动关掉的已确认信号"这一区别（见 §6） |

## 2. 五步（每步独立可验收）

### S1 · 导出 / 导入信号表（**零运行时风险，先做**）

| 做什么 | 细节 |
|---|---|
| 修 BOM | `CsvRecorder` 首次写文件前 `appendText("\uFEFF")` |
| 「导出观察表」 | 沿用 `CanFrame.Accumulator.aggregateCsv()`，但改成**中文表头 + BOM + 加 `报文ID(dec)` 冗余列** |
| 「导出信号表模板」 | 25 列（§3.1），**每个观察到的 ID 一行**，预填：报文ID(hex)/dec、DLC、**观察到的取值集合**；其余留空 |
| 「导入信号表」 | 读 CSV → 逐行校验（§3.4）→ 生成 `PidDefinition(source=monitor)` → 写 `Store.customPids` |
| 入口 | 设置页「导入画布 / 导出画布」那一行下面，或 CAN 探测页底部（**建议放探测页** —— 探测完就在那儿） |

**验收**：探测 20 秒 → 导出模板 → 在 Excel 填一行（拿 `0x09A` 试：起始位 18、长度 1、Intel、unsigned、因子 1）→ 导回 → PID 列表出现一条监听型 → 开常驻监听 → 拨转向灯 → 该 PID 有值、仪表能绑。

### S2 · 运行时的三个语义（**让值不骗人**）

| 语义 | 实现 |
|---|---|
| **DLC 守卫** | `FrameMonitor.feedLine`：帧长度 < `minDlc` → **不解析**，记一条 `信号跳过 \| 原因=DLC不足 需要=N 实际=M` |
| **无效原始值** | 解析出原始值后先比 `invalidRaw` → 命中则 `VehicleBus.put(PidValue(..., ok=false))` |
| **新鲜度** | `PidValue` 加 `ttlMs`；`VehicleBus.get()` 判 `now - ts > ttlMs` → 返回 `ok=false` 的副本 |

**为什么这么设计（已核实）**：`VehicleBus.value()` 与 `DashRenderer` **都是 `ok` 才给值** → 让超时/无效变成 `ok=false`，**仪表自动显示 `--`、规则不误触发、CSV 记空**，下游零改动。

**验收**：手工构造一帧 `raw=FF` 的水温信号 → 仪表显示 `--`（**不是 207℃**）；停掉广播 2 秒 → 值变 `--`；发一帧短于 `minDlc` 的 → 日志有"DLC不足"，值不变。

### S3 · 录入界面（不导表也能手建监听 PID）

`PidEditorActivity` 补：`source`（poll/monitor）、`header`（CAN ID）、`invalidRaw`、`minDlc`、`ttlMs`。
> 这是当前最大的空白：**全 app 只有 2 条内置监听 PID，用户连第三条都造不出来**。

**验收**：手工填 `header=09A` + `公式=bit(C,2)` → 保存 → 常驻监听能用。

### S4 · 探测页解码显示（**"看得懂"**）

探测时对每个收到的帧，用 `header` 匹配已有的监听 PID → 直接显示
`0x2C7 → 油温 88℃（候选）`，并显示 **DLC 够不够 / 距上次收到多久 / 是否命中无效原始值**。

> **不需要新数据模型**：拿已有 PID 的 `formula` 解帧即可。所以这一步很便宜。

**验收**：开着监听时探测页显示物理值而不是 hex；未绑定的 ID 显示原始 hex（不假装）。

### S5 · 分段轮换扫描 + 帧率闸（**独立，可插队**）

| 做什么 | 细节 |
|---|---|
| 分段轮换 | 复用现成的 `ATCM700 + ATCF<段>`（`FrameMonitor.filterPlan` 已有这段），8 段 × 10 秒自动换段，汇总成「整车 ID 清单」 |
| **帧率闸（必须一起做）** | 把切行/解析挪到**工作线程**，只把结果 `post` 回主线程 |

**为什么帧率闸不能省（已核实）**：`onRawChunk` 是 `main.post{}` 到主线程的
（`BleTransport:605` / `SppTransport:291`）→ 不过滤时**每秒上千次主线程解析**；
2026-10-06 12:06 已经因此 ANR 过一次。轮换必然经过大流量段。

**验收**：一轮 90 秒后得到一张"哪些 ID 在说话 + count/changed/取值集合"的表；
轮换期间**无 ANR**、UI 不卡。

## 3. 数据结构规格

### 3.1 信号表 25 列

前 17 列**沿用宝马参数总表的列名与顺序**（便于和网络资料互通），后 8 列是我们补的。

| # | 列名 | 必填 | 示例 | 映射到 `PidDefinition` |
|---|---|---|---|---|
| 1 | 报文ID(hex) | ✓ | `0x09A` | `header`（去 `0x`、大写、补足 3 位） |
| 2 | 报文ID(dec) | 可选 | `154` | 校验用（与 1 不一致 → 软警告） |
| 3 | 报文名 | 可选 | `TurnSignals` | `group`（列表按报文分组，一举两得） |
| 4 | DLC | ✓ | `2` | 校验用；也是 `minDlc` 的兜底 |
| 5 | 发送节点 | 可选 | `FRMFA` | 进 `note` |
| 6 | 信号名 | ✓ | `LeftTurn` | `name` |
| 7 | 起始位 | ✓ | `18` | 生成公式 |
| 8 | 长度(bit) | ✓ | `1` | 生成公式 + 推 `minDlc` |
| 9 | 字节 | 可选 | `B2` | 校验用（不符 → 软警告） |
| 10 | 字节序 | ✓ | `Intel(LE)` / `Motorola(BE)` | 生成公式 |
| 11 | 符号 | ✓ | `unsigned` / `signed` | 生成公式 |
| 12 | 因子 | ✓ | `0.25` | 公式乘数 |
| 13 | 偏移 | ✓ | `-48` | 公式加数 |
| 14 | 最小 | ✓ | `0` | `minVal` |
| 15 | 最大 | ✓ | `255` | `maxVal` ⚠️ **不是编码范围**（见 §7） |
| 16 | 单位 | 可选 | `rpm` | `unit` |
| 17 | 接收节点 | 可选 | `XXX` | 进 `note` |
| 18 | **可信度** | ✓ | `已确认` / `候选` | `enabled`（已确认=1，候选=0） |
| 19 | **证据** | 可选 | `2026-10-07 0x09A changed=13` | `note` |
| 20 | **无效原始值** | 可选 | `255` | `invalidRaw` |
| 21 | **显示超时(ms)** | 可选（默认 2000） | `2000` | `ttlMs` |
| 22 | **周期(ms)** | 可选 | `100` | 进 `note` |
| 23 | **值表** | 可选 | `0:关,1:开` | 进 `note`（v1，见 §6） |
| 24 | **多路复用条件** | 可选 | `ST_SW_LEV_RPM=2` | 进 `note` + 导入时**软警告**（本版不判断选择位） |
| 25 | **观察到的取值集合** | 仅模板 | `00 00 00 00 88…` | **导入时忽略** —— 它是给人看的提示 |

> 第 25 列是**模板的核心价值**：它正是 `turn-signal-09A.md` 里那个判据
> （"操作开关 → 看取值集合变了哪一位"）的自动化。印在模板里，人就不用自己翻 hex。

### 3.2 `PidDefinition` 只加 **3** 个字段

```kotlin
/** 原始值等于它 → 视为无效（ok=false，仪表显示 --）。null = 不判断 */
var invalidRaw: Int? = null,
/** 解码这条信号至少需要几个字节（0 = 不检查）。帧更短就跳过并记日志 */
var minDlc: Int = 0,
/** 值的新鲜度上限(ms)，超时视为无效（0 = 不判断）。只在 source=monitor 上有意义 */
var ttlMs: Int = 0,
```

**三个默认值都等于旧行为 → 零迁移。**

> ⚠️ 这是对 `PidDefinition` 的又一次加字段 —— 它已经是"上帝对象"（见
> `下一步-主题工具与仪表盘重构.md` §2.2 步骤 5 记的债）。将来真做分组时，
> 这三个应该和 `header` 一起进一个 `CanSignal` 子对象。

### 3.3 其余列怎么落（不进字段，进 `note`）

`note` 是自由文本，**v1 用它承载"只记录不参与运行时"的列**，格式固定便于再导出：

```
信号表|报文名=TurnSignals|DLC=2|周期=100|发送=FRMFA|接收=XXX|值表=0:关,1:开|复用=ST_SW_LEV_RPM=2|证据=…
```

- 前缀 `信号表|` 标记"这条来自信号表"（再导出时能识别）
- **只写非空项**，避免噪音
- 解析失败不报错（`note` 本来就是给人看的）

### 3.4 导入校验

**硬错误 → 整行拒绝**（汇总提示，不静默）：

- `报文ID(hex)` 非法 / `信号名` 空 / `起始位`/`长度` 非数或 ≤0 / `长度` > 32
- `字节序` 或 `符号` 不认识 / `因子` = 0
- **按字节序算真实位集**后超出 `DLC*8`（⚠️ **不能用线性 `起始位+长度`**，Motorola 是锯齿位序 —— 这条判错会误报，见 §7）
- `最小 > 最大`

**软警告 → 照收但提示**：

- `报文ID(dec)` 与 hex 不一致 / `字节` 列与 `起始位` 不符
- `无效原始值` ≥ 2^`长度`
- 同一报文内**位重叠**
- 带 `多路复用条件`（本版不判断选择位）
- `单位` / `证据` 空

**重复导入**：按 `(header, 信号名)` 去重 **覆盖**，不新增 —— 否则每导一次 PID 列表翻一倍。

### 3.5 公式生成：**给公式语言加一个通用位段函数**

现在 `bits(v,start,len)` 只能取**单字节内**的位，`be16/le16` 只管 16 位 —— 所以
**非字节对齐且跨字节的 Motorola 信号、以及 >16 位的 Intel 信号，现有语言表达不了**。

**决定：加一个通用函数**，一次解决所有位序/位宽组合：

```
bitsAt(起始位, 长度, 字节序, 符号)     字节序 0=Intel(LE) 1=Motorola(BE)   符号 0=unsigned 1=signed
```

- **可行性已核实**：`Formula.Parser(private val data: ByteArray)` —— 求值器手里**有整帧**，
  所以这个函数能自己按位序遍历，不需要调用方把字节拼好传进来。
- 于是**任何一行信号表都能生成公式**，不存在"表达不了"的行。
- 公式形态：`bitsAt(18,1,0,0)`；因子/偏移非 1/0 时接 `* 0.25 + -48`。

> ⚠️ 与现有 `bits(v,start,len)` 名字太像 → **要么改名为 `bitsAt`（推荐），
> 要么在知识库和报错文案里把两者区别写清**。别让下一个人用错。

## 6. 已知取舍与遗留

- **可信度往返有损**：`已确认/候选` 映射到 `enabled`。若用户手动关掉一条**已确认**的信号，
  再导出会被写成「候选」。要精确往返就得加 `role` 字段 —— v1 不加。
- **值表只进 `note`**：`PidDefinition` 没有 `valueLabels`（只有 `GaugeItem` 有）。
  v1 不做；将来要么给 `PidDefinition` 加，要么明确"值表属于仪表不属于信号"。
- **多路复用不解释**：带 `多路复用条件` 的行照收 + 软警告，但**运行时不看选择位** ——
  值可能是无效的。这类报文要真支持，得先有"选择位"概念。
- **周期只记录**：`note` 里，运行时不用。将来做"采样率检查"（"这条 2 Hz，你每秒采 1 帧，看不见"）时才需要它进字段。
- **S5 的轮换是"摸一遍"不是"抓全"**：得到的是聚合级（存在 + 变化次数 + 取值集合），不是每一帧。
  真要抓全 → 换适配器（CANable / RPi+MCP2515），那是独立的一条路。

## 7. 陷阱清单（别重犯）

1. ⚠️ **判"解到帧外"不能用线性 `起始位+长度`**。Motorola 是**锯齿位序**：
   实测按线性判据在宝马表上报了 2 条越界，重算真实位集后**都是误报**
   （`ST_OBD_CTFN_GRB` 实际只占 bit56~60、`setMe_0xFC` 只占 bit24~31）。
2. ⚠️ **`最小/最大` 不是编码范围**。实测 48 行的 `最大` ≠ 2^长度−1
   （`Counter_*` 写 14、`Checksum_*` 写 0、1 位的 `AccOn` 写 255）。
   **做掩码只能用 `长度(bit)`。**
3. ⚠️ **CSV 不带 BOM 会让 Windows Excel 中文乱码**。本项目 `CsvRecorder` 就踩了（S1 修）。
4. ⚠️ **`setMessage` + 列表 = 列表整个消失**（v1.20.1 实测）。导入结果/校验汇总的对话框
   **不要用 `setMessage` + `setItems`**，说明进标题或改成自定义 View。
5. ⚠️ **别把"观察"和"结论"塞进同一张表**：Excel 里难看，程序解析也容易错。两个文件。
6. ⚠️ **`onRawChunk` 在主线程**（`main.post{}`）。S5 不做帧率闸就是主动撞 ANR。
7. ⚠️ **`source=monitor` 期间轮询是停的**（ELM327 半双工）。别在文档里承诺"同时看"。

> **这是 `docs/` 的入口索引。** 接手项目请从 [`接手大纲.md`](接手大纲.md) 开始读；

> 最后核对：**2026-10-11**（App `v1.20.20` / versionCode 89 · ICarUI `v2.84.0`）。
> **体检报告见文末 [附录 A](#附录-a--逐份体检报告)** —— `docs/` 下每一份都有一行结论。

   **只补回缺失的那一行**，不动正文（本轮补 v1.20.8 标题就是这么做的）。

   "以前写的是 319 / 344"）—— 那是"这个数字曾经错过"的记录，改了反而丢了教训。
6. **已放弃的方向要进 §4**，写清**真实原因**（不是"看起来不好"）。
7. 改完 `docs/**` 后跑一次 `tools\check-build-guard.ps1`（它会查文档里的破折号是否成对等格式问题）。
8. **改完 `docs/**` 跑一次死链守卫：`node tools\check-doc-links.js`**（**v2.85.0 起常驻**，
   也挂在 `tools\run-all.ps1` ③，默认开）。查 `docs/**/*.md` 的两类相对链接：
   **Markdown 链接**按所在目录解析；**反引号里的路径**按 `{所在目录, 仓库根, docs/}` 多基准兜底。
   失效 → 打印 `文件:行 + 链接 + 解析到的绝对路径` 并**非 0 退出**。
   ⚠️ **豁免只有一条路**：写进 `tools/doc-link-allowlist.json`，按 **(文件, 链接原文)** 精确匹配，
   **每条必须写 `reason`**（缺 reason 即失败）。**历史归档 / CHANGELOG 历史条目里的失效链接
   是刻意保留的**（改它 = 改历史，见上面第 4、5 条）—— 但"有清单"不等于"全放过"：
   同一个文件里**新出现**的失效链接照样红。守卫自己不会静默跳过：清单读不到、JSON 坏了、
   扫到的链接数低于金丝雀阈值，**一律算失败**。
   > 上一轮体检（v1.20.20）就是靠临时脚本一次揪出 3 处路径错误（`主题设计大纲.md` 的
   > `../../tools/icarui/…` 少/多一层、`迭代清单.md` 指向已改名的 `tools/theme-studio/`）。
   > 但临时脚本扫完就没了 —— v2.85.0 才把它变成常驻守卫。
9. **改完浏览器套件（`tools/icarui/tests/verify-*.js`）跑一次 `tools\run-browser-tests.ps1`，
   断言数不得低于基线**（v2.85.0 起逐个套件核对，红则 `exit 4`）。
   基线是 `tools/icarui/tests/expected-counts.json`：**每个套件名 → 最少断言数**（下限，不是等值 ——
   加断言不用管）。它守的是"**断言静默消失**"：`if (常量) eq(...)` 在常量改名后整条不执行，
   而套件照样打印 `PASS=<n> FAIL=0`（v2.84.0 人工体检扫出 6 处，已修）。
   ⚠️ **合法地删/改断言**时用 `tools\run-browser-tests.ps1 -UpdateBaseline` 重建基线
   （会打印每个套件的增减）—— **不许手改 JSON**：手改没有 diff 输出，下一个人查不到是谁放低了基线。
   **新增套件必须同时更新基线**（不自动加入：自动加入等于让下限 = 它第一次跑出来的数，
   而那个数本身可能正是"断言被包住了"的结果）。基线读不到 / JSON 坏了 / 基线里的套件本轮没跑
   / 冒出不在基线里的新套件 → **一律失败**。

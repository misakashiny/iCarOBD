## 2. 家里电脑上要做什么

### 2.1 四个用户级环境变量

| 变量 | 值 |
|---|---|
| `JAVA_HOME` | `C:\Android\jdk21` |
| `ANDROID_HOME` | `C:\Android\Sdk` |
| `ANDROID_SDK_ROOT` | `C:\Android\Sdk` |
| `GRADLE_USER_HOME` | `C:\Android\gradle-home` |

> ⚠️ **`GRADLE_USER_HOME` 必须是纯 ASCII 路径。**
> 这是踩出来的：默认的 `C:\Users\<中文名>\.gradle` 会让 Gradle 的 worker 参数文件路径带中文，
> 报 `ClassNotFoundException: GradleWorkerMain` —— **单测全红，而测试 XML 里却是 550/0**
> （看起来像"通过"，极具误导性）。

### 2.2 ⚠️ 中文路径 → ASCII 联结（本机踩过，必须照做）

项目路径上面有中文用户名。**JVM / NDK / CMake 处理中文路径会出问题**，
本机建了三个联结（junction，管理员 cmd）：

```cmd
mklink /J D:\icarobd "C:\Users\<你的用户名>\Desktop\iCarOBD"
mklink /J D:\sdk     C:\Android\Sdk
mklink /J D:\jdk     C:\Android\jdk21
```

**构建一律在 `D:\icarobd` 下做。** 如果家里电脑的路径本来就全 ASCII，可以跳过这步。

### 2.3 编译

```cmd
set JAVA_HOME=C:\Android\jdk21
set ANDROID_HOME=C:\Android\Sdk
set ANDROID_SDK_ROOT=C:\Android\Sdk
set GRADLE_USER_HOME=C:\Android\gradle-home
cd /d D:\icarobd
gradlew.bat assembleDebug testDebugUnitTest
```

**预期：`BUILD SUCCESSFUL` + 单测 `TOTAL=563 FAILED=0`。**

### 2.4 装机

```cmd
adb install -r -d dist\iCarOBD-debug-v1.19.16-android.apk
```

### 2.5 改完代码必跑的三个校验

| 命令 | 期望 |
|---|---|
| `gradlew.bat testDebugUnitTest` | **563 全过** |
| `powershell -NoProfile -ExecutionPolicy Bypass -File tools\check-build-guard.ps1` | 通过（**1 条警告** = 已知缺口） |
| `node tools\theme-studio\tests\verify-crosslang.js` | `PASS=104 FAIL=0` |

### 2.7 ⚠️ 批量改文档/脚本时的两个致命坑（本机各踩过一次）

**这两个都"不报错、不影响运行"，只是悄悄改坏字** —— 只能靠 `git diff` 发现。

**① PowerShell 单元素数组会被展平 → 变成"按字符替换"**

```powershell
# ❌ 这样写：只有一对时，$pairs 被展平成 2 个字符串
$pairs = @( @('本仓库路径是 …', '新路径') )
foreach ($pr in $pairs) { $t = $t.Replace($pr[0], $pr[1]) }
#   $pr 变成字符串 → $pr[0]='本'、$pr[1]='仓' → **每个「本」都被换成「仓」**
#   实测：脚本→脚仓、本仓库→仓仓库、根本→根仓
#   另一例：配对以 '-' 开头 → 每个连字符被换成空格 → 一份 500 行的文档改了 490 行

# ✅ 前置逗号防展平；或者干脆用 edit 工具逐处改
$pairs = @( ,@('本仓库路径是 …', '新路径') )
```

**② 编辑工具会静默抹掉 `.ps1` 的 UTF-8 BOM**

`[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`
写出来的**没有 BOM** → PS 5.1 按 GBK 解码 → 中文注释吃掉行尾。
**写法：先探测原文件有没有 BOM，用 `UTF8Encoding($hasBom)` 原样写回。**

> **两条都靠同一个判据兜住**：改完立刻
> ```powershell
> git diff --numstat      # 行数应与预期相符（改 1 处就该是 1 行）
> powershell -ExecutionPolicy Bypass -File tools\check-build-guard.ps1   # BOM / 编码
> ```
> **改动行数远超预期 = 被字符级替换了** → `git checkout -- <文件>` 重来。
> 这也是"**动手前先提交**"的实际价值：有对照才能一眼看出，也能一键回滚。

```powershell
# 换机后照这个顺序做（本机实测通过）
Get-Item D:\icarobd -Force | Select-Object LinkType,Target   # ① 确认指向新拷贝
cmd /c rmdir D:\icarobd
cmd /c mklink /J D:\icarobd "D:\AI Dsh\车机项目\iCarOBD2"
Remove-Item D:\icarobd\app\build\test-results\testDebugUnitTest\*.xml -Force   # ② 删陈旧结果
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-tests.ps1        # ③ 强制真跑
```

**本机实测结果（2026-10-06）**：

| 项 | 结果 |
|---|---|
| `assembleDebug` | ✅ BUILD SUCCESSFUL |
| `testDebugUnitTest` | ✅ **TOTAL=563 FAILED=0**（删掉 32 个陈旧 XML 后**真实执行**） |
| `check-build-guard.ps1` | ✅ 通过（1 条警告 = 14 个控件未绑定，已知缺口） |
| `verify-crosslang.js` | ✅ **PASS=104 FAIL=0** |

> **教训**：`run-tests.ps1` 报的 `TOTAL` 来自**磁盘上的 XML**，不是"这次跑过"。
> 换机、或任何"构建产物被一起拷过来"的场合，**必须先清 XML**，
> 否则会把上一台机器的通过当成本机的。判据是「测试任务**不是** `UP-TO-DATE`」。

## 3. 会话记录能通用吗

**能搬，但不保证 `resume` 得起来** —— DSH 的会话是**按"工作区路径"分目录**的：

```
C:\Users\大青虫\.dsh\sessions\
  └── --C-Users-~5927~9752~866B-Desktop-iCarOBD--\     ← 目录名 = 工作区路径的编码
        └── session-47e64321-d21a-4381-9ed0-b9a3893529ad\
              └── session.v4.jsonl.zstd                  ← 3.7 MB，zstd 压缩
```

**目录名编码规则**（`C:\Users\大青虫\Desktop\iCarOBD` → `--C-Users-~5927~9752~866B-Desktop-iCarOBD--`）：

- 非 ASCII 字符 → `~` + 4 位十六进制 + `~`（大=`5927`，青=`9752`，虫=`866B`）
- `:` 和 `\` → `-`
- 首尾各加 `--`

**操作步骤：**

1. 把 `~\.dsh\sessions\` 整个拷到家里电脑的 `%USERPROFILE%\.dsh\sessions\`
2. 家里电脑的项目路径**大概率不一样**（用户名不同就会不一样）→
   把那个目录**改名成对应编码**。例如项目放 `D:\icarobd` → 目录名改成 `--D-icarobd--`
3. 试 `dsh` 的恢复/继续命令

> ⚠️ **只拷 `sessions\`**，不要拷 `.credentials.yaml` 之类的凭据文件 —— 凭据不该跨机复制，
> 家里那台自己登录。
>
> ⚠️ **跨"程序端 → CLI"我没有实测过**，所以：**别把它当成交接的必要条件**。

### 4.2 🎯 本次最大成果：转向灯

> **CAN `0x09A` 第 3 字节（`A B C…` 里的 `C`）：`bit(C,2)` = 左转，`bit(C,3)` = 右转。**

实车确认：两次探测**各自只有 2 个不同取值**，正好差一位。
证据链与复现步骤：[`../stage/oncar-evidence/turn-signal-09A.md`](../stage/oncar-evidence/turn-signal-09A.md)

**三条关键教训**（都写进 CHANGELOG 了）：

1. **采样率是前提，不是细节。**
   适配器只漏出约 **77 帧/秒**，而总线有约 **80 个 ID** → **每 ID 每秒 1 帧**，
   1.4 Hz 的闪烁**根本还原不出来**。加 CAN 过滤器后才变成 20 帧/秒。
   **判断"能不能看见一个信号"之前，先算 `适配器帧率 ÷ 目标 ID 广播频率`。**
2. **随机出现 ≠ 因果。** 两次把"只在某一次冒头的 ID"当成信号（那些网络管理帧），
   都在查了全日志之后被推翻。**判据必须"可复现"，不是"这一次有"。**
3. **数据到了 ≠ 有人消费。** `命中=114` 但一点声音都没有 ——
   规则引擎是**轮询周期**驱动的，而 `ATMA` 期间轮询是停的。
   这类 bug **光看数据侧完全看不出来**。

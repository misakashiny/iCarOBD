## 2. 交互（用户已确认）

| 项 | 设计 |
|---|---|
| **入口** | **设置页一个开关**「控件检视」（仪表盘设置页，与「手势」「灵动岛」并排） |
| **开启后** | 屏幕上出现**悬浮窗**（可拖动、半透明、浮在最上层） |
| **点控件** | 悬浮窗**立即**显示该控件的信息（见 §3）；**被点的控件描边高亮** |
| **长按悬浮窗** | 把全部信息**复制到剪贴板**（方便贴给作者） |
| **关闭** | 再点一次开关 → 悬浮窗消失、触摸恢复正常 |

**只看不改**（用户明确要求）—— 不要做"运行时改样式"。

## 3. 显示哪些信息（用户已确认"足够了"）

```
┌──────────────────────────────┐
│ Button                       │  ← 类型（简单类名）
│ btnGestures                  │  ← ID（资源名；无 id 时显示"（无 id）"）
│ 尺寸 120×40dp  边距 8/8/0/0  │  ← 宽高 + 四边 margin
│ 内边距 12/12/12/12           │
│ 字号 14sp  色 #E8EEF7        │
│ 背景 @drawable/bg_input      │
│ 可见 VISIBLE  可用 true      │
│ 层级 LinearLayout > Scroll…  │  ← 父链（从根到该控件的路径）
└──────────────────────────────┘
```

⚠️ **拿不到就明说"（无）"，不要编**（例如 `wrap_content` 控件没有固定宽高 → 显示实测像素值并标注"实测"）。

**可选加**（如果便宜）：`layout_weight` / `gravity` / `maxWidthDp`（`MaxWidth*` 那个属性）。

## 4. 硬约束（**违反就是 bug**）

1. ⚠️ **只在检视模式抢触摸** —— 平时**完全不介入**，否则会挡住画布横滑与编辑态拖拽
   （本项目为此栽过：v1.20.4 的"把手"贴在屏幕边缘，总误触系统手势）
2. ⚠️ **不改任何布局** —— 悬浮窗用**浮层**（`WRAP_CONTENT` 挂 `android.R.id.content`），
   **不许动 `activity_main.xml` / `fragment_dash.xml`**
   （v1.20.12 那个 P0 的触发条件就是"父容器重排 → 画布重建 → 表盘 0×0"）
3. ⚠️ **不盖画布** —— 悬浮窗可拖动；且默认位置别压在画布中心
4. ⚠️ **与现有浮层共存** —— 灵动岛（顶部居中）、监听警示条（顶部）都在上面；
   检视窗默认放**底部或侧边**，别和它们叠
5. **出口要明显** —— 关掉后必须能恢复正常触摸（否则用户会以为 App 坏了）

## 5. 与 `UI样式与排版总表.md` 的配合（**这是这个功能真正的价值**）

检视器给的是 **id**（如 `btnGestures`），用户拿这个 id 去**样式总表里搜** →
立刻拿到 **`文件:行` + 全部样式值 + "改了会出事"的坑**。

所以：
- 检视器里**必须显示 id 的资源名**（不是数字）—— 用 `resources.getResourceEntryName(id)`
- 样式总表里**每个 id 都要能被搜到**（已经满足：255 个 id 逐个写了 `文件:行`）
- 建议在检视窗底部加一句提示：**「搜这个 id 到 UI样式与排版总表.md」**

## 6. 实现要点（供参考，不强制）

- **怎么拿到"被点的是哪个控件"**：
  - 方向 A：检视模式下用一个**覆盖全屏的透明 View** 接住触摸，再用坐标**自己遍历 View 树**找最上层可见的、包含该点的控件
  - 方向 B：重写 `Activity.dispatchTouchEvent`（本项目已有先例：`MainActivity` 的双指手势就是旁听不消费），
    在检视模式下**消费**触摸并解析命中的 View
  - ⚠️ 无论哪种，都要处理**浮层自己**（点悬浮窗不应被当成"点控件"）
- **拿属性**：`view.javaClass.simpleName` / `id` → `getResourceEntryName` /
  `width,height,padding*,layoutParams.margin*` / `TextView.textSize,currentTextColor` /
  `background`（`getResourceName` 可能拿不到 → 退化成类名） / `visibility,isEnabled`
- **单位**：像素 → dp/sp（用 `displayMetrics.density` / `scaledDensity`），**标注是"声明的"还是"实测的"**
- **单测**：把"像素→dp/sp 换算"与"父链字符串拼装"抽成**纯函数**再测
  （View 本身在 JVM 里碰不得，与 `FrameRateGate`/`CanvasRebuildPolicy` 同一套路）

## 7. 验收判据

| # | 判据 |
|---|---|
| 1 | 设置页开「控件检视」→ 出现悬浮窗；关掉 → 消失且**触摸恢复正常** |
| 2 | 点一个**有 id 的控件** → 悬浮窗显示正确的**类型 + id 资源名 + 尺寸/边距/字号/颜色** |
| 3 | 点一个**没有 id 的控件** → 显示"（无 id）"，**不崩、不空白** |
| 4 | 被点控件**描边高亮**，能一眼看出点中的是哪个 |
| 5 | **检视模式下横滑画布不翻页**（触摸被消费）；**关掉后横滑恢复正常** |
| 6 | **画布尺寸不受影响**（用像素统计证明画布没重排/没消失） |
| 7 | 悬浮窗**可拖动**、**不盖住灵动岛与监听警示条** |
| 8 | 长按悬浮窗 → 剪贴板里是完整信息 |

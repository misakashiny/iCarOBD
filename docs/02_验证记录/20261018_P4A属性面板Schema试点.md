## 一、P3D 遗留核验

### 发现并修复一个阻断性 Bug：双击/点击添加从未工作

`catalog-panel.addToCanvas` 调 `addNode(node)`（1 参数），
而签名是 `addNode(nodes, node, parentId)`（3 参数）→ 抛错被 catch 吞掉 → **静默返回 false**。

P2B 端到端测试只覆盖了拖拽，没测双击添加，所以长期未发现。

修法：新增 `js/ui/insert-control.js` 统一插入适配层，三入口共用。

修复后实测：
| 入口 | 宽度 |
| --- | --- |
| 双击/点击添加 | **150** |
| 拖拽 | **150** |
| 统一适配层 | **150** |
| Registry.build（契约） | 240 |

多画布比例回归 4 种全部通过。

### 其他核验

- 像素案例 43 个（28+12+2+1），与报告一致
- `__controlKey` **不进序列化**，保存重载后必然丢失 → 识别改用 `type + trackStyle`

## 二、架构

五个组件：SchemaResolver / SchemaRenderer / PropertyAccessor /
PropertyValidator / PropertyUpdate。

`registry/` 零改动、`panels.js` 零改动。

## 三、性能（60 控件场景实测）

| 指标 | 旧面板 | Schema 面板 |
| --- | --- | --- |
| 单次刷新 | 0.310 ms | **0.0080 ms（38.8×）** |
| 刷新后同一 DOM | ❌ 重建 | ✅ 原位 |

旧面板本身就快，**真正收益是"不重建 DOM"** —— 那是焦点丢失、光标跳位、
拖动被截断的根因。

## 四、受控编辑 4 字段

orient / segments / glow / fill，11 行中恰好 4 个可编辑。
null 保持真 null（不误转字符串）；非法输入不写入模型；
连续拖动 10 步只产生 1 条撤销。

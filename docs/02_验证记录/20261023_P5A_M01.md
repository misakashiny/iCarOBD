## 修掉的真实缺陷（2 个）

### 缺陷 1【严重】拒绝蓝牙权限 → App 崩溃

**根因**：Android 14 对 `FOREGROUND_SERVICE_TYPE_CONNECTED_DEVICE` 要求
manifest 声明 **且** 持有 `BLUETOOTH_CONNECT`/`SCAN` 之一。
用户点「不允许」→ `SecurityException` → 在 `Service.onCreate()` 无人接 → **FATAL**。

**实测复现**：撤销两权限后启动 → crash buffer **2 条 FATAL**。

**修复**：三段降级（带类型 → 无类型 → 放弃前台但不崩），不吞异常。
**验证**：修复后 FATAL 数 = **0**，App 正常存活；新增 5 项单测钉住决策。

### 缺陷 2【中】模拟 `step` 参数空转

**根因**：`step(n)` 只 `tick++` + `SignalSimulator.tick()`（重写通道），
但场景通道是 `WAVE_CONSTANT`（min==max），重写值不变；
真正算值的 `applyScenario()` **没被调用**。

**实测**：`--ei step 0` 与 `--ei step 20` 回显完全一致（`std_0C=860` 两次）。

**修复**：每 tick 重新 `applyScenario(scenario)`。
**验证**：修复后 `std_0D 62.1→57.9`、`std_05 90.5→91.5`。

### 修掉的自身问题

1. 像素指纹用 FNV-1a 64 位 → PowerShell `[uint64]` 遇负数抛异常。改双累加器。
2. C2 第一版"等 4 秒看画面变" —— 前提错：`tick` 是手动步进，不自动循环。
3. C2 第二版以为 `--ei step 0` 能归零 —— `tick` 累加，必须 `off` 再 `normal`。

## 一、分类原则

按任务要求，每项归入四类：

| 类别 | 判定依据 |
|---|---|
| **A. 自动化行为测试可验** | 能用 CDP 真实操作 DOM / 读取真实数据完成 |
| **B. 自动化视觉测试可验** | 能生成真实截图，但**判定仍需人眼** |
| **C. 必须真机人工操作** | 涉及 Android 真实渲染、触屏手感、真实设备 |
| **D. 当前环境无法验证** | 需硬件/权限/数据，本轮没有 |

> ⚠️ **A 类通过 ≠ 用户人工验收通过**。GUI 卡片状态一律保持「未验收」，

## 四、最小人工操作清单

> 目标：**用最少的连续操作覆盖全部 36 项需人工确认的内容**。
> 按「一次进入某环境 → 连续完成多组检查」组织。

### 场景 1：【Windows 浏览器】一次打开，约 15 分钟

| 步骤 | 操作 | 覆盖项 |
|---|---|---|
| 1.1 | 打开 `tools/icarui/index.html` | — |
| 1.2 | 选中一个**仪表**，看属性面板：23 行是否完整、色带与子部件编辑器是否可用 | P4E-GUI-001 ①②、P4F-GUI-004 ③ |
| 1.3 | 加 2 段色带 → 改颜色/透明度 → 删除 1 段；点「按阈值生成」看结果 | P4F-GUI-004 ①② |
| 1.4 | 加 2 个子部件 → 用 ↑↓ 调顺序 → **看画布上谁压谁**变了 | P4F-GUI-004 ④⑤ |
| 1.5 | 连续按 Ctrl+Z / Ctrl+Y 各 3 次 | P4F-GUI-004 ⑦ |
| 1.6 | 点保存 → **刷新浏览器** → 看色带/子部件是否还在 | P4F-GUI-004 ⑧、P4R-GUI-001 ④ |
| 1.7 | 选中**普通图片** → 素材下拉选另一张 → 看画布是否立即换图且**没有变糊** | P4F-GUI-002 ①②③、P4R-GUI-001 ①②③⑥ |
| 1.8 | 改宽度、高度，看画布边框变化 | P4F-GUI-002 ④ |
| 1.9 | 选中**条形轨道** → 改圆角/刻度/渐变 → 看效果是否符合预期 | P4F-GUI-001 ①②③ |
| 1.10 | 选中**文字** → 改内容/宽度/高度 | P4F-GUI-003 ①② |
| 1.11 | 选中**容器** → 改 scale，看**子控件是否跟着放大且相对位置不变** | P4F-GUI-003 ③④ |
| 1.12 | 对照 `screenshots/` 目录下的 `track-01-plain.png` 至 `track-10-glow.png`（共 10 张） 看 10 种轨道效果是否正确 | P4F-GUI-001 ④–⑨ |

| 步骤 | 操作 | 覆盖项 |

## 五、本轮环境限制记录

| 限制 | 影响 |
|---|---|
| 当前 AI 模型**不支持图像输入** | 无法自行判读截图内容，只能生成证据 |
| Android 设计文件走 **SAF 系统文件选择器** | 难以全自动注入测试设计 |
| 已连接设备是 **Meta Quest 3（VR）** | 非目标设备；已另建 AVD 模拟器（Android 14 / 1080×2400）|
| 无 PID 数据源 | 状态灯与仪表数值无法自动驱动 |

> 已在模拟器上完成：APK 构建（7.2 MB）、安装、启动、UI 结构确认（`dashPager` / `canvasRoot` / `gaugeGrid`）。

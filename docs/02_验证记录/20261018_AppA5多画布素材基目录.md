# T-App-A5-BASEDIR：多画布素材基目录并存

日期：2026-10-18（Asia/Shanghai）
任务：`T-App-A5-BASEDIR`（问题清单 `App-A5 / P1` 的核心缺陷）

## 一、用户视角：修的是什么

**给「画布 1」导入了一套素材，切到「画布 2」后它的素材全都不见了**（盘面空白、背景消失）。

问题清单原文（第 39 行）：

> `| App-A5 / P1 | 多画布素材基目录、背景覆盖、资源引用和可迁移包 | 按引用图/双画布同路径/失败保配置验收，保护旧设计 |`

## 二、缺陷定位

| 事实 | 位置 |
|---|---|
| 素材基目录是**全局单值** | `Store.settings.designBaseDir: String`（`Store.kt:79`） |
| 画布是**多套**的 | `settings.canvases`，上限 `DashCanvas.MAX_CANVASES = 8` |
| `DashCanvas` **没有** baseDir 字段 | 它有 `designJson` / `bgImagePath`，唯独没有基目录 |
| `switchCanvas()` **不碰** `designBaseDir` | `Store.kt` 只做 snapshot → 换 id → load → save |

### 后果链

```
画布1 导入素材 → designBaseDir = files/design/<ts1>
切到画布2（也有自己的素材）→ designBaseDir 仍是 <ts1>
  → 画布2 的相对路径素材全部解析失败
  → NodeTreeRenderer 记进"素材缺失"报告
  → 用户看到：切过去之后盘面是空的 / 背景没了
```

## 三、修复

### 3.1 数据层：字段下沉到画布

`DashCanvas` 新增 `designBaseDir: String = ""`：

- `toJson()`：**空串不写**（与 `designJson` 同一约定），避免老画布一存盘多一行噪音
- `fromJson()`：缺省空串 → 交给迁移逻辑

### 3.2 Store：切换时双向同步

| 函数 | 新增 |
|---|---|
| `snapshotToActiveCanvas()` | 全局 → 画布（**只在全局非空时覆盖**） |
| `loadActiveCanvas()` | 画布 → 全局 |
| `migrateLegacyBaseDir()`（新） | 旧配置迁移 |

### 3.3 一个关键的取值：为什么 snapshot 要"非空才覆盖"

第一版写的是无条件 `c.designBaseDir = settings.designBaseDir`，**测试立刻红了 3 条**：

```
切换画布后 designBaseDir 跟随目标画布    expected: </data/a> but was: <>
两套画布来回切换互不覆盖                  expected: </data/dirA> but was: <>
切到无基目录的画布再切回来值仍在          expected: </data/a> but was: <>
```

**根因**：切换画布的瞬间，全局值可能还是空的（新建画布、备份导入后未同步等），
无条件覆盖会把本画布**已经记下的有效目录清空** → "切出去再切回来，素材全没了"。

**真实编辑不会因此丢失**：导入素材时会同时写画布与全局两处，snapshot 时两者一致。

### 3.4 旧配置迁移

`migrateLegacyBaseDir()` 的规则：

- 全局值非空 → 才能迁移
- **已存在任何一套画布自带基目录 → 不动**（说明是新配置或已迁移过）
- 只迁到**首套画布**：老配置无法反推素材属于哪一套，迁到首套最保守
- 幂等：多次调用结果相同

调用点放在 `applySettingsJson` 里、`loadActiveCanvas()` **之前** —— 顺序错了会先被清空。

### 3.5 导入素材时写两处

`CanvasSettingsFragment.pickAssetDir` 现在同时写：

```kotlin
val canvas = Store.activeCanvas()
canvas.designBaseDir = dest.absolutePath
Store.settings.designBaseDir = dest.absolutePath
```

### 4.2 用例清单

| # | 用例 | 守什么 |
|---|---|---|

## 六、未做 / 未验

1. **"可迁移包"（把素材打包进设计包）不做**：问题清单把"可迁移包"与"基目录"并列，
   但那是**新格式方向**，需要独立设计与验收。本卡只解决已确认的多画布覆盖缺陷。
2. **真机多画布切换未验**：全部为 JVM 层验证，设备观感需授权后另验。
3. **`bgImagePath` 的跨画布覆盖**：问题清单原文提到"背景覆盖"，本卡只处理了基目录；
   背景图路径本身已存在 `DashCanvas.bgImagePath` 里（per-canvas），
   但"背景覆盖"是否指遮罩层尚未核实，**留待后续**。
4. **资源引用校验**：问题清单提到"资源引用"，本卡未新增引用完整性检查。

## 两项风险核验

### A. `verify-next-library` 缺 `production.png`

**根因**：不是缺测试素材，是**遗留的调试截图写盘**。
L54 的 `writeFileSync` 写到 `stage/t11i-codex-20261012/`（被 gitignore、别的机器不存在），
且**在全部断言之后**执行 —— 没有断言依赖它。

**修复**：改写到 `os.tmpdir()` + 补一条断言（PNG 非空）。
结果：90+1失败 → **91+0**（断言数还增加了）。

### B. 未知字段安全透传

方案见专题 32：推荐**显式 `ext` 扩展位**，不用全局透传。
**本阶段未修改 `nodeToJson`**，只提交方案 + 测试样例。

## 构建 Catalog 时踩的四个坑（都已在代码注释里写明）

1. 构建早于 `panels.js` → `ensureBuiltinAsset` 未定义 → 104 素材无 assetId
2. 构建早于 `app.js:init()` → `design.canvas` 为空 → 15 个 next_* 全失败
3. 每条探测后立即恢复状态 → 下一条查不到路径 → 素材全落「其他」
4. `assetId` 是内部 id 不含路径 → 需反查 `design.assets`

最终方案：`panels.js` 之后构建 + DOMContentLoaded 轮询 + **整轮快照恢复** + 路径反查。

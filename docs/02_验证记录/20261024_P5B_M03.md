## 阶段 A：前台服务兼容性安全复核（22/22）

### 官方规则核对

| 项 | 值 |
|---|---|
| minSdk / targetSdk / compileSdk | **24 / 34 / 35** |
| 前台服务类型 | `connectedDevice\|dataSync` |
| 启动入口 | `MainActivity.startServiceSafely()` → `startService()` |

**Android 15+ 对 dataSync**：每 24 小时累计 6 小时上限；超时回调 `onTimeout`，不处理会 ANR/崩溃；
**targetSdk ≥ 35 才强制**（当前 34，暂不受限）。

### 设计变更（按指令 §A2 的三条硬规则）

| 情况 | P5B-M02（旧）| **P5B-M03（新）** |
|---|---|---|
| 有蓝牙权限 | `CONNECTED_DEVICE` | `CONNECTED_DEVICE`（**完全不变**）|
| **无蓝牙权限** | `DATA_SYNC` 保活（**滥用**）| **不进前台服务**（不占 FGS 配额）|
| 后来授权 | — | `onResume` 主动补起 |

### 🔴 修的两个真实缺陷

**缺陷 1【严重，我自己引入的】**：无权限时用 `stopSelf()` 满足 `startForegroundService` 的 5 秒契约
→ 实测 `ForegroundServiceDidNotStartInTimeException` **崩溃**。
**真相**：系统只认 `startForeground()`，`stopSelf()` 无效。
**修法**：调用方改用 `startService()`（无 5 秒契约）。

**缺陷 2【中】**：授权后前台服务不恢复。
原因一（测试方法）：`am start` 到已 resumed 的 Activity 不触发 `onResume`；
原因二（真实缺陷）：恢复只在 `onStartCommand`，Activity 常驻时不触发。
**修法**：`onResume` 里主动 `startServiceSafely()`（幂等）。

### 设备端 22/22

A0 有权限 count=1 / **A1 无权限 count=0（不占 FGS）** / A2 无轮询空转 /
A3 授权后 HOME 往返 → count=1 / A4 5 次前后台切换无残留 / A5 3 轮反复无残留 /
A6 `onTimeout` 已重写 / A7 恢复。

### Undo 的五轮踩坑（全部记录在脚本注释）

1. 推 `JSON.stringify(S.design)` → 结构不对（真实格式 `{d, sel}`）
2. 用 `nodes[idx]` → 快照恢复后下标失效
3. 先 push 再改属性 → undo 回到更早状态
4. 以为多次 push = 多步可退
5. **真因**：**首次 commit 就是基准**（`init: index=0, size=1, canUndo=false`），`undo()` 返回 `stack[index-1]`

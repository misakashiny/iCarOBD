# T-UI-EXPORT-02 App 导出设计文件保真（v2 原文直出）

日期：2026-10-17（Asia/Shanghai）
任务：`T-UI-EXPORT-02`
前置：`T-UI-HUD-01`（HUD 动效原型 + 工具侧接入）

## 一、问题是什么

App 内「导出当前布局为设计文件」（`CanvasSettingsFragment.exportDesign()`）原来固定调用
`DesignFile.toJson()`，而那个序列化器**只认 v1**：

```kotlin
put("gauges", JSONArray().apply { gauges.forEach { put(it.toJson()) } })
```

它**不写** `nodes` / `assets` / `parts` / `states` / 字体 / 旋转 / 图层。

后果：v2 设计的完整闭环是断的 —— **在电脑上做好 → 导入设备 → 想回电脑继续改，导出的文件是残缺的**。
丢失范围**不止动画**，所有 v2 特性都会丢。

`DesignFile.SCHEMA` 注释里"v2 渲染还没做，导出 v2 会产出画不出来的文件"这个保守理由
**已过期**：App 侧 v2 渲染自 v1.11.0/v1.12.0 完成，本会话已实测 v2 盘面正常显示。

## 二、我先纠正了一个错误判断

上一张卡（`T-UI-HUD-01`）收尾时我说过"工具里编辑的子部件导出后会在 App 里全部丢失"。
**实测后确认这是错的**，真实情况是：

| 方向 | 是否丢 |
|---|---|
| 工具 → App（导入设计文件） | **不丢** —— App 存的是原文（`designJson`） |
| 工具内保存 → 再打开 | **不丢** —— `model.js:842` 的 `nodeToJson` 确实写 `parts`，anim 也随之写出 |
| **App 导出 → 再导入** | **丢** —— 就是本卡修的这条 |

实测证据（`toV2Json` 序列化一份带 anim 的设计）：`HAS parts: true`、`HAS anim: true`。

## 三、方案（用户确认 A：原文直出）

新增 `DesignExporter`（`data/DesignFile.kt` 末尾）：

```kotlin
object DesignExporter {
    fun isReusableV2(rawDesignJson: String): Boolean   // 解析出 schema 且 == icar.ui/2
    fun build(rawDesignJson: String, fallback: DesignFile): String
    //   v2 原文 → 原样返回；否则 → fallback.toJson().toString(2)
}
```

`exportDesign()` 改为 `DesignExporter.build(canvas.designJson, d)`。

### 三个刻意的设计决定

1. **判据是解析 schema，不是 `contains("icar.ui/2")`**
   原文里可能只是某个字符串字段碰巧含这串字。用 `contains` 会把一份 schema 其实是 v1 的
   文件误判为可直出，导出自相矛盾的内容。**有专门用例守这条。**

2. **原文直出而不是重新序列化**
   原文里可能有 App 当前版本还不认识的字段（工具侧先在用的新特性）。
   重新序列化会**静默抹掉**它们。直出零损失。

3. **抽成纯函数是为了能单测**
   原先这段逻辑埋在 Fragment 里，一行测试都写不了。

### 已知取舍（用户已确认接受）

**原文直出不反映 App 内的增量编辑** —— 例如在 App 里拖动了仪表位置，导出的仍是导入时的坐标。
项目的定位是「PC 上设计、设备上显示」，故可接受。

### 7.4 附带发现：分享给某些第三方应用会被 URI 权限拒绝

抓到一个**与本卡无关**的既有现象。用户用 MT 管理器（`bin.mt.plus`）打开分享的
`design.json` 时被拒：

```
E/DatabaseUtils: java.lang.SecurityException: Permission Denial:
reading androidx.core.content.FileProvider uri content://com.icar.obd.fileprovider/cache/design.json
from pid=25341, uid=10275 requires the provider be exported, or grantUriPermission()
```

**判断**：这是 `FileProvider` + `FLAG_GRANT_READ_URI_PERMISSION` 的既有行为，
不是本卡引入。代码里已经 `addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)`，
但该授权只对**通过这个 `ACTION_SEND` Intent 接收的组件**生效；MT 管理器是以
`ACTION_VIEW` 自行去打开 content URI，不在授权范围内。

**影响面**：文件本身**已正确写出且内容完整**；受影响的只是"选某些第三方文件管理器打开"
这条路径。通过微信/网盘/系统「保存到文件」等正常分享目标不受影响（本轮未逐个实测）。

**未修**：超出本卡范围（属分享链路健壮性）。如实登记，留给后续按需处理。

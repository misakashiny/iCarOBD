# T-UI-HUD-01 ICarUI 工具侧接入 · 验证记录

日期：2026-10-17（Asia/Shanghai）
任务：`T-UI-HUD-01`
本文记录把「持续装饰动画」从"只能手改 JSON"补成"可在 PC 工具里编辑并预览"的过程。

## 一、做了什么

前几轮把 App 侧的 `GaugePart.anim` 做完了（1/6/12 表性能已验证），但**工具侧完全缺位**：
用户看不到、也改不了，字段还没跨语言钉住。本轮补齐这四件事。

### 1. `schema.js` —— 字段定义与规范化

- `PART_ANIM_KINDS`：spin / pulse / sweep / drift（与 App 侧 `PartAnim.KINDS` 同序）
- `MIN_ANIM_PERIOD_MS = 400`、`MAX_ANIM_PERIOD_MS = 60000`
- `PART_ANIM_DEFAULT`：pulse / 2400ms / phase 0 / amplitude 1
- `normalizePartAnim(o)`：未知 kind 回落 pulse、周期夹到区间；**`null` = 无动画**
- `partAnimCycle(a, nowMs)`：与 App 侧 `PartAnim.cycle()` **同一公式**
- 接入 `PART_DEFAULT.anim = null` 与 `normalizePart()` 末尾

> 周期下限 400ms 与既有 `MIN_BLINK_MS` 同一条依据（WCAG 2.3.1：每秒不超过 3 次闪烁）。
> 装饰动画快到像闪烁，同样是驾驶安全隐患。

### 2. `verify-crosslang.js` —— 跨语言断言（关键）

在既有 `MAX_PARTS` 断言之后加了三组：

1. **kind 的名字与顺序**逐条一致（`kotlinConstList` 解析 `PartAnim.KINDS`）
2. **周期下限**一致，且断言 ≥400ms（顺带算 Hz）
3. **`cycle()` 公式**：4 组参数 × 7 个时间点交叉比对，工具与 App 结果差 <1e-6，且都落在 0..1

理由写进注释：单边改是**静默的** —— 只改 App 侧用户设了 60ms 却被抬回去；
只改工具侧老文件在 App 上报未知 kind 静默回落；**cycle 算法不一致会让"电脑上看到的
动画节奏和设备上不一样"**，用户只会觉得工具不准。

### 3. `panels.js` —— 编辑面板

部件展开体里、紧挨「静态旋转」下面加 `animPanel(i, q)`：
- 顶部一个「启用」勾选（关 → 写 `null`，不产生任何开销）
- 开启后显示：动画种类下拉、周期 ms（带 Hz 提示）、相位 0~1、幅度
- 加了一句提示区分「装饰动画（持续）」与「数值变化时的缓动」——
  用户极易混淆两者，标题与说明都刻意点明

位置选择：**紧挨"静态旋转"**。两者一个静态一个动态，放在一起便于对照。

### 4. `canvas.js` + `app.js` —— 预览播放

- `drawPartTree` 里按 App 侧同一套变换追加：spin 绕 pivot 再转、pulse 调 alpha、
  sweep 三角波往返、drift 双频正弦
- 新增**预览时钟** `ensureAnimPreview()`：每帧推进 `S.__animMs` 并重绘

三条不破坏现有行为的设计：
1. **只在真的存在 anim 部件时才跑** —— 没动画的设计零开销，不让工具一直 60fps 空转
2. 与既有 `S.anim` 让位仲裁并存：用独立 raf，不抢 `tween` 名字
   （它们动的是数值，动画动的是装饰，互不覆盖）
3. 可暂停（`window.toggleAnimPreview`）—— 编辑静态布局时不该被动画干扰

挂接点在 `refreshAll()` 末尾，因为它是所有设计变更的统一出口。

## 二、过程中抓到并修掉的真问题

### `verify-layout` 红了：CSS 字号继承

加完面板后 `verify-layout` 从 58/0 变成 57/1：

```
❌ 没有继承浏览器默认字号的元素（13.3333px）
   >>> 13.3333px 元素: ["INPUT < LABEL.chk < DIV.animHead < DIV.animBox | type=checkbox", ...]
```

**根因**：CSS 里复选框的尺寸规则限定在 `.prow` 内
（`.prow input[type=checkbox]`），而我的 `.animHead` 不是 `.prow`，
里面的 `<input type=checkbox>` 掉回浏览器默认 13.3333px。

**修法**：补 `.animHead input[type=checkbox]` 规则，并显式 `font: inherit`。
修完 `verify-layout` 回到 **58/0**。

> 这个断言很有价值：它把我"新加面板忘了给字号"这种**不会报错、不会让别的测试变红**
> 的隐性退化当场抓了出来。失败事实保留在此。

## 四、未验证

- **真实浏览器里的主观观感**：程序能证明"断言全绿""动画循环在跑"，但**面板好不好用、动画好不好看需人工目视**。
  本轮未做人工 UI 走查。
- **动画预览的帧率**：工具侧预览循环未做性能测量（App 侧已测：12 表 60.8fps 零掉帧）。
- 与设备端的**逐像素一致性**未做截图比对（只保证变换公式与 cycle 公式在同一套定义下）。
- `parts` 不回写 JSON 的既有缺口**未修**（属序列化改造，超出本轮范围）—— 意味着工具里编辑的子部件
  在导出后仍可能丢失，这个问题与本轮动画字段同源。

## 五、结论

工具侧接入完成：**用户可以勾选启用动画、选种类、调周期/相位/幅度，并在画布上实时看到效果。**

跨语言守卫已把 kind 顺序、周期下限、cycle 公式三方钉住，单边改会当场跑不过。

**下一件该做的事**是补 `parts` 写回 JSON 的缺口 —— 否则"工具里编好了、导出就丢"会让整个子部件
（含动画）功能失去意义。这需要单独开卡。

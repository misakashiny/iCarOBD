# T-UI-EXPORT-03 导出写入 Download/ICarOBD

日期：2026-10-17（Asia/Shanghai）
任务：`T-UI-EXPORT-03`
前置：`T-UI-EXPORT-02`（导出内容保真）

## 一、为什么改

上一张卡修好了导出**内容**（v2 原文直出，真机验证逐字符一致），但导出**路径**仍是
「写 `cache/` → 弹分享面板」。真机验证时暴露两个问题：

1. **分享给某些第三方文件管理器被拒**：`FileProvider` 的 URI 权限
   （`FLAG_GRANT_READ_URI_PERMISSION` 只对通过该 Intent 接收的组件生效）。
2. **分享面板里找不到微信**：平板实际**没装微信**（只有 `com.tencent.soter.soterserver`，
   那是微信的指纹服务组件），且 `type = "application/json"` 过窄 ——
   微信等应用不声明接收它。

用户决定：**不折腾分享链路，直接写到找得到的地方**。

## 二、技术方案与关键发现

### 直接写 `/sdcard/Download` 会被拒（实测）

```
adb shell run-as com.icar.obd sh -c 'echo test > /sdcard/Download/__t.txt'
→ sh: can't create /sdcard/Download/__t.txt: Permission denied
```

`targetSdk = 34`，Android 10+ 分区存储不允许应用直接写公共目录。

### 必须走 MediaStore，且要分两条路径

`minSdk = 24`（Android 7），而分区存储从 **API 29** 生效：

| API | 写法 | 原因 |
|---|---|---|
| ≥ 29 | `MediaStore.Files` + `RELATIVE_PATH = Download/ICarOBD/` | 分区存储下不能直接写公共目录 |
| < 29 | `Environment.getExternalStoragePublicDirectory` + `File` | `RELATIVE_PATH` 是 API 29 才有的列 |

**已实测 MediaStore 可行**：`content insert --uri content://media/external/file
--bind relative_path:s:Download/ICarOBD/` 成功创建了目录。

### 实现要点

新增 `data/DesignExporterFiles.kt`：

- `fileName(canvasName, stamp)` —— **纯函数**，可 JVM 单测：
  `ICarOBD_<画布名>_<yyyyMMdd-HHmmss>.json`
- `write(context, displayName, text)` —— 按 API 分支写盘
- `Result.Ok(uri, location, displayName)` / `Result.Failed(reason)`
- **`IS_PENDING` 原子性**（API ≥ 29）：写一半的文件不会以完整身份出现在文件管理器里；
  写失败会把半成品删掉，避免留空 json

`exportDesign()` 改为：

1. 先写 `Download/ICarOBD/`，成功则 Toast 告知完整路径
2. **写入失败也明确报错**，不静默当成功
3. **保留分享面板**（用户要求）：优先分享刚写的 MediaStore Uri；
   失败时退回 `cache/` 副本作为兜底载体
4. 分享 MIME 从 `application/json` 放宽（见 §五）

## 三、几个刻意的决定

1. **文件名带画布名 + 时间戳**
   同一画布多次导出**不互相覆盖** —— 只写固定 `design.json` 会把上一次冲掉，
   而用户往往想留几个版本对比。

2. **非法字符清洗**
   `/ \ : * ? " < > |` 与控制字符替换成 `_`，首尾空白与点去掉（Windows 上以点结尾会创建失败）。
   不清洗的症状是"文件创建了但在某些文件管理器/传输工具里看不到或被截断"。

3. **不申请存储权限**
   API ≥ 29 写 MediaStore 属 App 自己创建的媒体，无需 `WRITE_EXTERNAL_STORAGE`。
   项目 Manifest 至今没有任何存储权限，本轮也没增加。

4. **不硬编码微信包名**
   当前卡范围内只放宽 MIME（见 §五），不写 `com.tencent.mm` 这类脆弱依赖。

## 五、附带的 MIME 调整

分享 Intent 的 `type` 从固定 `application/json` 改为：

- 有 MediaStore Uri（API ≥ 29 正常路径）→ 仍用 `application/json`（语义准确）
- 退回 cache 兜底 → `*/*`（让系统列出所有能收文件的 App）

**理由**：`application/json` 太窄，很多应用（含微信）不声明接收它，于是**根本不出现在面板里**。
不硬编码任何具体 App。

⚠️ 这条**未在真机验证**：本机没装微信，无法确认放宽后微信是否出现。

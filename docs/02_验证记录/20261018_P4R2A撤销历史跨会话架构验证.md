## UndoStack 语义审计

| 项 | 结论 |
|---|---|
| `snapshot()` | `JSON.stringify({d:S.design, sel:S.selection})`；历史快照含 selection |
| `UndoStack` limit | 构造 limit=100；内存 `trim` 上限 limit+1=101 条 |
| 持久化 | `icar-studio-undo`；最多 40 条，另受 1,228,800B 预算 |
| index | 指向当前设计快照；depth()=index；新编辑先截断 redo 分支 |
| 合并 | 相同 coalesceKey 替换当前栈顶；endCoalesce 清 key |
| 普通新编辑 | splice(index+1)，截断 redo，再 push |
| `beginBatch/endBatch` | 起点压一次，结束 flush 最终状态 |
| `endLive` | 实时阶段不压栈；结束时回到 start 再 commit(end)，压成一步 |
| `reset` | 单条当前设计基准，index=0 |
| `loadUndoStack` | 仅函数定义及测试钩子，无正式启动调用；本阶段未接入 |

持久化只保存 `undo.index` 及之前最多 40 条；**redo 分支本来不跨会话保存**。内存可撤销步数可明显多于重载后的可撤销步数。

## 审计时发现并修复的预算绕过

**复现**：`saveUndoStack` 预算条件仅在 `parts.length > 0` 时执行。单条快照大于 1.2MiB 时，首条绕过预算；实测 5 张大图时 localStorage 写入约 1.7MiB，10 张时约 3.38MiB，均超过声明预算。

**修复**：首条也检查预算；单条本身超预算时跳过本次持久化，保留内存 UndoStack，不改变内存撤销语义。

**剩余行为**：超预算时旧 localStorage 历史可能留存，但锚点校验不能证明它对应当前草稿时会拒绝；P4R-2B 需考虑提示“设计已恢复、撤销历史未恢复”。

## 一致性锚点原型

隔离文件 `undo-anchor.js`：递归排序完整设计对象 key，保留数组顺序；从 snapshot 只取 `d`，排除 `sel`。使用 FNV-1a 作为**原型级一致性指纹**，不是密码学完整性证明。

fail-closed 条件：schema、designId、draftRevision、index、**每条** undo/redo 快照结构与 digest、当前 index 快照与恢复设计 digest 全部匹配。缺失 revision、越界 index、任意 redo 分支记录损坏都拒绝整个历史；应保留设计并 reset 为新基准。

正式测试：`verify-p4r2a-anchor-prototype.js` 19/19（18 类场景 + 模块加载）。该套件是**隔离原型验证**，不是正式历史加载功能。

## 三方案比较及原子性

Edg/155 headless、60 控件、22 条持久记录测量：

| 方案 | 写中位/P95 | 读中位/P95 | 原子性 |
|---|---|---|---|
| A localStorage | 2.8/3.5ms，同步 | 0.8/1.5ms | 草稿与历史不能原子提交 |
| B IndexedDB 独立事务 | 1.1/7.9ms，异步 | 0.2/0.3ms | 两笔事务可版本分离 |
| C 同库同事务 | 1.1/1.7ms | 同量级 | drafts + meta 同一 transaction 可原子提交 |

**推荐 P4R-2B 方案 C**。隔离验证证实 drafts 与 meta 可在一个 `readwrite` transaction；主动 abort 后两者均未提交。这证明平台事务机制可行，不代表现有产品已经保存历史。

## 旧 localStorage 兼容

格式仅 `stack,index,designName`，无可靠 `designId`、`draftRevision`、content digest。因此不按名称自动加载，不删除旧键；保留供诊断。若后续提供用户确认的导入，也只能作为当前设计新历史，不能声称恢复了原身份。

## 双标签页 E2E 原型

通过正式 `checkForDraft()` + `restorePending()`：

- A、B 都恢复同一 designId/revision=1。
- A 改设计并保存：成功到 rev=2。
- B 改另一属性保存：`reason=conflict, expected=1, current=2`。
- B 本地值仍是 x=222；另存独立副本后新 designId，原草稿保留。
- 历史锚点只验证，没有加载 UndoStack。

## 持久 tombstone 修复与 v1 升级

此前真实两标签页复现：删除 A 后 B 等 65 秒写入 `ok=true`，草稿复活；重启 B 后 CAS 才拒绝。为满足用户第八部分，升级 DB v1→v2 新增 `tombstones` store；删除和 tombstone put 同事务；saveDraft 同事务检查 tombstone + revision CAS。

修复后真实两标签页：65 秒后 B 保存返回 `tombstoned`；关闭重开 B 再保存仍 `tombstoned`；记录未复活。

隔离 v1 schema fixture（drafts+meta）升级到 v2（+tombstones）：已有 draft rev=7 和 legacy history 保留，新 store 初始为空。

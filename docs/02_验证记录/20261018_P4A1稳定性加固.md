## 二、修复 Schema 双源（任务第三部分）

P4A 初版 schema-props.js 内置了一份 TRACK_SCHEMA，同时 SchemaResolver
又会读 Registry —— 同一族两套字段表，且已产生偏差（内置多了 nullable）。

更严重的是：__controlKey 保存后必然丢失，所以**绝大多数情况下实际用的是内置那份**，
Registry 的 schema 形同虚设。

修复：删除内置表，只保留 Registry 一处。持久化能力只用来判族，
字段表一律从 Registry 取。可编辑清单移入 EDITABLE 表（只存路径）。

实测两条路径返回**同一个 Registry 对象**（sameObject: true）。

## 三、修复并行面板同步缺失（D-12）

旧面板改字段后走 refreshAll()，它只调 renderPanels→renderProps，
**不通知 Schema 面板**，导致新面板显示旧值（实测 model:12 / panel:5）。

修复：refreshAll() 追加 SchemaPanel.refresh()（+9 行），
放在 renderPanels 之后、draw 之前。

8 项同步测试全部通过。

## 六、端到端性能（60 控件，中位数/P95 ms）

| 路径 | 中位数 | P95 |
| --- | --- | --- |
| renderProps（旧面板纯刷新） | 0.5 | 0.8 |
| SchemaRenderer.update | ~0 | 0.1 |
| **refreshAll** | **33.7** | **69.9** |
| draw | 0.7 | 1.2 |
| 完整交互（新） | 42.3 | 53.4 |
| 完整交互（旧） | 51.3 | 64.7 |

**修正 P4A 报告的不准确表述**：38.8× 只是面板自身刷新耗时比，
属性面板只占完整交互约 1%。**真正瓶颈是 refreshAll（33.7/69.9ms）**。

新面板真正收益是**不重建 DOM**（0/10 次 vs 旧面板 10/10 次），
不是速度快 —— 那才是焦点丢失、光标跳位、拖动截断的根因。

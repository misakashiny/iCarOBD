# 20261018 P4C 容器属性面板

详见专题：[46_ICarUI_P4C容器属性面板](../01_专题/46_ICarUI_P4C容器属性面板.md)

## 一、group 识别范围（第二部分）

全库 215 条实测 **19 条产 group**：
  derived（Registry）4 条：group / box_card / box_row / box_col（0 子节点）
  probe（旧工厂）15 条：全部 next_* 组合预设（各 2 子节点）

运行时另有：手动组合（model.js:489）、历史导入、嵌套 group。

**关键依据**：w/h/rotation/alpha/locked/visible **全是 createNode 的通用基础字段**
（model.js 的 base 对象），任何节点都有，不是容器专有。

→ **不需要按 key 分派，不需要新增持久化字段**，type === "group" 一个判据就够。

实测：4 容器 / 15 next_* / 嵌套 / 手动组合 全部识别为 container；
text 与 gauge 不识别。

## 二、Schema 审计（第三部分）

distinctSignatures: **1**（4 条完全一致，与文字族 P4B 时的 2 种签名不同）。

Schema 共 7 字段：w/h/rotation/scale/alpha/locked/visible。
**本阶段只开放 6 个**，scale 保持只读（任务要求 6 个）。

UI 层未复制 CONTAINER_SCHEMA，containerSchemaFor 完全从 Registry 取。
registry/ 零改动。

## 三、六字段（第四部分）

w/h     min=1；拒 NaN/Infinity/负数/0/非数字
rotation **无范围限制**：-45/0/45/360/450 全部原样保留（含重载）
alpha   0~255；**255 保持 255 不被换算成 1**；拒 256/-1
locked  boolean；隐藏/锁定后节点仍在设计里（不是删除），可解回
visible boolean；同上

## 四、父子回归（第五部分，7 场景）

空容器 / 含文字 / 含图片 / 含仪表 / 嵌套 group / next_* / 历史导入嵌套
—— 全部通过。

关键断言：父容器改 w/h/rotation/alpha 后，**子节点局部坐标不变**。

**未引入自动布局或容器裁剪**（断言 autoLayout/clipChildren 均为 undefined）。

## 五、异常重复计数修复（第八部分第 1 项）

P4B.1 里 SchemaPanel.refresh 内部 +1、refreshAll 外层再 +1
→ 同一次故障算 2 次。

修复：内部只打标记不计数，统一外层计数。
实测一次故障计数 = **1**，原始 message 与 stack 均保留。

## 六、性能（第九部分）

容器属性修改**不重建 Schema DOM**（before===after）。
重复赋同值 **0 次 commit**。
20 子节点容器 refreshAll 中位数 **25.8ms** / 最大 32.7ms
（对照 P4A.1 的 60 控件 33.7ms —— 嵌套未让它变慢）。

# T-UI-HUD-01 科幻 HUD 动效原型 · 验证记录

日期：2026-10-17（Asia/Shanghai）
任务：`T-UI-HUD-01` 科幻 HUD 动效仪表原型（单表验证）
结论摘要：**机制可用、性能代价可接受（0% 掉帧）；但这是原型，不是成品。**

## 一、背景与判断

现有动画底座已有：共用 `GaugeTicker`、4 种缓动、霓虹 12 层、子部件系统。但 `stepFrame` 只在「数值过渡」与「报警爆闪」两种情况下返回 true：**数值一稳、报警一停，时钟就停，画面完全静止**。所谓"酷炫仪表"的核心不是数值动画，而是**持续装饰动画**（永不收敛，只要有东西在动）。

另发现 App 侧**没有**弹簧/物理动画（ICarUI 有 `spring.js` 33KB，App 侧零实现），但不属本原型范围。

## 二、实现内容

### 数据层 `data/DesignNode.kt`

- 新增 `PartAnim`：`kind`（spin/pulse/sweep/drift）、`periodMs`、`phase`、`amplitude`。
- `GaugePart.anim: PartAnim? = null`：**缺省 null = 完全无动画**，存量设计逐像素不变。
- 解析 `_parse`：未知 kind 回落 pulse 并警告；`periodMs` 夹到 `MIN_PERIOD_MS=400`（WCAG 2.3.1：每秒不超过 3 次闪烁，与 `NodeState.MIN_BLINK_MS` 同一理由与数字），上限 60000。

### 渲染 `ui/view/GaugePartsView.kt`

- 新增 `stepFrame(nowMs)`：有 anim 部件就按时间推进并 `invalidate()`，**返回 true 永不收敛**。
- `hasAnim` 惰性判定：无 anim 的设计 `stepFrame` 直接返回 false，**零开销**。
- `drawPart` 在静态布局之上追加时间偏移：spin 绕 pivot 匀速转、pulse 调 alpha、sweep 三角波往返、drift 双频正弦漂移。

### 驱动 `ui/dash/NodeTreeRenderer.kt` + `DashRenderer.kt`

- `NodeTreeRenderer` 新增自己的 `Handler` 时钟（`ANIM_FRAME_MS=16`），遍历 `partsViews` 推进；全部返回 false 即停止投递。
- 每个 `pv.isShown` 守卫：不可见不推进。
- `DashRenderer.start()/stop()` 接 `resumePartsAnimation()` / `stopPartsAnimation()`：**与 5Hz 取值时钟同一个页面激活边界**，非当前页不会 60fps 空转。

### 测试 `app/src/test/java/com/icar/obd/data/PartAnimTest.kt`

7 例全绿：缺省 null、四种 kind、未知 kind 回落+警告、periodMs 夹取+警告、cycle 周期性且 0..1、phase 偏移、parts 不回写（见 §五 缺口）。

### 4.3 动画真实在动（决定性证据）

间隔 800ms 连拍三帧，三帧**字节数与哈希均不同**：

| 帧 | 字节 | SHA256 前 16 |
|---|---|---|
| 1 | 245684 | `EAD100A9C353F0D3` |
| 2 | 250238 | `61E7AF037282AD75` |
| 3 | 229462 | `3E2E25762F4E511F` |

三帧互不相同 → 画面确实在动（不是静态渲染）。恢复动画后复测两帧 234626 / 238860 B，同样不同。

### 4.4 性能：A/B 对照（核心结论）

同一份设计、同一台设备、各 10 秒，仅切换「有/无 anim 字段」：

| 指标 | 有动画 | 无动画（对照） |
|---|---|---|
| 10 秒总帧数 | **608** | **0** |
| 实测帧率 | **≈60.8 fps** | 静止（不重绘） |
| Janky frames | **0（0.00%）** | 0 |
| 99th 帧耗时 | **8 ms** | 无（无帧） |
| Missed Vsync | **0** | 0 |
| Slow UI thread | **0** | 0 |

**两条结论同时成立**：
1. **动画确实在跑**（608 帧 vs 对照 0 帧），不是"看起来没动"。
2. **性能代价可接受**：60.8fps、99% 帧 8ms（预算 16.7ms，余量约 52%）、**零卡顿零掉帧**。

⚠️ **本测仅单表**。文档既有实测为「12 表 + 霓虹 9 层 = 零掉帧」；本原型未做多表叠加，**12 表同时动画的代价未测**，不能据此推断多表也安全。

## 五、发现的既有缺口（非本轮引入）

**`parts` 从不被写回 JSON**：`GaugePart.parseAll` 是唯一读写点，`DesignNode.toJson()` 不输出 `parts`，全项目没有对应写出路径。后果：「解析 → toJson → 再解析」会**丢失全部子部件**（连同 anim）。

`PartAnimTest` 里有一条用例**专门钉住这个现状**，断言 `back.nodes.first().parts` 为空，并在注释写明：若该断言失败说明缺口已补上，应移除用例并改成正向往返测试。真正修复属序列化/工具侧改造，超出本原型白名单。

## 六、未验证

- **多表叠加性能**：只测单表；12 表同时动画未测。
- **真实观感主观评价**：截图保存在项目外，**最终好不好看需用户目视判断**；程序只能证明"在动"与"不掉帧"。
- **旋屏/后台/跨会话**：未逐项验；`isShown` 与 `stopPartsAnimation` 的守卫逻辑已实现但未做切页/熄屏专项测量。
- **真车/适配器**：未涉及。
- **ICarUI 工具侧**：未做（`schema.js`/`panels.js`/`verify-crosslang.js` 均未改）→ 目前**不能**在工具里编辑动画，只能手写 JSON。

## 七、结论与建议

**技术上可行**：持续装饰动画能在现有架构上以极小代价实现（新增约 200 行，不改任何既有动画路径），单表性能余量充足。

**但不是成品**：
1. 工具侧完全缺位：用户无法编辑，只能手改 JSON。
2. 跨语言守卫未钉，字段属"单边存在"，违反项目"两边逐字一致"的铁律。
3. 多表性能未知，而真实盘面通常 6–12 表。
4. 车规安全：持续动态在驾驶场景需默认关闭 + 开关，本原型未做。

**建议下一步**（需另开卡）：
1. **先做 6/12 表叠加性能测试**：这决定能不能铺开。
2. 若性能过关，再补 ICarUI 编辑面板 + `schema.js` + `verify-crosslang.js` 断言。
3. 补全局开关（默认关闭）与可见性/熄屏专项验证。

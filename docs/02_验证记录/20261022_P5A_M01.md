**核心发现**：`VehicleBus` 是数据层与渲染层的唯一接口（源码注释明示）。
数据流：

```
ObdEngine → VehicleBus.put(source, PidValue) → get/value/snapshot（拉）
                                            → addValueListener（推）
      ↓
DashRenderer.pushValues() 每 200ms
  ├→ gauges     → BaseGaugeView.updateMulti
  ├→ trackViews → TrackView.setValue          ★本轮新增
  ├→ partsViews → GaugePartsView.setValues
  └→ stateCells → applyStates
```

### 🔴 修复 2 个真实缺陷

**缺陷 1：模拟源断开时 UI 不回落**

- 现象：`disconnect` 与 `warmup` 截图 MD5 **完全相同**
- 根因：`enable()` 每次清空 `writtenPids` → `markAllStale()` 遍历空集合
- 证据：`BUSD` dump 断开后仍全部 `ok=1`
- 修复：只有 `disable()` 才清 `writtenPids`
- 验证：截图 81835 → **56323 bytes**

**缺陷 2（重要）：条形轨道不随数据变化 —— P4F-M01 遗留**

- 现象：5 条轨道跨场景像素差异 **0.00%**（同屏仪表是 2.5%~8%）
- 根因：`buildTrack()` 只设静态 `trackStyle`，**没接 PID**；
  `TrackView` 无接值接口；`pushValues()` 不遍历轨道
- 影响：编辑器里调好的轨道只是「静态装饰」，永远画成设计时的比例
- 修复：
  1. `TrackView` 加 `setValue()` / `setValueRange()` / `effectiveFill()`
  2. `NodeTreeRenderer` 加 `TrackCell` / `trackViews`
  3. `DashRenderer.pushValues()` 增加轨道推值
  4. `DesignNode.TYPE_IMAGE` 读 `pid`（回落 `statePid`，**不新增字段**）
- 验证：差异 **0.00% → 23%~58%**
- 回归：`DesignNodeImagePidTest` 6 项

## 阶段 D：多分辨率（**14/14**）

| 环境 | 分辨率 | 形变系数 |
|---|---|---|
| 手机竖屏 | 1080×2400 | **0.475**（竖拉 52%）|
| 平板横屏 | 1600×1000 | **1.690**（横拉 69%）|
| 车载宽屏 | 1280×600 | **2.254**（横拉 125%）|

**根因**：`SCALE_STRETCH`（默认为 v1 契约）是**每轴独立缩放**。
**这不是宽屏特有问题** —— 竖屏手机也有 52% 拉伸。

**处置**：登记为**跨端兼容问题**（不是代码缺陷）。用户可写 `scaleMode:1` 换等比。

测完已 `wm size reset` / `wm density reset` 恢复，不覆盖用户配置。

## 六个仪表

g_speed(obd.speed→std_0D) / g_coolant(obd.coolant→std_05) /
g_fuel(obd.fuel_level→std_2F) / g_volt(obd.voltage→std_42) /
g_load(obd.load→std_04) / g_throttle(obd.throttle→std_11)

全部 dataCapability=bound、channelStatus=implemented、**vehicleStatus=unverified**。
**没有把"App 已实现 PID"当成"真车可用"。**

## 关键发现（D-06）

`createNode` 对 NODE_GAUGE 会把 `pid` 归一化成解析后 id（std_0D），
用户别名存在 `rawPid`（obd.speed）。这是既有设计，不是迁移引入。
写测试时踩到（14 条断言先红后修），已登记到 Debt 清单。

## 架构收敛证据

`catalog.js` 本阶段**零改动** —— 仪表通过既有的 derived 派生路径接入，
不需要新增任何 Catalog 逻辑。

## 数据源缺失行为

`build({pid:'obd.nonexistent'})` → 能构建、量程回落 0..100、
给出 `warn:pid-unresolved` 诊断。与旧行为一致，不崩不丢控件。

## 测试断言调整

p2b-catalog-ui / p3b-container-family 里硬编码的阶段数字改为结构性断言，
数字精确校验交由各阶段自己的套件守（避免"改数字就算通过"）。

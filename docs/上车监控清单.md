## 0.5 两个新工具（2026-10-06 上车后加的）

> 上一趟上车最大的教训是**采样率**：克隆版在满速总线上只漏出约 **77 帧/秒**，
> 摊到约 80 个 CAN ID 上就是**每个 ID 每秒 1 帧** —— 1.4 Hz 的转向灯闪烁**根本还原不出来**。
> 所以别急着怪"信号不在总线上"，先看这两个工具。

### 「CAN 探测」页的**过滤器**（`ATCRA` / `ATCM`+`ATCF`）

| 填法 | 效果 |
|---|---|
| `228` | 只放行单个 ID（内部发 `ATCRA228`） |
| `ATCM700+ATCF400` | 放行 `0x400~0x4FF` **一整段**（掩码过滤） |
| `ATCM700+ATCF000` | 放行 **`0x000~0x7FF` 全部 11 位 ID** —— ⚠️ **不是"只扫 0x0xx 段"**，别被段号误导 |
| 留空 | 不过滤（原行为） |

> **段号是 `ATCF` 的高三位**：`ATCF000` = 全总线、`ATCF100` = `0x100~0x1FF`、
> `ATCF200` = `0x200~0x2FF` … `ATCF700` = `0x700~0x7FF`。
> 所以想"只看某一段"就填 `ATCM700+ATCF<段>`（段 = 2/4/6，不是 200/400/600）。
> 界面上有 5 个预设 chip 可直接点（`228` 左转向灯 / `0x400~0x4FF` / 全部 11 位 / `7E8` OBD 应答 / 不过滤）。

**效果**：过滤后单 ID 采样率 0.7 帧/秒 → **20 帧/秒**（28 倍），总帧数 77 → 344 帧/秒。

> ⚠️ **过滤器会连带挡住正常 OBD 应答**（正常请求回 `7E8`，过滤器只放行指定 ID）。
> 收尾会自动重新初始化（`ATZ`）清掉；万一没清干净，到「连接」页重新初始化一次即可。
> 每趟结束都会打一行**健康检查**（`0100 有应答` / `⚠️ 无有效应答`）告诉你清没清干净。

### 「对比基准（找位）」—— 找广播帧里的信号位

| 步 | 动作 | 为什么 |
|---|---|---|
| 1 | 过滤器按段填好、采集 **20 秒** → **关闭**目标（如关门）跑一次 | 这一趟成为**基准** |
| 2 | **打开**目标 → **同参数**再跑一次 | 这一趟成为**当前** |
| 3 | 点 **「对比基准（找位）」** | 列出状态变化的位（`★` = 这次操作引起的） |
| 4 | 点该行 **「加为监听」** | 立刻变成可用的监听型 PID（`source=monitor`），**已启用** |
| 5 | ⚠️ **重启常驻监听**（先「停止」再「开启」） | 新加的信号**不会自动进当前这次监听** —— `signals()` 只在 `start()` 时读一次 |

**判据**：某一位在基准里 `恒0`/`恒1`、操作后变成 `在变` → **就是它**。
用"状态"比而不是"两个值 XOR"，因为单次采样会**撞相位**（1.4 Hz 的灯，采到亮还是暗是掷硬币）。

**对应日志**（**基准是"上一次探测"**，所以必须在**同一趟里连跑两次**）：

```
CAN 探测结束 | frames=… ids=… dropped=0 reason=…
CAN 差分     | 共 3 处，下面是前 20 处
CAN 差分位   | 9A 第3字节 bit2：恒0 -> 在变  公式=bit(C,2)   <== 这次操作引起的
```

> ⚠️ **两次探测必须同参数**（同一个过滤器、同一个采集时长）。
> 换了参数就不是"只动了目标那一件事"，差分出来的位不可信。
>
> ⚠️ **基准是"上一次探测"，跨会话会丢** —— 关机 / 重启 app / 中途插了别的探测，
> 基准就变成不是你想比的那一趟了。**两次对照要在同一趟里连着跑完。**
>
> ⚠️ **「清空」不会清掉基准**（有意的）：清空只扔掉"当前这一轮"，
> 基准只在**下一次 `start()`** 时才被提升。想在两次对照之间清空而不破坏对照，
> 这是唯一说得通的语义 —— 见 `CanSniffer.reset()` 的注释。
>
> ⚠️ **差分结果是"候选"不是"结论"**：每个 ID 只留 **8 个不同取值**，
> 稀疏变化的位可能被误判成"恒定"（漏报）。所以**加为 PID 后必须在真实操作下再确认一次**。

### 「开启常驻监听」—— 让广播信号真正喂给规则与仪表

它是**模式切换**，不是"顺便多收"：ELM327 **半双工**，`ATMA` 期间**轮询必须让位** ——
开着监听时转速/水温会**冻结在最后一个值**。停掉时会自动重新初始化（`ATZ`）。

**过滤器是自动选的**（不用手填）：

| 监听信号 | 自动发的命令 | 结果 |
|---|---|---|
| 只监听**一个** ID 段（如只有 `0x09A`） | `ATCRA09A` | 每秒只剩 2~11 帧，最干净 |
| 监听**同一段**的多个 ID | `ATCM700` + `ATCF0xx` | 整段放行，采样率够 |
| 监听信号**跨多个段** | **不加过滤器** + 明确提示 | ⚠️ 整条总线灌进来（344 帧/秒）→ 见下面那条 |

**判据（每 5 秒一行）**：

```
监听通道 | 帧=581 命中=114 信号=2 各ID[9A=581] | 帧率正常（116 行/秒）
监听信号变化 | 左转向灯(mon_turn_left) = 1
```

- `命中 > 0` = 公式真的求出了值（`帧` 大而 `命中=0` 是**另一个**问题：ID 没对上，见 §8 第 9 条）
- `各ID[...]` = **过滤器到底放行了谁**的唯一直接证据
- `监听信号变化` 每种信号最多 20 条（有界），是"这一位到底有没有在跳"的硬证据

**v1.20.6 起界面上看得见了**（P10-3）：监听期间**顶部会挂一条常驻警示**

```
监听中 · 轮询已暂停（转速/水温冻结）
```

不用翻页就能看到（`MonitorWarnBar`，挂在 Activity 的 content 上、不占布局）。
**看不到这条 = 监听没在跑**（或已经停了）。

> ⚠️ **跨 ID 段时加了帧率闸**（v1.20.6，P10-5）。监听信号跨段 → 加不了过滤器 →
> 整条总线的帧都会灌进**主线程**（本项目因为主线程堆积 ANR 过一次）。
> 现在的行为：超过 150 行/秒**自动按监听 ID 预筛**（不相关的帧连解析都不做），
> 超过 240 行/秒**整块丢弃**，并弹一条
> 「监听帧率过高（信号跨多个 ID 段，加不了过滤器）—— 请把监听拆成两次」。
>
> 日志里对应 `监听帧率过高，已介入` / `监听帧率恢复`。
> **看到"已丢弃 N 行"就说明信号会断续** —— 那时必须拆成两次监听，不要当它是数据噪声。

> ⚠️ **退出前一定要停掉**：它不会自己停。不停掉的话后续所有轮询都是冻结的，
> 而界面上只有那条警示条能告诉你原因。

## 4. ✅ 判据表（**看到什么 → 说明什么 → 怎么办**）

### 4.1 连接建立（**每次上车的第一步** —— 10-08 两趟就卡在这）

> ✅ 这一节的两条历史目标（GATT 竞态 / `ATCAF0`）**都已实车确认**，
> 现在它的作用是**每趟的健康检查**：**过不了就别往下做**（后面所有判据都要求"已连接"）。

| 日志 | 含义 | 怎么办 |
|---|---|---|
| **`CCCD 写入完成 \| status=0`** | ✅ **GATT 竞态修好了** —— 描述符写回调正常回来了 | 继续往下看 4.2 |
| `CCCD 回调丢失 —— GATT 栈已卡死` | ❌ 还有东西在抢 GATT 操作 | 把整份日志留下来（这是新证据）；**先断开重连一次**再试 |
| 成片的 `写入被拒` / `BLE 写入持续失败` | ❌ 栈卡住了（v1.18.1 前的症状） | 断开 → 重连 → 再初始化；若复现，记录 `写失败累计` 的**第一次**值 |
| 连 `已写 CCCD` 都没有 | ❌ 特征/描述符没选对 | 看 GATT 表段（`===== GATT 表开始 =====`） |
| **扫描设备时列表是空的** | ⚠️ 适配器**没被系统配对**（app 只连已配对设备） | 到**平板的系统蓝牙设置**里配对（适配器要在车 OBD 口上取电才会广播）—— 见文首那段 |

## 6. 扫描器：一次问清"这台车支持什么"

**这一步能同时回答"这台车支持哪些标准 PID"和"挡位/总里程在不在标准空间里"。**
（⚠️ 它**回答不了**"12 个指示灯在哪" —— 那些是广播帧的位，扫描器是**主动请求**，
看不见广播。找灯要走 §0.5 的「对比基准」。）

「PID」页 →「PID 扫描器」：

| 参数 | 值 | 为什么 |
|---|---|---|
| 模式 | `01` | 标准空间 |
| 范围 | `00` ~ **`C0`** | ⚠️ **必须是 C0** —— 挡位 `A4`、总里程 `A6` 在 A1~C0 段（v1.18.0 才修好这一段） |
| 勾选「支持位图」 | ✅ | 走 `01 00 → 01 20 → … → 01 C0` 全链枚举，**比范围扫描快得多** |
| 安全确认 | ✅ | 必须勾 |
| 黑名单 | 默认 | `01:02,01:03,01:07,01:0A` |

扫完点**「导出结果」**，把文件发出来。

> 重点关注：有没有命中 **`A4`（挡位）/ `A6`（总里程）**。
> - `A6` ✅ **已知支持**（实车读到 67046km）—— 这一趟只是**留档**，不是发现。
> - `A4` —— 实车**已有样本**（P/N/R/D 三种原始帧，见 CHANGELOG v1.18.3「追加实车结论」），
>   但**字节 B 只有 `00`/`10` 两个取值**，所以"B 是枚举挡位"那条推论**是错的**。
>   要拿它当挡位用，得**慢速开一段 + 开 CSV 记录 1Hz**，看 `(C*256+D)/1000` 这个齿比怎么走
>   （方法见 CHANGELOG v1.18.3）。
> - 这一趟把**全链枚举的完整结果导出留档**（v1.18.0 修好位图链之后还没做过完整的一轮）。

## 8. 已知的坑（**别重蹈**）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **适配器是 v1.4 水平的克隆** | 自报 v2.3 是假的。**手册里 v2.x 的行为它可能没有** —— 所以只能实测，不能推断 |
| 2 | **`AT SH` 是粘性的** | 切到 `760` 之后后续请求都去那个模块。**切回广播必须显式发**，否则标准 PID 读到别的模块的值而**看不出来** |
| 3 | **`ATCAF0` 曾让请求变畸形** | 会让发出的帧缺 PCI 字节 → ECU 回 NRC 0x13。v1.17.1 已删，**已复验**（见 §9 问题 2） |
| 4 | **「初始化」按钮非 READY 时是灰的** | 点了没反应先看这个，别以为是点击问题 |
| 5 | **`adb shell am start` 拉不起内部页面** | `ScannerActivity` 没导出（这是对的）。验证要从应用里走 |
| 6 | **别用 8×6 像素探针判断画面** | 整片漏掉文字。用亮像素统计或截图解码成色彩网格 |
| 7 | **改 `tools/*.ps1` 必须保留 UTF-8 BOM** | 无 BOM 时 PS 5.1 按 GBK 解码，中文注释会吃掉行尾。**编辑工具会静默抹掉 BOM** —— 改完跑一次 `tools/check-build-guard.ps1` |
| 8 | **日志刷屏有前科** | 单点刷屏曾刷出 57MB / 113 万行。正常路径的刷屏 AppLog 自我保护**挡不住**（每条内容不同，去重用不上） |
| 9 | **`帧` 大而 `命中=0`** | 帧一直在进、一条都不命中 = 监听型 PID 的 `header` 与真实帧 ID **对不上**（`Frame.idHex()` 用 `%X`，`0x09A` 出来是 `9A`，而配置里习惯写 `09A`）。代码已改成**按数值比**；新加的信号仍要拿 `各ID[...]` 核对一遍 |
| 10 | **常驻监听忘了停** | 它**不会自己停**，轮询会一直冻结在最后一个值。v1.20.6 起顶部有常驻警示条，日志里 `监听通道` 每 5 秒一行；停止时会自动 `ATZ` 重新初始化 |
| 11 | **动手改用户设备前先备份 config + log** | 上一趟误点对话框把用户画布转成了自定义，靠升级前备份才恢复；更早一趟只备份了 config 没备份 log，**日志永久丢了**。见 §2 的备份命令 |
| 12 | **点对话框按钮先 `uiautomator dump` 拿坐标** | 不同对话框按钮宽度不同（「转为自定义并编辑」比「取消」宽）。凭记忆复用上一个对话框的坐标 → 点错。**这一条已经真的坑过一次** |
| 13 | **日志要拉两次** | `AppLog` 是**批量落盘**，刚操作完立刻拉可能看不到最新几行（曾因此误判"渲染没打日志"） |
| 14 | **过滤器用错段号会白跑一趟** | `ATCF000` 是**全总线**不是"0x0xx 段"；段号看 `ATCF` 的高三位（`ATCF100`=0x100~0x1FF）。而且**过滤器会连带挡住 `7E8` 的 OBD 应答** —— 探针设了过滤器之后紧跟着发 `01 xx` 会全部超时，看起来像链路死了 |
| 15 | **「加为监听」之后必须重启常驻监听** | `FrameMonitor.signals()` 只在 `start()` 时读一次 → 新加的信号**不会进当前这次监听**，现象是"我明明加了，它一点动静都没有" |

| C | 多画布判据 6/7/9 | 只 9 要 | ❌ | ❌ | 10 分钟 | ✅（**6/7 完全不连车也能做**） |
| — | S5 分段轮换扫描 | — | — | — | — | ⛔ **未实现，本趟不做**（见 11.5） |

**推荐顺序：0 → B → A → C**（也可以 0 → C → B → A）。理由：

1. **0 是闸门**，不通就回家。
2. **B 排第二**：它要的"CAN 广播"只要拧到 ON 就有，**不需要人操作开关**，
   而且是**纯判据、不用等**；顺手能把车热起来（水温上来后 A 的怠速场景更真实）。
3. **A 最耗时且需要第二个人配合**（开关车门 / 插安全带 / 喷玻璃水），
   放在中间、人还在的时候做；做不完就按 11.1 的优先级**砍尾部**。
4. **C 最后**：不需要车、也不需要适配器（判据 6/7），
   在**收车回家后、甚至办公室**都能补 —— 它是唯一"没做完也不亏"的一项。

### 11.1 工单 A · 12 个指示灯（**最耗时的一项**）

> **目标不是"找到位"，而是"能用的 PID"。** 判据的最后一环是
> **它能在仪表上驱动那盏灯的三态图** —— 只找到位不加为 PID，等于没做。
> 方法（怎么做 / 为什么用状态而不是 XOR）见 §0.5，这里只讲**怎么排期**。

#### A.1 一次上车最多能收几个？

- **每个目标至少要 2 趟探测**（关 / 开），每趟 = 准备（排空 + `ATH1`/`ATS1`/`ATL1`，约 2~3 秒）
  + 采集 **20 秒** + 收尾（`ATZ` 重初始化 + `0100` 健康检查，约 3~5 秒）
  ≈ **30~40 秒/趟**。
- **所以 12 个目标串行 = 24 趟 ≈ 12~16 分钟纯机器时间**，
  再加人工操作开关 / 记录 / 加为监听 → **保守 25~35 分钟**。
- ⚠️ **但"最多能收几个"的真正上限不是时间，是"你还能复现几次操作"**：
  每做完一个目标就要做一次对照，**人的注意力在第 6~8 个目标之后会明显下降**，
  而差分结果一旦看错（把心跳帧的抖动当成目标位），就会**留下一条错的 PID**，
  比没收更糟（它会一直喂错值）。
- 👉 **建议一次上车收 4~6 个**，宁可分两趟，也别在一趟里硬塞 12 个。

#### A.2 先摸底：这些灯在哪些 ID 段上

`ATCF000`（全总线）下每个 ID 只有约 **1 帧/秒**，慢周期报文根本还原不出来。
所以要**按段摸底**，再决定怎么分组（每段一趟，共 6 趟，约 3 分钟）：

| 趟 | 过滤器 | 看什么 |
|---|---|---|
| 1 | `ATCM700+ATCF100` | `0x100~0x1FF` 有哪些 ID 在稳定广播（`CAN ID` 行 + `count`/`changed`） |
| 2 | `ATCM700+ATCF200` | 同上 |
| 3 | `ATCM700+ATCF400` | 同上 |
| 4 | `ATCM700+ATCF600` | 同上 |
| 5 | `ATCM700+ATCF000` | 兜底：全 11 位 ID 各出现一次，确认没漏段 |
| 6 | 留空（不过滤） | 对照：确认"不过滤时确实看不清慢信号"（也是 §0.5 那条结论的复现） |

**判据**：`CAN ID` 行里出现**稳定周期**的 ID（`count` 高、`changed` 低）= 心跳/周期帧；
`changed` 高而 `count` 不高 = **闪烁类**（转向灯就是这个特征）。

> ⚠️ 已知：**转向灯在 `0x09A`**（`0x000~0x0FF` 段）。
> 车身信号（门/安全带/玻璃水）**大概率在 `0x2xx`~`0x6xx`**，
> 但**不要假设** —— 摸底那一趟就是为了不猜。

#### A.3 逐个目标的操作单（模板）

每个目标照这 9 步做，**9 步全过才算收下**：

| 步 | 动作 | 判据（看不到就别往下走） |
|---|---|---|
| 1 | 「连接」页确认 READY，轮询有值 | §4.1 / §4.3 的判据 |
| 2 | CAN 探测页：过滤器填该段的 `ATCM700+ATCF<段>`，时长 **20 秒** | 日志 `CAN 探测开始 \| … filter=…` |
| 3 | **关闭**目标（如关门）→ 开始探测 → 等 `CAN 探测结束` | `frames=` 明显 > 0；`parsedFrames` 与 `frames` 一致（不一致看 §4.4 的 `探测准备`） |
| 4 | **打开**目标 → **同参数**再跑一次 | 同上。⚠️ **参数必须一模一样** |
| 5 | 点「对比基准（找位）」 | 日志 `CAN 差分 \| 共 N 处`（N=0 → 见下面"没差异怎么办"） |
| 6 | 找带 `★` 的那一行 | 日志 `CAN 差分位 \| <ID> 第N字节 bitM：恒0 -> 在变 公式=bit(X,M)   <== 这次操作引起的` |
| 7 | 点该行「**加为监听**」 | Toast `已加为监听型 PID：监听 …`；日志 `监听信号变化` 之后要能出现它 |
| 8 | 到「PID」页把它的**名字改成中文**（如"车门未关"），确认**已启用** | 分组 `监听型(实车确认)` 里有它 |
| 9 | CAN 探测页 **停止常驻监听 → 再开启**（新信号才会进过滤器）→ 再操作一次目标 | `监听通道启动 \| 信号=…,<新 id> 过滤=ATCRA<ID>` 里有新 id；`监听通道 \| 帧=… 命中=…`（**命中 > 0**）；`监听信号变化 \| 车门未关(mon_…) = 1` |
| 10 | （收尾，可批量做）仪表盘上把 `lamp_door` 之类的控件**绑到这个 PID**，操作一次目标看它变状态 | 三态图跟着变（这一步才是"能用了"） |

**"没差异怎么办"**（`CAN 差分 \| 与基准无差异`）：

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 两次都没收到该 ID | 段选错了 | 换段（回 A.2） |
| 该 ID 的 `changed` 两次都很高 | 目标位被心跳抖动淹没 | 缩小过滤器到**单个 ID**（`ATCRA<ID>`）重跑两次 |
| 位状态两次都"在变" | 目标在这段里**一直**在变（不是被这次操作拨动的） | 换一个更"静态"的目标复现，或把它当"本来就是周期量"处理 |
| 该 ID 只留了 8 个不同取值 | 稀疏变化的位被误判成"恒定"（**已知漏报**） | 改用 `ATCRA<ID>` 单 ID 过滤，采样率拉满再跑 |

#### A.4 优先级（**按"车上最容易复现"排**）

> ⚠️ **这不是"哪个信号重要"的排序，是"哪个今天就能复现"的排序。**
> 复现不了的目标**强行做只会得到假结论**。

| 批 | 目标 | 怎么复现 | 要什么前置 | 为什么排这里 |
|---|---|---|---|---|
| **第 1 批** | **车门** | 开门 / 关门 | 点火 ON | 操作最干净、状态最持久（开着门就是开着） |
| | **安全带** | 插 / 拔（**主驾**；副驾要人坐上去） | 点火 ON | 同上；注意有些车只有"未系"报警、没有"已系"位 |
| | **玻璃水** | 喷一下（**会真的喷水**） | ON，最好怠速 | 状态可保持一段时间；⚠️ **别在没水时硬喷** |
| **第 2 批** | **保养提示** | 仪表菜单里翻保养项 / 重置提示 | ON | 需要翻菜单，但**不用改车状态** |
| | **制动液** | ⚠️ 拉手刹 / 松手刹**可能**是它 | ON | 复现方式**不确定**，先试手刹；不行就归到"难复现" |
| | **刹车片** | ⚠️ 同上（很多车这个位是"传感器已磨到"才置位） | ON | **很可能复现不了** |
| **第 3 批** | **ABS / ESP** | 点火 ON 时仪表自检会**短暂点亮**（约 2~3 秒） | ON | **窗口很短** → 用 `ATCRA<ID>` + 采集 20 秒，在自检期间跑；或者拔 ABS 保险丝（**不建议**） |
| | **胎压** | 通常只在"胎压不足"时亮 | — | **复现不了就别做** |
| **第 4 批（建议直接跳过）** | **气囊 / 碰撞 / 车道** | 无合法复现方式 | — | 🔴 **为了逆向而触发安全系统是不划算的**。这一批**本趟明确不做**，在清单上标"无法复现，等有故障车再收" |

> 📌 **档位（`g_gear`）**：不需要"找位"，它已经有公式（`bit(B,4)*2+bit(D,0)-1`）。
> 缺的是**逐挡确认枚举映射** —— 做法是**慢速开一段 + 开 CSV 记录 1Hz**，
> 记录 P/R/N/D/1~6 各挡的 `B` 与 `D` 字节（见 CHANGELOG v1.18.3「追加实车结论」）。

> 📌 **电池电量（`g_soc`）**：既没有标准 PID 也没有派生通道

> ⚠️ **前置有个坑**：这三条都要**监听型 PID**，而"手工新建监听型 PID"的能力是

> 所以它**造不出**这三个语义）。这是**代码活，不用车** —— 建议单独排。

### 11.4 「常驻监听」与「对比基准」的用法 —— 现有两节够用吗？

**结论：§0.5 那两节够用，但缺 4 个会直接导致"白跑一趟"的细节，已补进本节与 §8：**

| 缺的细节 | 补在哪 |
|---|---|
| **基准 = 上一次探测**，跨会话会丢 → 两次对照必须**同一趟连着跑完** | §0.5 的警告块 |
| **「加为监听」后必须重启常驻监听**，否则新信号不进过滤器 | §0.5 步骤 5 + §8 第 15 条 |
| `ATCF000` 是**全总线**不是"0x0xx 段"；段号看 `ATCF` 高三位 | §0.5 的过滤器表 + §8 第 14 条 |
| **差分结果是"候选"不是"结论"**（每 ID 只留 8 个取值，会漏报） | §0.5 的警告块 + 11.1 A.3 的"没差异怎么办" |

> **判据本身不用补**：§0.5 已经给了 `监听通道`（帧/命中/各ID）、`监听信号变化`（每种 ≤20 条）、
> `监听帧率过高，已介入`、顶部 `监听中 · 轮询已暂停` 这几条硬判据，
> §4.4 也有对应的判据表 —— **这里只补"用错的后果"，不重复判据**。

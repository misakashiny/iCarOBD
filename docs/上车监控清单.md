# 上车监控清单（笔记本实时监控用）

> **这份是给"人 + 智能体"在车边上照着做的操作单。** 目标只有一个：
> **一次上车，把"链路到底通不通、这台车到底支持什么"两个问题一起答掉。**
>
> 别再靠推断。每一条判据都落到**一行日志**上 —— 看到就有结论，看不到就是没通。
>

## 0.5 两个新工具（2026-10-06 上车后加的）

> 上一趟上车最大的教训是**采样率**：克隆版在满速总线上只漏出约 **77 帧/秒**，
> 摊到约 80 个 CAN ID 上就是**每个 ID 每秒 1 帧** —— 1.4 Hz 的转向灯闪烁**根本还原不出来**。
> 所以别急着怪"信号不在总线上"，先看这两个工具。

### 「CAN 探测」页的**过滤器**（`ATCRA` / `ATCM`+`ATCF`）

| 填法 | 效果 |
|---|---|
| `228` | 只放行单个 ID（内部发 `ATCRA228`） |
| `ATCM700+ATCF400` | 放行 `0x400~0x4FF` **一整段**（掩码过滤） |
| 留空 | 不过滤（原行为） |

**效果**：过滤后单 ID 采样率 0.7 帧/秒 → **20 帧/秒**（28 倍），总帧数 77 → 344 帧/秒。

> ⚠️ **过滤器会连带挡住正常 OBD 应答**（正常请求回 `7E8`，过滤器只放行指定 ID）。
> 收尾会自动重新初始化（`ATZ`）清掉；万一没清干净，到「连接」页重新初始化一次即可。
> 每趟结束都会打一行**健康检查**（`0100 有应答` / `⚠️ 无有效应答`）告诉你清没清干净。

### 「对比基准（找位）」—— 找广播帧里的信号位

1. 过滤器 `ATCM700+ATCF000`、采集 20 秒 → **关闭**目标（如关门）跑一次
2. **打开**目标 → 同参数再跑一次
3. 点 **「对比基准」** → 列出状态变化的位（`★` = 这次操作引起的）
4. 点该行 **「加为监听」** → 立刻变成可用的监听型 PID

**判据**：某一位在基准里 `恒0`/`恒1`、操作后变成 `在变` → **就是它**。
用"状态"比而不是"两个值 XOR"，因为单次采样会**撞相位**（1.4 Hz 的灯，采到亮还是暗是掷硬币）。

### 「开启常驻监听」—— 让广播信号真正喂给规则与仪表

⚠️ 它是**模式切换**，不是"顺便多收"：ELM327 **半双工**，`ATMA` 期间**轮询必须让位** ——
开着监听时转速/水温会**冻结在最后一个值**。停掉时会自动重新初始化。

## 4. ✅ 判据表（**看到什么 → 说明什么 → 怎么办**）

### 4.1 连接建立（**本次首要目标**）

| 日志 | 含义 | 怎么办 |
|---|---|---|
| **`CCCD 写入完成 \| status=0`** | ✅ **GATT 竞态修好了** —— 描述符写回调正常回来了 | 继续往下看 4.2 |
| `CCCD 回调丢失 —— GATT 栈已卡死` | ❌ 还有东西在抢 GATT 操作 | 把整份日志留下来（这是新证据）；**先断开重连一次**再试 |
| 成片的 `写入被拒` / `BLE 写入持续失败` | ❌ 栈卡住了（v1.18.1 前的症状） | 断开 → 重连 → 再初始化；若复现，记录 `写失败累计` 的**第一次**值 |
| 连 `已写 CCCD` 都没有 | ❌ 特征/描述符没选对 | 看 GATT 表段（`===== GATT 表开始 =====`） |

### 4.2 初始化与协议

| 日志 | 含义 | 怎么办 |
|---|---|---|
| `初始化完成 \| ok=true` | `0100` 真的解析出了 4 字节位图 | 正常 |
| `ok=true` 但后面全失败 | ⚠️ 就是 v1.17.1 那次的情形 | 看 `探测通过但真实 PID 无响应` 那条警告 |
| **`协议已锁定 \| ATDPN=A6`** | ✅ 自动协商完成（A6 = ISO 15765 CAN 11/500） | 正常 |
| `协议未锁定（超时）` | 自动搜索没收敛 | 在「连接」页**手动把协议选成 6**（CAN 11bit 500k）再试 |
| `ECU 拒绝 \| 服务=0x.. NRC=0x..` | **ECU 明确拒绝**（不是没人答） | NRC 0x13 = 报文长度错 → 看是不是又发了畸形帧；0x7F = 该服务不支持 |

### 4.3 轮询是否有值（**"通没通"的最终判据**）

| 日志 | 含义 |
|---|---|
| **`轮询汇总 \| 有值 6/23 \| 车速=0km/h 冷却液温度=92℃ …`** | ✅ **通了**，而且直接告诉你哪些有值 |
| `首次拿到数值 \| id=std_05 name=冷却液温度 value=92℃` | ✅ 每条 PID 第一次成功时报一次（有界，不会刷屏） |
| `轮询汇总 \| 有值 0/23 —— 一条都没成功过` | ❌ 一条都没有，看上面的失败原因 |
| **`连续 60 次请求无一成功，已停止轮询`** | ⚠️ 链路自检生效了（v1.17.9）。**这是"链路不可用"的明确结论**，不是 bug |

## 5. 上车流程（照着点）

1. **适配器插 OBD 口** → 点火开关拧到 **ON**（不必发动）
2. **锁方向**（否则转屏会让 Fragment 重建、验证链断掉）：
   ```powershell
   & $ADB -s 7e7d7bb4 shell settings put system accelerometer_rotation 0
   ```
3. 打开 App →「连接」页 →「扫描设备」→ 点 **IOS-Vlink**
4. 等 `状态变更 | READY` —— **此时盯窗口 A，看 `CCCD 写入完成` 有没有出现**
5. 「初始化 ELM327」（**连上之前这个按钮是灰的**，别以为点了没反应）
6. 盯 `初始化完成` / `协议已锁定` / `轮询汇总`
7. **车要怠速运转**（水温 90℃ 上下、电压 13.5~14.5V 才说明在充电）

## 6. 扫描器：一次问清"这台车支持什么"

**这一步能同时回答"挡位/总里程在哪"和"13 个指示灯有没有标准来源"。**

「PID」页 →「PID 扫描器」：

| 参数 | 值 | 为什么 |
|---|---|---|
| 模式 | `01` | 标准空间 |
| 范围 | `00` ~ **`C0`** | ⚠️ **必须是 C0** —— 挡位 `A4`、总里程 `A6` 在 A1~C0 段（v1.18.0 才修好这一段） |
| 勾选「支持位图」 | ✅ | 走 `01 00 → 01 20 → … → 01 C0` 全链枚举，**比范围扫描快得多** |
| 安全确认 | ✅ | 必须勾 |
| 黑名单 | 默认 | `01:02,01:03,01:07,01:0A` |

扫完点**「导出结果」**，把文件发出来。

> 重点关注：有没有命中 **`A4`（挡位）/ `A6`（总里程）**。
> 有 → 我们 v1.18.0 加的那两条就能直接用。
> 没有 → 说明这台车不支持，再谈 Mode 22。

## 8. 已知的坑（**别重蹈**）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **适配器是 v1.4 水平的克隆** | 自报 v2.3 是假的。**手册里 v2.x 的行为它可能没有** —— 所以只能实测，不能推断 |
| 2 | **`AT SH` 是粘性的** | 切到 `760` 之后后续请求都去那个模块。**切回广播必须显式发**，否则标准 PID 读到别的模块的值而**看不出来** |
| 3 | **`ATCAF0` 曾让请求变畸形** | 会让发出的帧缺 PCI 字节 → ECU 回 NRC 0x13。v1.17.1 已删，**本次要复验** |
| 4 | **「初始化」按钮非 READY 时是灰的** | 点了没反应先看这个，别以为是点击问题 |
| 5 | **`adb shell am start` 拉不起内部页面** | `ScannerActivity` 没导出（这是对的）。验证要从应用里走 |
| 6 | **别用 8×6 像素探针判断画面** | 整片漏掉文字。用亮像素统计或截图解码成色彩网格 |
| 7 | **改 `tools/*.ps1` 必须保留 UTF-8 BOM** | 无 BOM 时 PS 5.1 按 GBK 解码，中文注释会吃掉行尾。**编辑工具会静默抹掉 BOM** —— 改完跑一次 `tools/check-build-guard.ps1` |
| 8 | **日志刷屏有前科** | 单点刷屏曾刷出 57MB / 113 万行。正常路径的刷屏 AppLog 自我保护**挡不住**（每条内容不同，去重用不上） |

### 2.2 【缺陷】降级无效：无类型调用仍继承 Manifest 类型

**实测证据**（`verify-p5b02-fgs.js`，全部来自系统状态）：

| 场景 | `startForegroundCount` | 结论 |
|---|---|---|
| 有蓝牙权限 | **1** | 前台服务正常 |
| **撤销蓝牙权限（旧代码）** | **0** | **带类型与无类型都没成功** |
| 重新授权 | **1** | 恢复 |

**根因**：Manifest 写了 `android:foregroundServiceType="connectedDevice"`。
Android 14 对**无类型调用也按 Manifest 声明校验** → 缺运行时蓝牙权限时同样抛
`SecurityException` → 所谓"降级成无类型"这条路**走不通**。

**后果**：P5A-M01 R2 修掉了崩溃（异常被 catch），但 **Service 从未成为前台服务** ——
App 切后台时没有 FGS 保护，可能被系统回收。

### 2.3 修复：权限前置检查 + 场景化类型选择

```kotlin
val btGranted = hasBluetoothPermission()
val chosenType = chooseForegroundType(btGranted)
//  · 有权限 → CONNECTED_DEVICE（正常路径，与既有行为完全一致）
//  · 无权限 → DATA_SYNC（不需要蓝牙权限，仍给 FGS 保护）
startForeground(NOTIF_ID, n, chosenType)
```

Manifest 同步改为 `foregroundServiceType="connectedDevice|dataSync"`
并加 `FOREGROUND_SERVICE_DATA_SYNC` 权限。

**修复后实测**：撤销权限后 `startForegroundCount` 从 **0 → 1**。

## 六、F 段：八样式主题 Android 加载与截图（**两轮阻塞解除**）

### 6.1 前两轮为什么没跑通 —— 终于查明

P5B-M01 尝试时：主题**成功写入** `settings.designJson`，回读校验 gauge 数=8，
但截图**一点没变**（24,860 B / 颜色数 198）。

**真因**（`Store.kt:655` `activeCanvas()`）：

```kotlin
fun activeCanvas(): DashCanvas {
    ...
    val cur = settings.canvases.firstOrNull { it.id == settings.activeCanvasId }
    if (cur != null) return cur
}
```

**App 渲染的是 `settings.canvases[activeCanvasId].designJson`**，不是顶层
`settings.designJson`。上次只改了顶层实时字段 → 渲染仍用旧画布。

### 6.2 修法

`deploy-8styles.js` 改为**同时写两处**：
- `settings.designJson`（顶层实时字段）
- `settings.canvases[activeCanvasId].designJson`（画布自己那份）

同时把测试主题布局从 4×2 改为 **2×4**（每个 172×72，最大 y+h=332 ≤ 360），
保证 8 个表盘一屏可见。

## 八、发现及修复的缺陷（6 个）

| # | 缺陷 | 级别 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **嵌套分组里的 v3 节点被判非法** | **协议级** | `DesignNode.parse` 递归 `children` 时**没传 `allowV3`** | 传入 `allowV3` |
| 2 | **顶层 `nodes`（无 `pages`）的 v3 主题读不回** | **协议级** | `DesignFile.kt:524` 的 `parse` 调用**没传 `allowV3`** —— 而这正是编辑器导出的形态 | 传入 `allowV3 = isV3` |
| 3 | **编辑器能导出 v3 但读不回自己导出的文件** | **协议级** | `validate.js:133` 只认 `SCHEMA_V1`/`SCHEMA_V2` | 加认 `SCHEMA_V3` |
| 4 | **`createNode` 丢掉 v3 节点的 `pid`** | 高 | 只在 `NODE_GAUGE` 分支处理 pid | 加通用分支（与 gauge 同一套 `pid`/`rawPid` 规则）|
| 5 | **`nodeToJson` 丢失基元专有字段** | 高 | 按 type 分支的白名单里没有四种新 type → 导出只剩通用字段 | 加逐字段白名单（含 `zoneColors` 的 `at`）|
| 6 | **部署脚本 `ENAMETOOLONG`** | 中 | 整份 base64 作为一个命令行参数，大主题超 32K 上限 | 改 `adb push` 分块 + `cat` 拼接 |

### 另修（编辑器行为）

| # | 缺陷 | 修法 |
|---|---|---|
| 7 | **未知 node type 静默跳过**（编辑器 `drawNode` 无 `else`）| 画红色虚线占位 + 登记 `getUnknownNodes()` |
| 8 | `NODE_TYPES` 契约表无法容纳 v3 | 用 `_allowV3` 按 schema 分层，**不改契约表**（保 v2 语义）|
| 9 | `verify-crosslang` 正则不认 `val TYPES = A + B` | 支持 `+` 拼接递归展开 |

### 我自己犯的错误（记录以便后人避坑）

| 错误 | 教训 |
|---|---|
| 用 `stopSelf()` 满足 5 秒契约（P5B-M03 遗留）| 系统只认 `startForeground()` |
| 往 1000 行的既有类塞大段逻辑 → 触发跨文件 `internal` 编译错误 | **改数据类结构后必须 `clean` 编译**；新逻辑单独成文件 |
| 跨端套件的 `__dirname` 少算一级 → `chrome-error://chromewebdata/` | 症状是"页面未就绪"而非"文件不存在"，很隐蔽 |
| 测试把 `toV2Json` 的字符串返回值当对象用 | 解析两层 |
| 用"像素越亮=点亮越多"当判据 | 颜色语义变化会反转（临界时白字变红）|
| 按设计坐标线性换算屏幕位置 | App 渲染会**缩放并居中**，必须用 uiautomator 实测 |

### 1.1 `GaugeViewFactory` 的 8 个 View 是否实际可用 ✅ **确实可用**

`GaugeViewFactory.create(ctx, style)` 是**唯一映射处**，8 档全部指向独立类，未知 style 回落 `DigitalGaugeView`（不崩）：

| style | 常量 | View | 行数 | 真实绘制内容 |
|---|---|---|---|---|
| 0 | `STYLE_CIRCLE` | `CircularGaugeView` | — | 圆盘表 |
| 1 | `STYLE_DIGITAL` | `DigitalGaugeView` | 80 | 数字 |
| 2 | `STYLE_BAR` | `BarGaugeView` | 142 | 条形 |
| 3 | `STYLE_LINE` | `LineChartView` | 98 | **历史折线**（见 1.3）|
| 4 | `STYLE_DUAL_STACK` | `DualStackGaugeView` | 28 | **上下一分为二的两个数值格** |
| 5 | `STYLE_QUAD` | `QuadGaugeView` | 31 | **2×2 四格数值** |
| 6 | `STYLE_SUB_DUAL` | `SubDualGaugeView` | 28 | **上大下小（下分两格）** |

### 1.2 编辑器 style 0~7 的真实绘制分支 ✅ **文档正确**

**结论：文档完全正确。** style 3 是装饰正弦波（不接数据），style 4/5/6 只有"×N"占位，style 7 直接复用圆盘。

### 1.3 ⚠️ **需纠正一处**：文档说 style 4/5/6 是"一条线 + ×2"等，实际 App 侧是**文字数值格**

文档表格写：

| style | 文档描述 | **实际 App 侧** |
|---|---|---|
| 4 | 一条线 + `×2` | **上下两个数值格**（各含 标签/数值/单位 三行，`TextFit` 自适应字号）|
| 5 | 十字线 + `×4` | **2×2 四个数值格** |
| 6 | 两条线 + `×3` | **上大（主参数）下分两格（子参数）** |

**为什么重要**：这决定了编辑器补齐预览时该画什么。
如果照文档字面"画一条线 + ×2"，补出来的东西**仍然是错的**。
必须画**数值格子**（标签 + 数值 + 单位），才与 App 一致。

> 文档是"从编辑器视角反向描述 App"，视角错了但"不一致"的结论没错。
> 已在本文档纠正，并在后续阶段按**真实外观**补齐。

### 1.4 style 3 / style 7 的数据语义 ✅ **文档正确**

**style 3（`LineChartView`）确实用真实历史数据**：

```kotlin

// 历史来自 VehicleBus.historyOf，由渲染层推给视图（视图不读总线）
```

→ **编辑器不得继续用装饰正弦波**。必须提供可重复的模拟历史数据。

**style 7（`GForceGaugeView`）真实语义**：

```kotlin

主参数 value  = 综合 G 值（calc_gforce）
副参数 0 = 横向 G（calc_gx）→ x 轴
副参数 1 = 纵向 G（calc_gy）→ y 轴（向上为正）
画：外圈 + 0.5G 参考圈 + 十字准线 + 一个按 (gx,gy) 定位的圆点 + 中央"综合 N g" + 左下"横"/右下"纵"
```

→ **编辑器不能复用普通圆盘**。必须画 G 力散点语义。

### 1.5 `parts` / `bands` / `neonPreset` 是否有其它覆盖渲染路径 ✅ **无覆盖，但有叠加**

| 字段 | 与 style 的关系 |
|---|---|
| `parts`（子部件）| **独立叠加层**，与 style 无关；`GaugePartsView` 画在表盘之上 |
| `bands`（色带）| 用于 style 0 的圆盘弧段着色；4/5/6 是文字格，**不消费 bands** |
| `neonPreset` | 是 `palette` 来源（`BaseGaugeView.palette`），**所有 style 共用** |

**结论**：不存在"某个 style 被 parts 覆盖掉"的路径；但 **parts 会叠加在任意 style 之上**，
所以补齐预览时必须确认 parts 层不被破坏。

### 1.7 轨道默认静态 `fill` 与 Android 动态 PID 联动是否被文档混淆 ✅ **确有混淆，需澄清**

文档把轨道 `fill` 当作"静态样式"，但实际：

- `trackStyle.fill` 是**无数据时的静态示意值**
- 一旦节点绑了 PID（`pid` 或 `statePid`），`TrackView.effectiveFill()` 会**用实时值/量程覆盖它**
- P5A-M04 实测：设计 `fill: 0.55`，但截图里填充是 **24%** —— 因为车速 60/260 = 0.23

**结论**：文档没说清这一点。补齐轨道预览时，编辑器**也应该**在有 PID 时用"模拟值/量程"算比例，
而不是画静态 `fill`。否则又会出现"编辑器看着 55%、真机是 24%"。

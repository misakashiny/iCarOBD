## 二、上一轮报告的两处描述差异（本轮以 Git 为准更正）

### 差异 1：`openSource()` + `put(source,v)` → 实际实现用了 `put(v)`

**上一轮报告的说法**：阶段 A 计划用 `openSource()`，最终改为 `put(v)`，
原因是 `openSource` 是 `internal`、debug 源集访问不到。

**本轮实测复核**（写了一个会编译失败的探针来验证，不是凭记忆）：

```kotlin
// app/src/debug/.../SimInternalProbe.kt（验证后已删）
object SimInternalProbe { fun probe(): Any = VehicleBus.openSource("probe") }
```

编译报错：

```
e: Cannot access 'fun openSource(owner: Any): VehicleBus.Source':
   it is internal in 'com.icar.obd.obd.VehicleBus'.
```

**结论**：`internal` 在 `app/src/debug/` 里确实不可见 —— 上一轮这个观察是对的。

**但这个"绕过去"的做法有真实副作用，上一轮报告没写清楚。** 本轮用 JVM 测试把它钉住了
（`VehicleBusSourceSemanticsTest`，13 项）：

```kotlin
@Test fun `put(v) 会摘掉归属 之后再关来源也失效不了`() {
    val real = VehicleBus.openSource("real")
    VehicleBus.put(real, pv(v = 60f))      // 真实采集，归属 = real
    VehicleBus.put(pv(v = 99f))            // 模拟值：内部 currentOwners.remove(pidId)
    VehicleBus.closeSource(real)           // 关真实来源
    assertTrue(VehicleBus.get(PID)!!.ok)   // ← 值仍 ok=true，仪表还以为"在实时采样"
}
```

`put(v)` 的实现（`VehicleBus.kt:91`）：

```kotlin
fun put(v: PidValue) {
    synchronized(sourceLock) {
        currentOwners.remove(v.pidId)   // ← 把该 PID 从"谁在采"表里摘掉
        storeLocked(v)
    }
    notifyValues(listOf(v))
}
```

**实际影响（三条，全部有测试证据）**：

| # | 影响 | 证据 |
|---|---|---|
| 1 | 模拟值**无法被正确失效**：关来源时 `closeLocked` 找不到归属，留下 `ok=true` 的陈旧值 | 上面的用例 |
| 2 | 该 PID 脱离 `openSource` 的 epoch 保护（旧来源的迟到写入不再被区分）| `快速切换来源时旧来源的写入不会复活` 只能覆盖有归属的路径 |
| 3 | 归属被逐步"漂移"：谁最后写谁拥有，真实/模拟交替写时归属在两者间跳 | `两个不同来源同时写同一 PID 后者归属后者` |

**本轮处置**：不再用 `put(v)`。改为**复用项目自 v1.5.0 就有的 `SignalSimulator`**
（它内部 `openSource` + `put(source,v)`），模拟层只负责「场景 → 通道配置」与互斥。
详见 [77_P5A_M02_阶段B_数据源隔离设计](77_P5A_M02_阶段B_数据源隔离设计.md)。

> ⚠️ 这条差异不是"上一轮做错了要掩盖"，而是**上一轮只记了"改成了什么"，没记"代价是什么"**。
> 本轮把代价补成可执行断言。

## 三、十项审计结果

### 2. Debug / Release 变体

| 项 | 值 |

| 本轮需重做 | 阶段 H 重建 Release 复核 |

⚠️ **重要发现**：`SignalSimulator` 与 `SimulatorActivity` 在 **main** 里，
即**Release 也带**模拟信号发生器与调试界面。它们是 v1.5.0 起的**既有产品功能**，
不是本轮新增；本轮新增的只有 `app/src/debug/` 里的**广播入口**。
→ 因此"Release 不含模拟入口"的准确含义是：**不含 adb 广播入口与场景化模拟源**，
而不是"不含任何波形发生器"。这一点必须在报告里说清楚，避免再次形成错误结论。

### 3. VehicleBus 数据来源管理

| 成员 | 可见性 | 语义 |
|---|---|---|
| `openSource(owner)` | `internal` | 同一 owner 重复开 → **自动关闭旧来源** |
| `sourceActive(source)` | `internal` | 是否仍是当前来源（epoch 校验）|
| `closeSource(source)` | `internal` | 关闭并把**它写过的** PID 标 `ok=false, error="采集来源已停止"` |
| `put(source, v)` | `internal` | 校验来源有效后写；**建立归属** |
| `put(v)` | **public** | 写值并**摘除归属**（见差异 1）|
| `get/value/snapshot` | public | 视图读取；`value()` 带 TTL 新鲜度判定 |
| `currentOwners` | 私有 | pid → 最后写入的 Source |

失效语义：`closeLocked` 只失效**归属等于该来源**的 PID；`value()` 在 TTL 过期时返回 null。

### 4. `ObdEngine` / `ObdService` 生命周期

- `ObdEngine.start()` → `openSource(this)`，`stop()` → `closeSource(oldSource)`，
  写值走 `put(epoch, PidValue(...))`（`ObdEngine.kt:265/286/300/375`）
- `ObdController.startPolling()/stopPolling()` 是唯一开关；`engine.running` 可读
- `ObdController.isConnected()` = `transport.isReady()`
- **真实采集与模拟不能同时写同一 PID**：源码注释明示「合成值会和真实值交替写入总线，画面会来回跳」
  （`SignalSimulator` 文件头），`SimulatorActivity.toggle()` 的做法是**先停引擎再开模拟**

### 5. `DashRenderer` 数据分发（5Hz / 200ms）

```
pushValues()
 ├→ nodeRenderer.gauges      → BaseGaugeView.updateMulti(values, override)
 ├→ nodeRenderer.trackViews  → TrackView.setValue(v)            （M01 修）
 ├→ nodeRenderer.partsViews  → GaugePartsView.setValues(map)     （M02 阶段 D 验证）
 ├→ nodeRenderer.stateCells  → applyStates(valueOf, nowMs)      （状态灯）
 └→ cells（v1 网格）        → BaseGaugeView.updateMulti
```

### 6. `DesignNode` 的 PID 与状态字段

| 字段 | 适用 type | 说明 |
|---|---|---|
| `pid` | gauge | 必填，走 `DesignFile.resolvePid`（别名 `obd.rpm` → `std_0C`）|
| `pid` | **image** | M01 起读取（回落 `statePid`），用于条形轨道 |
| `statePid` | image | 状态灯绑的 PID |
| `stateWarn` / `stateCritical` | image | 覆盖 PID 库阈值 |
| `states` | image | `{normal:{assetId},warn:{...},critical:{...}}`，**必须是对象** |
| `trackStyle` | image | 非 null → 走代码绘制的条形轨道 |
| `parts` | gauge | 非空 → 走 `GaugePartsView` 拼装 |

### 7. `GaugePartsView` 动态更新接口

- `neededPids()`：主 PID + 所有部件 `pid`（**递归含 children**）
- `setValues(map)`：整表替换，`NaN`/缺失视为不可用
- `valueOf(part)`：`values[part.pid ?: item.pidId]`
- `drawPart()` 支持 `alpha / rotation / pivotX/Y / sweepFrom/To / sweepFollow / anim`
- **只 `needle` 与 `value` 会解析 `pid`**，其余 kind 一律空
- ⚠️ **本轮发现的缺陷**：`GaugePartsView` 只接收单一 `pxPerUnit`，X/Y 用同一比例；
  而节点尺寸用 `pxX/pxY`。非方形视口下部件横向溢出被裁 → **见阶段 D 修复**
- ⚠️ 指针未显式绑 pid 时，量程回落到**节点 `min/max`（默认 0..100）**，
  与主 PID 量程不一致会导致指针钉死 —— 文档化语义，登记改进建议

### 8. 状态灯图片与规则更新机制

`NodeStateResolver.select()`（全项目唯一判定）：

```
warnAt     = node.stateWarn     ?: pid.warnHigh ?: 返回 NORMAL
criticalAt = node.stateCritical ?: (warnAt + (pid.maxVal - warnAt) * 0.5)
value >= criticalAt → critical
value >= warnAt     → warn
否则                 → normal
```

- **只有高值判定**（`>=`），**没有 warnLow 支持** → 低值报警灯不会变色（登记缺口）
- 无值 / 非有限值 → 未知态（画 `--`，`NodeStateResolver.UNKNOWN_TEXT`）
- 闪烁周期夹到 `MAX(MIN_BLINK_MS=400)`（WCAG 2.3.1）

## 四、本轮隔离方案（阶段 B 结论先行）

**采用「严格互斥 + 默认关闭」**，理由与依据：

1. 项目**已有**这套策略（`SimulatorActivity.toggle()`：先 `engine.stop()` 再 `SignalSimulator.start()`）
2. 无法证明"Debug 与真实采集安全并存"——两者写同一 PID 会交替覆盖，
   源码注释已把症状写明（画面来回跳）
3. 复用 `SignalSimulator` 可免费获得**正确的归属语义与失效语义**，且**生产代码零改动**

详见 [77_P5A_M02_阶段B_数据源隔离设计](77_P5A_M02_阶段B_数据源隔离设计.md)。

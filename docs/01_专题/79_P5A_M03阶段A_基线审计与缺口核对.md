## 二、实证探针结果（`_probe-p5a03.js`，不是推测）

### A1 新建仪表不传量程 → 默认 0..100

```
createNode(NODE_GAUGE, { pid:"obd.rpm" })  →  nodeMin=0  nodeMax=100
PID std_0C 真实量程                        →  pidMin=0  pidMax=8000
```

**后果**：用 parts 拼装、指针未显式绑 PID 时，`GaugePartsView` 回落到节点量程 0..100；
转速 800 早已 ≥100 → **指针钉在端点不动**（M02 阶段 D 踩过，当时是改测试主题绕开）。

### A2 换 PID 会静默覆盖用户自定义量程

```
用户设 min=999 max=7777
→ assignControlBinding(n, "obd.speed")
→ 变成 min=0 max=260   ← 用户的 999~7777 被覆盖
```

**违反任务要求**：「尊重用户手动设置的 min/max」。

### A3 `canvas.scaleMode` **已经是完整支持的字段**

```
design.canvas.scaleMode = 0
UI 下拉存在，3 个选项：
  0:拉伸铺满（可能变形） / 1:保持比例（可能留边） / 2:保持比例并铺满（裁切）
SCALE_MODES 常量一致
```

读写链路齐全：`app.js` 读写 + `model.js` 解析/序列化 + `canvas.js` 变换
+ `pack.js` 导出 + `control-files.js` 宽高比计算。

> ⚠️ **更正 P5A-M02 报告第四节 4.4**：那里写「导出未暴露 scaleMode，用户只能手改 JSON」
> —— **这是错的**。M02 的 FIT 对照包之所以手写字段，是因为我用脚本生成 JSON（没走编辑器），
> 不是因为编辑器不支持。本项目**从未缺这个功能**。

### A4 状态灯无低值方向表达

```
NODE_IMAGE 节点字段：有 stateWarn / stateCritical；无任何 low / dir / below 类字段
```

→ 低值报警**必须新增持久化字段** = `icar.ui/2` 契约变更 → 按任务要求**本轮只出方案，不改协议**。

### A5 拼装表默认量程同样 0..100

```
createNode(NODE_GAUGE, { pid:"obd.rpm" }) + parts=[needle(无 pid)]
→ nodeMin=0 nodeMax=100，部件回落到节点量程
```

## 三、Android 新增行为测试（24 项）

### 无 Robolectric，用纯 JUnit 做**行为级**断言

任务要求「能做 Android 单元测试的，优先做行为级断言，而不是只检查源码里是否存在特定字符串」。
项目只有 `junit:junit` + `org.json`，**未引入 Robolectric**（避免为测试引入庞大框架）。

### `TrackStyleParseTest`（14 项）

| 关注点 | 断言内容 |
|---|---|
| 完整解析 | 11 个字段逐个断言（orient/radius/inset/glow/band/gradient/segments/ticks/fill/color/accent）|
| 缺 trackStyle | `parse(null)` → null |
| 空对象 | 全部取默认值 |
| 部分字段 | 只覆盖给定项 |
| **radius 边界** | -5→0、999→64、30→30 |
| **gradient 枚举** | 只认 fade/gloss；非法→null（不静默改）|
| **segments/ticks** | 9999→64、-3→0、10.7→10 |
| **fill** | 5→1、-1→0、null→null |
| **color** | 只认 `#RRGGBB`；"red"/"#F00"/""→null |
| 布尔/枚举 | inset/glow/band、orient 非法→h |
| 常量 | MAX_SEGMENTS/TICKS/RADIUS 与工具侧一致 |
| 真实片段 | 完整设计片段可解析 |

### `DesignNodeTrackDispatchTest`（10 项）

**锁死分派语义**（这是最关键的回归防线）：

| 断言 | 意义 |
|---|---|
| 普通图片 `trackStyle == null` | **否则所有普通图片会变成空白轨道** |
| 老文件无 trackStyle → null | 向后兼容 |
| 显式 null → null | — |
| 有 trackStyle → 解析出对象 | 走轨道分支 |
| 仪表/文字/分组 trackStyle == null | 其它类型不受影响 |
| **分派谓词** `isImage && trackStyle != null` | 三种节点分别验证 |
| 状态灯与轨道互不干扰 | states 独立 |

### ⚠️ 诚实边界

**这不等于 TrackView 的绘制结果已验证。**
`TrackView.onDraw()` 需要 Android 图形栈，纯 JVM 测试**无法覆盖**。
绘制正确性仍需真机人工验收（`P4F-GUI-004` ⑨⑩）。

## 五、发现和修复的缺陷

### 缺陷 1：`window.partKindName is not a function`（**已修复**）

| 项 | 内容 |
|---|---|
| **发现方式** | B2-5「嵌套 children 不丢失」测试触发 |
| **症状** | 一旦部件带有**嵌套 children**，属性面板**整个白屏** |
| **根因** | `panels.js:904`（`partRows`，depth>0 时递归）调用 `window.partKindName(q.kind)`，但**该函数从未定义** |
| **为什么之前没发现** | 只有「部件有嵌套子部件」才走到那一行；普通单层部件正常，所以历史测试没覆盖到 |
| **修复** | 在 `schema.js` 补 `window.partKindName`，实现与 `PART_KINDS` 同源（不复制名字表）|
| **回归** | B2-5a/b/c 三断言锁死 |

### 最小人工操作清单（2 个场景）

#### 场景 1：【Windows 浏览器】一次打开，约 15 分钟

1. 打开 `tools/icarui/index.html`
2. 选中**仪表** → 看 23 行属性、色带与子部件编辑器
3. 加 2 段色带 → 改颜色/透明度 → 删 1 段；点「按阈值生成」
4. 加 2 个子部件 → 用 ↑↓ 调顺序 → **看画布谁压谁变了**
5. Ctrl+Z / Ctrl+Y 各 3 次
6. 保存 → **刷新浏览器** → 看色带/子部件还在
7. 选中**普通图片** → 换素材 → 看画布**立即换图且没变糊**
8. 改宽高，看边框变化
9. 选中**条形轨道** → 改圆角/刻度/渐变
10. 选中**文字** → 改内容/宽高
11. 选中**容器** → 改 scale，看**子控件跟着放大且相对位置不变**
12. 对照 `screenshots/track-01..10.png` 看 10 种轨道效果

#### 场景 2：【Android 平板】一次装 App，约 10 分钟

1. Windows 做一个含**图片 + 状态灯 + 条形轨道**的设计 → 导出
2. 导入平板 App → **看条形轨道是否是代码绘制**（圆角/渐变/刻度/色带）
3. 并排开着 Windows 编辑器**对比**轨道外观
4. 看状态灯在真实 PID 下是否正常切换
5. 看仪表与图片显示

> **场景 2 最关键** —— `TRACK-APP-001` 能否关闭完全取决于第 2、3 步。

### 5.3 **新发现并修复的产品缺陷**

#### 缺陷：属性面板输入后「点画布空白处」丢失撤销记录

| 项 | 内容 |
|---|---|
| **发现方式** | 阶段 E 真实 CDP 鼠标点击 + 键盘输入（不是脚本直接调方法）|
| **复现步骤** | ① 选中控件 ② 在属性面板改数值 ③ **点画布空白处**失焦 ④ 按 Ctrl+Z |
| **症状** | Ctrl+Z 无效；撤销按钮 `disabled=true`，title「没有可撤销的操作」 |
| **根因** | 点画布空白 → `CanvasState.selection` 被清空 → `change` 处理器第 311 行 `selectedNode()` 返回 null → 提前 return → **`endLive()` 永不执行** → 撤销记录缺失 |
| **影响** | 用户最常见的「改完点旁边确认」操作会导致修改无法撤销 |
| **修复** | ① `PropertyUpdate` 暴露 `currentNodeId()` / `currentPath()`（读取 live 事务的 nodeId）<br>② `schema-panel.js` 的 `change` / `blur` 处理器在选中丢失时用该 nodeId 兜底 |
| **回归** | `verify-p4fm04-input-stability` E1-3b / E1-5（Ctrl+Z 250→180、Ctrl+Y 180→250）|

### 5.4 M03 遗留问题结论

| 问题 | 判定 | 依据 |
|---|---|---|
| **Ctrl+Y 重做未验证** | ✅ **已解决**（非缺陷）| M03 当时撤销本身就没生效，导致重做无法独立判定。修复撤销缺陷后 **Ctrl+Y 250→180→250 双向验证通过** |
| **面板刷新后输入落空** | ✅ **脚本时序问题**（非产品缺陷）| 实测面板刷新**不重建**输入框（同一元素）；改用「每轮重新定位 + 谓词等待」后连续 3 轮 **3/3 通过** |

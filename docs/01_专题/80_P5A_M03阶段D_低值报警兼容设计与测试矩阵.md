## 一、现有语义（审计，不猜测）

### 1.1 Android 侧唯一判定入口

`app/src/main/java/com/icar/obd/ui/dash/NodeStateResolver.kt` 的 `select()`：

```kotlin
val pid = node.statePid
if (pid.isBlank()) return states[NORMAL]
if (value == null) return states[NORMAL]
val def      = definitionOf(pid)                                  // PID 库定义
val warnAt   = node.stateWarn ?: def?.warnHigh ?: return states[NORMAL]
val max      = def?.maxVal ?: 100f
val criticalAt = node.stateCritical ?: (if (max > warnAt) warnAt + (max - warnAt) * 0.5f else null)
return when {
  criticalAt != null && value >= criticalAt -> CRITICAL ?: WARN ?: NORMAL
  value >= warnAt                            -> WARN ?: NORMAL
  else                                       -> NORMAL
}
```

**三条硬事实**：

1. **只有高值判定**（`value >= warnAt`），**没有任何低值分支**
2. `stateWarn` 只覆盖"报警线"，**不表达方向**
3. 自动推算的 `criticalAt = warnAt + (max - warnAt) * 0.5` 也是**朝上**的

### 1.2 无值 / 非有限值优先按"未知"处理

```kotlin
if (node.statePid.isNotBlank() && (value == null || !value.isFinite()))
    return Frame(null, true, 1f)     // unknown = 画 "--"
```

这条**必须保留**：断连、NaN、无值时先走未知，不参与任何阈值比较。

### 1.3 编辑器侧有**两份**平行实现（跨端一致性风险点）

| 位置 | 作用 |
|---|---|
| `js/canvas.js:1779-1785` | 画布**预览**的状态灯选图（与 Android 同口径）|
| `js/app.js:1720` / `panels.js:667` / `editor.js:198-202` | 属性面板编辑 `stateWarn` / `stateCritical` |

→ 低值报警**必须同时改三处**，否则"电脑上看着对、设备上不对"。

### 1.4 PID 库已有 `warnLow`，但状态灯**用不上**

| PID | warnLow | warnHigh | min | max |
|---|---|---|---|---|
| 水温 `std_05` | 60 | 105 | -40 | 215 |
| 电压 `std_42` | **11.8** | 15.2 | 0 | 20 |
| 油量 `std_2F` | 15 | — | 0 | 100 |

实测（P5A-M02 阶段 C）：电压 11.03 < warnLow 11.8 时，绑 `warnLow` 语义的灯**仍是绿**。

## 二、为什么必须新增字段才能正确表达

想「不加字段」有三条路，逐条否掉：

| 方案 | 为什么不行 |
|---|---|
| A. 让 `stateWarn` 自动选方向（值 < 中点就判低）| **静默改语义**：旧主题里 `stateWarn=105`（水温高报）在低温 20℃ 时会被判成报警 —— 直接违反「旧主题结果必须完全一致」|
| B. 无 `stateWarn` 时回落到 PID 的 `warnLow` | 同样静默改语义：所有绑了电压/油量的现有灯会突然开始报警 |
| C. 用负值表示"低值"（如 `stateWarn = -11.8`）| 与既有语义**冲突**（负阈值本身合法，水温 min = -40），会产生模糊优先级 |

**结论**：必须在设计文件里**显式**写"这个灯判低值"，否则无法既支持低值报警、又保证旧主题一字不变。

## 三、字段方案（建议，待批准）

### 3.1 新增可选字段 `stateDir`

```jsonc
{
  "id": "l_volt_low", "type": "image", "name": "低电压灯",
  "statePid": "std_42",
  "stateDir": "low",              // ★ 新增；缺省 = "high"（现有行为）
  "stateWarn": 11.8,
  "stateCritical": 10.5,
  "states": { "normal": {...}, "warn": {...}, "critical": {...} }
}
```

| 字段 | 类型 | 缺省 | 语义 |
|---|---|---|---|
| `stateDir` | string | `"high"` | `"high"` = 现在的高值判定；`"low"` = 低值判定 |

**向后兼容性**：
- 缺省 `"high"` → **不含该字段的旧文件行为逐字节一致**
- 未知取值（如 `"sideways"`）→ 视为 `"high"` 并给出 warning（不崩、不静默）

### 3.2 判定逻辑（新增分支，保持既有分支不变）

```kotlin
val dir = node.stateDir.takeIf { it == "low" } ?: "high"     // 未知 → high
val warnAt = when (dir) {
    "high" -> node.stateWarn ?: def?.warnHigh ?: return NORMAL
    else   -> node.stateWarn ?: def?.warnLow  ?: return NORMAL   // low 方向才回落到 warnLow
}
val criticalAt = node.stateCritical ?: when {
    dir == "low"  -> { val min = def?.minVal ?: 0f
                       if (warnAt > min) warnAt - (warnAt - min) * 0.5f else null }
    else          -> { val max = def?.maxVal ?: 100f
                       if (max > warnAt) warnAt + (max - warnAt) * 0.5f else null }
}
return when {
    dir == "low" && criticalAt != null && value <= criticalAt -> CRITICAL ?: WARN ?: NORMAL
    dir == "low" && value <= warnAt                            -> WARN ?: NORMAL
    dir == "high" && criticalAt != null && value >= criticalAt -> CRITICAL ?: WARN ?: NORMAL
    dir == "high" && value >= warnAt                           -> WARN ?: NORMAL
    else                                                       -> NORMAL
}
```

**优先级无歧义**：
- `stateDir` 只决定**比较方向**
- `stateWarn` / `stateCritical` 仍是**唯一阈值来源**（节点值优先，其次 PID 库同方向的阈值）
- `high` 方向**永远不看** `warnLow`；`low` 方向**永远不看** `warnHigh`
- 无值 / NaN / 断连 → **先走 unknown**，任何方向都不参与比较（顺序不动）

### 3.3 缺失值"不猜"原则

- `stateDir = "low"` 且既没有 `stateWarn` 也没有 `def.warnLow` → 返回 **NORMAL**（与现有"没有阈值就恒正常"一致），并建议在导入时给 warning：「这个灯设了低值方向但没有可用阈值」

## 六、迁移策略

1. **不需要数据迁移**：`stateDir` 缺省即 `"high"`，旧文件不动
2. **编辑器**：只有用户主动把方向改成 `"low"` 才写出该字段；改回 `"high"` 时**删除字段**（保持文件干净）
3. **App**：新版本读旧文件 → 完全旧行为；旧版本读新文件（含 `stateDir`）→ 忽略未知字段，行为退回 high（**可接受**：旧版本来就没有低值报警）
4. **文档**：CHANGELOG 明确写「新增可选字段，缺省不改变任何既有主题」

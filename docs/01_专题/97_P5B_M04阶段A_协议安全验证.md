## 四、🔴 A5：未知 node type 是否被静默跳过 —— **两侧都有风险**

### 编辑器侧（`canvas.js:725-727`）

```js
if (n.type === window.NODE_GAUGE) drawGaugeNode(n);
else if (isImage) drawImageNode(n);
else if (n.type === window.NODE_TEXT) drawTextNode(n);
// ← 没有 else 分支
```

**结论：未知 type 静默不画，无任何警告。** 这正是任务 §三 第 5 条要查的。

### Android 侧（`NodeTreeRenderer.kt:343-347`，P5B-M03 已查明）

```kotlin
else -> {
    rec(rptUnknown, "${node.id}(${node.type})")   // 只进 BuildReport
    null
}
```

**结论：记录了但界面无提示** —— 用户看不到。

### 任务 §四 B2 的硬要求

> 「对包含不认识的关键节点的 v3 主题，**必须产生明确错误或不可忽略的警告**。」
> 「**不得静默输出缺少重要动态仪表的主题。**」

**所以 B 段必须同时改两侧**：
- 编辑器：`drawNode` 加 `else` 分支，画出"未知控件"占位 + 收集警告

## 五、✅ A6：升级/重保存/Undo 是否会丢数据 —— **已规避**

### 关键证据（源码注释）

`DesignFile.kt:758`：
> `DesignFile.toJson()` —— 那是个**只认 v1** 的序列化器（只写 `gauges`）。

`CanvasSettingsFragment.kt:960`：
> 为什么存原文而不是序列化 d：`DesignFile.toJson()` 写的是 v1

**结论**：Android **不用 `toJson` 保存 v2/v3 主题，而是存原文** —— 所以**不会丢节点**。

`DesignFile` 有 `pages` / `DesignPage`（L82/L110/L446），但**没有** `DesignNode.toJson()` 的 v2 导出路径。这是**刻意的**（P5B-M03 的任务也是"不经授权不改契约"）。

**B 段待办**：为 v3 增加**只读不写**的保障 —— v3 主题在 Android 上**不许被改写成 v2**。
（现在的"存原文"机制已经保证了这一点，需要在测试里**钉住**它。）

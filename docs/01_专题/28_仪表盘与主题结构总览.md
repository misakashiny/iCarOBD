# 仪表盘与主题结构总览

> 梳理「仪表盘/主题」相关的**全部结构框架与控件**，供主题方向开发定位用。
> 只覆盖仪表盘与主题，不含 PID/CAN/连接/日志等其他模块。
> 记录写入前实际读时：2026-10-17T15:54:25.6136293+08:00。本文只做结构索引，不改变任何产品结论；历史失败与未验项另见各自报告。

## 一、数据链路（渲染层只认 pidId）

```
数据源（三选一，互斥）
  ① ObdEngine       真车轮询，按 pollInterval
  ② SignalSimulator 合成信号 10Hz
  ③ 无数据源         总线上没有值 → 仪表显示 --
        │ 写（推）
        ▼
   VehicleBus   按 pidId 存最新值 + 历史 150 点；带 Source/epoch 代际与 TTL
        │ 读（拉）
        ▼
   渲染层  Android 自绘 DashRenderer / NodeTreeRenderer（5Hz 主动拉）
           LVGL(C) LvglDashView —— 已放弃(dashEngine 默认 0)，代码仍在但不维护
```

关键性质：**写是推、读是拉**；渲染层不认识数据源，只认 `pidId`；因此模拟与真车同路，必须显示「模拟数据」提示。

## 二、两种设计文件格式（并存，v1 仍支持）

| | `icar.ui/1`（旧，扁平） | `icar.ui/2`（**当前主用**，节点树） |
|---|---|---|
| 结构 | 扁平 `gauges: [...]` | 节点树 `nodes: [...]`（group/image/gauge/text） |
| 解析器 | `data/DesignFile.kt` | `data/DesignNode.kt` |
| 能力 | 只能放仪表 | 图片·层级·变换·状态·子部件拼装 |
| 工具 | 手写 JSON | **ICarUI**（`tools/icarui/index.html`，双击即用） |
| 状态 | ✅ 仍支持（存量） | ✅ **当前主用** |

两处共用 `GaugeItem.fromJson`，所以 `style`/`min`/`max`/`pid` 语义相同。字段详见 [13_UI设计指南](13_UI设计指南.md)（v1）与 [12_主题设计大纲](12_主题设计大纲.md) §二（v2 权威）。

## 三、坐标与变换

- 画布每轴 **0..360**（归一化 × 360）；`x/y` 为**相对父节点**的左上角，`w/h` 为尺寸。
- `rotation` 绕自身中心、**在设备空间**施加（先排版再旋转）；`scale` 在 w/h 之上绕中心额外倍率。
- `z` **同一父节点内**绘制顺序，大者在上。拖拽网格 `STEP = 360/24 = 15`，`MIN_SIZE = 30`。
- 外部主题（Sky Gauge）例外：正方形 360×360，导入必须**统一缩放（取屏幕短边）+ 居中**，不能两轴各自缩放。

## 四、节点类型（`DesignNode.type`，共 4 种）

| type | 中文 | 关键字段 | 说明 |
|---|---|---|---|
| `gauge` | 仪表 | `gauge: GaugeItem`、`card: CardOverride`、`parts: List<GaugePart>?`、`labelFont`、`showLabel`、`showRange` | 复用 v1 全部字段；`parts` 非空时**不再走 style 程序化画法** |
| `image` | 图片 | `assetId`、`statePid`、`stateWarn/stateCritical`、`states: Map<String,NodeState>` | 三态故障灯；位置只写一次，三张图共用 |
| `text` | 文字 | `text`、`font: GaugeFont` | 静态文字 |
| `group` | 分组 | `children` | 组/嵌套；深度上限 **32 层** |

公共字段：`id`、`name`、`x/y/w/h`、`rotation`、`scale`、`alpha`、`z`、`locked`、`visible`、`children`。
约束：一屏最多 **200 节点**（`MAX_NODES`）；`TYPES`/`TYPE_NAMES` 与 ICarUI 侧 `NODE_TYPES` 由跨语言比对钉住。

## 六、子部件系统（`GaugePart`，v2.12.0 起）

一个仪表可拆成**可替换部件**，而非只能选一种画法。**绘制顺序 = 列表顺序**（先画的在下）。

| kind | 名称 | 说明 |
|---|---|---|
| `dial` | 表盘 | 底图/底盘 |
| `ticks` | 刻度 | 刻度线/文字 |
| `needle` | 指针 | 绕 `pivotX/pivotY` 转；`sweepFrom/sweepTo` 定扫描范围 |
| `value` | 数值 | 数字区（不用 assetId） |
| `decor` | 装饰 | 任意附加素材 |

字段要点：
- `assetId`、`x/y/w/h`（画布单位）、`alpha`、`rotation`
- **`pivotX/pivotY`** 相对自身 0..1 —— 指针轴心基本不在图片中心，设 0.5/0.5 会转歪
- **`pid`**（v2.17.0）：空 = 用仪表节点的 pid；设了用它 —— 双针表（转速+车速）靠此；**量程也跟着走**，否则车速按转速角度映射指针几乎不动
- **`children`**（v2.18.0）：子部件以**父 pivot 为原点**并**继承父旋转**（指针挂配重/装饰）
- **`sweepFollow`**（v2.27.0）：扫描范围跟随仪表，双针共用 135°→405° 时免逐针填

角度必须与工具侧 `partAngle()` **逐字一致**，否则"电脑上指 3000、设备上指 2800"会被当成数据不准。

## 七、主题系统（`GaugeTheme`）

内置 3 套 + 用户自建（`CUSTOM_ID_BASE = 100` 起）：

| id | 别名 | 名称 | 描述 |
|---|---|---|---|
| 0 | `neon` | 霓虹赛道 | 橙黄辉光，强调转速与性能感 |
| 1 | `ice` | 冰蓝极简 | 冷色调 |
| 2 | `amber` | 经典琥珀 | 低干扰琥珀字，夜间更克制 |

**别名才是跨机器稳定的**（数字 id 会随自建主题分配变化，设计文件写名字 `"neon"`）。

主题字段（14 个颜色 + 若干尺寸/行为）：

| 分组 | 字段 |
|---|---|
| 颜色 | `background`、`surface`、`surfaceEdge`、`accent`、`accentHot`、`accentDim`、`track`、`tick`、`needle`、`value`、`label`、`dim` |
| 卡片 | `cardRadiusDp`(18)、`cardStrokeDp`(1)、`cardAlpha`(255) |
| 几何 | `strokeDp`(9)、`needleLengthRatio`(0.62) |
| 刻度环 | `defaultRingStyle`(0)、`defaultRingSegments`(40) |
| 霓虹 | `neon: NeonStyle`、`glow` |
| 动效 | `easingMode`、`easingTauMs`(120)、`valueSmoothingMs`(90) |
| 其他 | `custom` |

## 八、霓虹系统（`NeonStyle`）

可全局设，也可**单块表覆盖**（`GaugeItem.neonPreset`，null = 跟随全局）。字段都是**乘数而非像素**（同一套样式的手机小表与平板大表都好看）。

| 预设 | layers | spreadRatio | intensity | textGlow |
|---|---|---|---|---|
| 关闭 | 0（disabled） | — | — | — |
| 克制 | 2 | 0.022 | 0.7 | false |
| 标准（默认 AUTO） | 0=自适应 | 0.035 | 1.0 | true |
| 强烈 | 8 | 0.055 | 1.25 | — |
| 夸张 | 11 | 0.075 | 1.5 | — |

`MAX_LAYERS = 12`（再多肉眼无差别只烧 GPU）。绘制入口 `NeonPainter`。

## 九、卡片覆盖（3 档粗 + 1 层细）

**粗档** `GaugeItem.cardStyle`（`Int?`，null = 跟随主题）：

| 值 | 含义 |
|---|---|
| 1 | 无边框（保留卡片底） |
| 2 | 完全透明 |
| 3 | 不画卡片 |

**细档** `DesignNode.card: CardOverride`（`show` / `alpha` / `radius`）—— 表达"半透明 + 大圆角"这类粗档做不到的组合。
优先级：`card` 的字段覆盖 `cardStyle` 对应项，缺的仍跟随主题。

> 为什么是枚举而不是三个数值：存 `radius/stroke/alpha` 会让 JSON 变胖，且"改主题圆角时覆盖项要不要跟着变"永远说不清。

## 十、状态系统（图片节点三态）

`NodeState`：`assetId`、`alpha`、`blink`、`blinkMs`。

- 状态名：`normal` / `warn` / `critical`（中文 正常/警告/严重）
- 阈值：`stateWarn` / `stateCritical` 可**覆盖 PID 库推断**（不同车报警线不同）
- **`MIN_BLINK_MS = 400`**（2.5 Hz，依据 WCAG 2.3.1「每秒不超过三次闪烁」；文件里写更小也不许照闪，数据层强制）——与工具侧 `MIN_BLINK_MS` 同源、跨语言钉住

## 十一、字体与值映射

- `GaugeFont`：表上文字（名字/PID/量程）的字体设置
- `valueLabels`：数值 → 文字映射（挡位 `P/R/N/1..6` 靠它）。**指针/弧/条仍按数值走**，映射只换读数文本，不换几何
- 语义 PID 别名（`obd.rpm` / `obd.speed` / `calc.gforce` 等）：写别名比写 `std_0C` 可读；条数以 `DesignFile.PID_ALIASES` 为准，由 `ThemeStudioSampleTest` 守着"不漏"

## 十二、色带（`bands`，v2.87.0 工具侧 / v1.20.22 App 侧）

`[{ from, to, color, alpha }]`，最多 8 段，`color` 只认 `#RRGGBB`，`alpha` 0..255。

**三条不能忘的语义**：
1. **不参与报警判定** —— `warnLow`/`warnHigh` 才是报警源；让色带顺带改报警 = 静默改变存量设计的安全语义
2. **空表 = 完全旧行为**（绘制走 `warnLow`/`warnHigh`，老文件逐像素不变）
3. 只影响**画出来的分区**

## 十五、多画布

- 每页有独立 `DashCanvas`（含 id、设计内容），由 `DashCanvasPagerAdapter` 分页
- **只有当前页跑 5Hz 定时器**（`DashFragment.updatePageActivation()`）——查"某画布不刷新"先看它是不是当前页
- 每页渲染 `DashSpec.buildFor(canvas)` 各自的盘面，**不是**当前画布的

## 十六、当前主题方向可选切入点

> 以下是结构上已经存在、但尚未做满的位置，供选方向时参考（不是任务清单，激活前须另立卡）。

1. **子部件系统（`GaugePart`）** —— 已支持 dial/ticks/needle/value/decor + 嵌套 + 多指针 + sweepFollow，但工具侧拼装体验与素材覆盖是短板
2. **状态系统** —— 三态 + 闪烁已就位，指示灯类素材 106 个，可做更完整的故障灯盘面
3. **色带 `bands`** —— 工具侧已落地、App 侧 v1.20.22 才读完，视觉分区尚未被充分利用
4. **卡片细档 `CardOverride`** —— 半透明/大圆角组合表达力已有，但 UI 暴露程度有限
5. **霓虹 5 档** —— 已可单表覆盖，可做更细的观感分级
6. **`CanvasSettingsFragment.kt`（77KB）** —— 全项目最大单文件，主题设置 UI 的集中地，也是维护负担集中处

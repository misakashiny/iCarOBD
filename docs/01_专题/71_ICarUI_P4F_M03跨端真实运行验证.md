## 二、Android 轨道截图及对比结果

### 截图

`docs/02_验证记录/screenshots/android-05-tracks.png`（1080×2400，有效 PNG）

### 对比方法

**不是比文件大小**。做法：
- 建立设计坐标 → 屏幕像素的映射：`sx = dx/360*W`，`sy = 128 + dy/360*(H-128)`
- 对每个轨道区域做**颜色统计**（平均/最小/最大 RGB + 唯一色数）
- 与纯色基准做**区域特征差异**对比

| # | 检查项 | 结果 |
|---|---|---|
| 1 | 位置与尺寸（9 个区域全部采样到）| ✅ 每区 15946~16184 采样点 |
| 2 | 方向（垂直轨道是竖条）| ✅ 区域 22×150 映射正确 |
| 3 | 色带（h_band 应为橙黄）| ✅ **最大 R=255, G=219**（红端+黄端都在），唯一色数 62（有渐变）|

### ⚠️ 诚实边界

- **不宣称逐像素一致**；抗锯齿与缩放差异属预期

### 关键技术发现

**草稿结构不是 `{design: {...}}`，而是**：

```
{ draftId, designId, designName, designJson: "<string>",
  nodeCount, assetCount, byteSize, checksum, revision, complete }
```

`designJson` 是**字符串**，需要 `JSON.parse`。另有独立的 `undoHistory` store 保存撤销栈。

### 隔离保证

- 使用**独立 `user-data-dir`**（每次新建临时目录，结束时删除）
- 只操作自己创建的 `draftId`
- **未触碰用户真实草稿**

## 五、发现及修复的缺陷（**3 个真实缺陷**）

### 缺陷 1：`window.requestDraw` 从未定义

| 项 | 内容 |
|---|---|
| 发现 | D2 未定义函数扫描（191 个函数中检出）|
| 调用处 | `schema-panel.js:234`、`schema-props.js:936`、`schema-props.js:1013` |
| 症状 | `if (window.requestDraw) window.requestDraw();` **永远不执行** |
| 影响 | Schema 面板改值后靠 `refreshAll()` 附带重绘，那些只想「画一下」的路径完全失效 |
| 修复 | `app.js` 补 `window.requestDraw = () => window.draw()` |
| 回归 | D2-2（191 个函数 0 缺失）|

### 缺陷 2：`window.updateUndoButtons` 未挂到 window

| 项 | 内容 |
|---|---|
| 发现 | 同上 |
| 症状 | `updateUndoButtons` 是 `app.js` 内的**函数声明**（闭包内），但 `draft-manager.js:462/860` 用 `window.updateUndoButtons && ...` 访问 → **永远短路** |
| 影响 | **草稿恢复后撤销按钮状态不更新** |
| 修复 | `app.js` 补 `window.updateUndoButtons = () => updateUndoButtons()` |

### 缺陷 3：`window.assetBitmapUrl` 从未定义

| 项 | 内容 |
|---|---|
| 发现 | 同上 |
| 调用处 | `catalog-panel.js:104` |
| 症状 | `typeof window.assetBitmapUrl === "function"` 永远为假 → **控件库素材缩略图永远走占位符** |
| 修复 | `canvas.js` 补 `window.assetBitmapUrl = (id) => S.assetUrls[id] \|\| S.thumbs[id] \|\| null` |

### 修复效果

修复前：191 个 `window.*` 函数中 **3 个缺失**
修复后：**0 缺失** ✅

> 已与 JSON 逐条核对一致。

### 1.3 根因（一句话）

M03 用「`canvasArea` 的 uiautomator bounds + 自己按公式算 k 与居中偏移」来定位 8 条轨道。
而 `canvasArea` 的 bounds 含额外 padding、且画布是垂直居中于**可用高度 567px**
（600 − 33 状态栏），不是 M03 假设的 526px。
于是采样框在 y 方向偏了约 **72px**，正好落在两排轨道之间的空白 → 测到背景亮度 27/44。

**用真实矩形重测同一批截图（同一份 PNG，未重新采集）**：

| 键 | `t_h_band` 区域 | max | 均 | 主色 |
|---|---|---|---|---|
| fit/carwide | 654,103-887,152 | **176** | **142** | `[152,222,154]` 绿 |
| fit/tablet | 824,165-1216,248 | **176** | **143** | `[154,221,154]` 绿 |
| fit/phone | 570,784-1050,886 | **176** | **143** | `[152,222,154]` 绿 |

band 轨道的**平均亮度 142 是全屏 8 条里最高的**（其它 62~106）—— 因为它铺满整条三色渐变。

### 1.4 诊断中发现并修掉的**第二处测试缺陷**

采集 `fit/carwide` 时，`setDisplay` 切到 1280×600 后**立刻**抓 uiautomator，
拿到的还是上一档（1600×1000）的布局 → 矩形 `maxY=881 > 600`，与截图对不上。
已在采集脚本加**硬校验**：矩形越界就等待重抓（最多 6 次）。

### 1.5 A2 交叉对比（确认不是 FILL/纵向/其它组合的问题）

| 组合 | 结果 |
|---|---|
| `band=true, fill=null`（`t_h_band`）| 6 档全部渲染 ✅ |
| `band=false, fill=0.55`（`t_h_fill`）| 6 档全部渲染 ✅ |
| 纵向（`t_v_fill`）| 6 档方向正确 ✅ |
| FIT / STRETCH | 都正常 ✅ |
| 手机 / 平板 / 车载宽屏 | 都正常 ✅ |

`TrackView.onDraw` 逐段核对：`band` 分支（169-184）设置渐变 shader 后，
在 204-205 统一 `drawRoundRect`；无 `save/clip` 泄漏；`canvas.save/restore`
只在填充段（269-282）成对出现。**绘制路径无缺陷**。

## 五、PID 量程保护结果

### 5.1 M03 的漏洞

`rangeWasDerived` 用「min/max 恰好等于 PID 定义」推断"这是自动填的"。
任务明确要求：**不能仅靠数值相等就绝对判定用户未手动设置** —— 用户完全可能手填一个正好等于默认的值。

### 5.2 M04 的做法：编辑期**来源标记**

```
n.__rangeAuto = { pid, min, max }     // 只在内存，不进设计文件
```

- 只有"自动填的入口"打标记：`createNode`（不传 min/max，**或传的值恰好等于该 PID 定义**）、
  换 PID 跟随之后、`applyPidDefaults`
- 用户手改 min/max（走 `setNodeNum`）→ **立即清除标记**
- 换 PID 时三条同时成立才跟随：① 有标记 ② 标记 pid == 旧 pid ③ 标记值 == 当前值
- 标记**不进设计文件**（`toV2Json` 只写已知字段）；草稿/导出/重新导入后消失 → 那就不再跟随（**保守**）

### 5.3 9 条测试结果（19 断言全绿）

| # | 用例 | 结果 |
|---|---|---|
| C1 | 新建自动填 PID 量程（rpm/speed/coolant）| ✅ 全部正确且已标记 |
| C2 | 手填量程 ≠ PID 默认 → 换 PID 不覆盖 | ✅ 999~7777 保留 |
| **C3** | **手填量程恰好等于 PID 默认 → 也不覆盖** | ✅ 0~8000 保留（走"先建后手改"真实路径）|
| C4 | 原 PID 是自定义 | ✅ 换内置 PID 后跟随 |
| C5 | 新 PID 是自定义 | ✅ **保留原量程**（无定义不乱改）|
| C6 | 主动点「回填量程」 | ✅ 跟随并重新成为派生 |
| C7 | Undo / Redo | ✅ 8000→200→Undo 8000→Redo 200 |
| C8 | 导出/重新导入 | ✅ 导出**不含** `__rangeAuto`；重导入后无标记 → 换 PID 保留（保守）|
| C9 | 旧主题手填量程 | ✅ 1234~5678 不被静默覆盖 |

### 5.4 与既有契约的关系

既有套件 `verify-data-bindings`（217 断言）要求 `source range follows binding` ——
预设/内置控件显式传 `info.min/max`，那条路径**仍然跟随**（`createNode` 判定"值等于 PID 定义 → 派生"）。
**217/217 全绿**，契约未破。

## 六、低值报警兼容方案的补充结论

**未修改 `icar.ui/2` 契约**（任务要求）。本轮补充见
[82_P5A_M04阶段D_低值报警兼容性补充](82_P5A_M04阶段D_低值报警兼容性补充.md)：

### 6.1 最重要的新发现：旧版 App 会**反向报警**

| 场景 | 旧版 App（不认 `stateDir`）| 危险性 |
|---|---|---|
| `stateDir:"low"` + `stateWarn:11.8` | 按 high 判 `value >= 11.8` → 电压 13.8V **判成 warn** | 🔴 一直亮黄灯 |
| 再加 `stateCritical:10.5` | `value >= 10.5` → 13.8V 直接 **critical 红灯** | 🔴 更危险 |
| 只有 `stateDir:"low"` 无阈值 | 回落 `warnHigh`(15.2) → 13.8V 接近，可能误报 | 🟠 中 |

→ **不是"功能不生效"，是更糟的错误行为**。必须在**导出端**拦住（旧版 App 无法自我保护）。

### 6.2 本轮补充的四项

1. **导出端版本警告**：设计含任何 `stateDir:"low"` 时，导出弹明确警告 + 可选 `manifest.requires`
2. **新旧版本功能矩阵**（5 种能力 × 2 个版本）
3. **阈值优先级 + 5 类非法阈值校验**（方向隔离：low 永不读 warnHigh，high 永不读 warnLow）
4. **"不能静默宣称有效"的 4 条约束**：无阈值/方向设反/旧版打开/测试必须有负面用例

### 6.3 未做的（等批准）

实现 `stateDir`、改 `manifest`、抽共享判定函数 —— 均涉及契约或跨端重构，**待统一批准**。

### 7.4 FILL 模式的如实说明

FILL 是"等比铺满 + 裁切"。在 1280×600 上 `k=max(1280/360,567/360)=3.56`，
画布 1280×1280 → 上下被裁掉约 340px，**部分轨道超出屏幕**。
因此 uiautomator **看不到**这些 View（不可见节点被略过），抓不到矩形 →
**FILL 无法用"真实矩形"做像素判定**。三张 FILL 截图保留作证据（亮像素占比 5.7%~11.1%，确认有渲染），
但**不纳入 38 条断言**。这是 FILL 的固有语义，不是缺陷。

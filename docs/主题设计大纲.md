## 一、为什么需要一次重构

v1 的格式（`icar.ui/1`）把仪表盘描述成**一个扁平的 `GaugeItem` 列表**：

```
gauges: [ {pid, style, min, max, x, y, w, h, ...}, ... ]
```

`GaugeItem` 是**复合控件** —— 一个「圆表」在渲染层会展开成弧 + 刻度 + 指针 + 标签。
这个模型对"用预设样式搭盘面"很好用，但对**做设计**有四个硬限制：

| 限制 | 后果 |
|---|---|
| 只能放仪表，**不能放图片** | 做不出"碳纤维底 + 车标 + 装饰线"这类真实主题 |
| 没有**层级**概念 | 控件重叠时只能靠添加顺序，无法显式控制谁盖谁 |
| 没有**变换**（旋转/缩放/透明度） | 指针不能斜着装，素材不能半透明 |
| 没有**状态** | 一个故障灯无法表达"正常/警告/严重"三张图 |

再加上编辑器本身缺**撤销**、**控件树**、**素材管理**，导致"做一个主题"实际是
"手写 JSON + 反复推设备看效果"。

所以格式要升到 **`icar.ui/2`**：从「扁平仪表列表」改成「**节点树**」。

## 二、核心模型：节点树

### 2.1 一个节点是什么

```json
{
  "id": "n2",
  "type": "gauge",
  "name": "RPM",
  "parent": null,

  "x": 0, "y": 0, "w": 240, "h": 240,
  "rotation": 0,
  "scale": 1,
  "alpha": 255,
  "z": 10,
  "locked": false,
  "visible": true,

  "children": [ { "id": "n3", "type": "image", "name": "Needle", ... } ],

  "pid": "obd.rpm", "style": 0, "min": 0, "max": 8000, "warnHigh": 6500
}
```

**关键决策：`gauge` 节点的字段与 v1 的 `GaugeItem` 同名同义**，不另起一套。
理由是迁移成本 —— v1 的 `gauges[]` 每一项都能**一对一**变成一个 `type: "gauge"` 的
根节点，不需要字段映射表。`GaugeItem.fromJson` 的逻辑可以原样复用。

### 2.2 四种节点类型

| type | 是什么 | 专属字段 |
|---|---|---|
| `group` | 纯容器。用来给一组控件**统一变换**（转整个表盘） | — |
| `image` | 图片素材 | `assetId` + `states` |
| `gauge` | 仪表（复用 v1 的 `GaugeItem` 全部字段） | `pid` / `style` / `min` / `max` / … |
| `text` | 静态文字（标题、单位说明） | `text` / `fontSize` / `color` |

`group` 存在的意义：**变换要能成组**。想让整个转速表倾斜 15°，不该逐个改子节点。

### 2.3 变换的语义（**必须写死，否则各端实现会分叉**）

| 字段 | 语义 | 范围 |
|---|---|---|
| `x` / `y` | **相对父节点**的左上角（画布单位 0..360） | 可越界（父节点可裁剪） |
| `w` / `h` | 尺寸（画布单位） | ≥ 1 |
| `rotation` | **绕自身中心**顺时针旋转，**在设备空间施加**（见下方⚠️） | 度，任意实数，归一化到 0..360 |
| `scale` | 在 `w/h` 之上的**额外**缩放（绕中心） | > 0，默认 1 |
| `alpha` | 不透明度 | 0..255 |
| `z` | **同一父节点内**的绘制顺序，**大者在上** | 任意整数 |

> ⚠️ `scale` 与 `w/h` 是**乘法关系**，不是替代关系。
> 这样"把素材等比放大 1.5 倍"不需要改 `w/h`（改了会丢原始尺寸信息）。

#### ⚠️ 旋转必须在**设备空间**施加（v2.2.0 的重要修正）

**先排好版、再旋转**，不是"先旋转、再缩放"：

```
盒子矩阵（平移 + 缩放，不含旋转）→ 画布矩阵 → 再在设备空间绕盒子中心转 θ
```

**为什么**：`stretch` 缩放模式下画布矩阵是**每轴独立**的（16:10 屏上是
2.183 × 1.364）。若把旋转写在节点空间（`画布矩阵 · … · R(θ)`），
就成了"先旋转、再非等比拉伸" —— **矩形被拉成平行四边形**。实测：

| 角度 | 外框 | 内容尺度 |
|---|---|---|
| 0° | 矩形 | 1.364 |
| 15° | 平行四边形（相邻边不垂直） | 1.433 |
| 45° | 平行四边形（对角线差 **209px**） | **1.820（+33%）** |
| 90° | 矩形 | 1.364 |

也就是"旋转时外框歪掉、控件还会变大"。

**这与 App 一致**：`view.rotation = θ` 旋转的是**已经排好版的设备盒子**
（`DashRenderer` 先按每轴归一化定位/定尺寸，再设 `rotation`），
所以 App 得到的是旋转矩形、尺寸恒定。编辑器必须照做。

**逐层累积**：每一层的旋转都在设备空间绕**该层自己的盒子中心**施加，
然后子节点在这个已旋转的坐标系里继续排布 —— 所以**分组旋转时子控件跟着转**，
且每一层各自都保持矩形（不被斜切）。

> 实现见 `canvas.js` 的 `withDeviceRotation()` / `deviceMatrix()`。
> **改旋转语义必须同时改这三处**：`deviceMatrix`、`withDeviceRotation`、
> `model.js` 的 `ungroupNode`（取消组合时要在设备空间换算，否则偏 23.7px）。

### 2.5 分组（v2.2.0）

`type: "group"` 的节点就是分组。**它建成时 `rotation=0`、`scale=1`（纯平移）**，
所以把子控件挪进去只差一个平移量，**视觉位置完全不变**。

| 行为 | 说明 |
|---|---|
| 拖动分组 | 子控件**一起动**（因为子坐标相对组） |
| 旋转/缩放分组 | 子控件跟着转/缩放（逐层设备空间旋转） |
| 点分组内部 | 选中**整个分组**（否则"一起拖动"就形同虚设） |
| 双击分组内部 | **下钻**，选中里面最深的那个控件 |
| 取消组合 | 子控件回到组的父级，**保持视觉位置** |

**打组的前提**：选中项的祖先不能带旋转/缩放。因为 `x/y` 是相对父节点的，
换父级时若原父级带变换，视觉位置会变 —— 而"打组不该让东西跳位置"是基本预期。
不满足时工具会拦下并说明原因（**且不往撤销栈里压空操作**）。

**取消组合的位置公式**（推导过程见 `model.js` 的注释）：
子中心要**在设备空间**绕组中心转 φ，然后转回父空间：

```
父空间中心 → 设备空间 → 绕组中心（设备） 转 φ → 回父空间
```

> ⚠️ 不能在父空间直接转：画布矩阵 `C` 非等比，`C(绕 gc 转 φ) ≠ 绕 C(gc) 转 φ`。
> 实测症状很典型：**父空间中心算得完全正确、设备空间只差一个轴（y 差 23.7px）**。

### 2.6 PID 的三种形态（**统一表示，别搞出两套**）

一个 PID 在三个地方有三种写法，必须明确谁是谁：

```
设计文件里            内部（节点上）                画布上
───────────────      ──────────────────────      ──────────────────
"obd.rpm"       →    pid     = "std_0C"      →   标签：发动机转速（友好名）
（语义别名）           rawPid  = "obd.rpm"          🏷 PID：std_0C（解析后的 id）
    或
"std_0C"        →    pid     = "std_0C"      →   同上
（直接写 id）          rawPid  = "std_0C"
```

| 字段 | 是什么 | 谁在用 |
|---|---|---|
| 文件里的 `pid` | 可以是**别名**（`obd.rpm`）或**id**（`std_0C`） | 人写、App 读（`resolvePid` 两者都认） |
| 节点上的 `pid` | **解析后的 id**（`std_0C`） | 内部查表：`BUILTIN_PIDS[pid]` 拿名字/单位/量程/阈值 |
| 节点上的 `rawPid` | **用户写的原样** | 编辑器回显 + 序列化时写回别名。**不写进文件** |
| 画布标签 | `BUILTIN_PIDS[pid].name`（友好名） | 给人看 |
| 🏷 PID 开关 | `pid`（解析后的 id） | 排查"这个表到底绑的哪个 PID" |

**为什么内部只存 id**：查表只能查一次、只有一种 key，不用到处 `resolvePid`。
**为什么还要存 rawPid**：序列化时写回别名（`obd.rpm` 比 `std_0C` 可读得多），
而且 PID 下拉框要能把当前值选中。

> 🔴 **`createNode` 与 `parseNode` 必须用同一套规则。**
> v2.2.1 修过一个 bug：`createNode` 直接把别名当 id 存了，
> 于是"预设建的表画布上写着 `obd.rpm`、导入的表写着发动机转速"，
> 而且预设建的节点**查不到内置库 → 单位丢失**。
>
> `statePid` / `rawStatePid`（状态系统的驱动 PID）同理。

### 2.8 控件库与控件编辑器（v2.3.0）

设计文件新增 **`controls`** 段：`[{id, name, node}]`，存**可复用控件模板**。
与 `assets`（图片）并列 —— 一个存图，一个存控件。

```
素材库
├─ 🧩 控件            11 个内置条目（8 种仪表样式 + 文字 + 分组 + 图片）
├─ 🧩 自定义控件       controls 段里的模板（跟着设计文件走）
└─ 📁 背景/仪表盘/…    图片素材（10 个分类，按相对路径引用）
```

**两种放入方式**：
- **单击** → 打开控件编辑器（"先改再放"）
- **拖拽** → 直接实例化到落点（`instantiateControl` 会深拷贝 + 换新 id）

**控件编辑器**（右键 →「编辑控件…」/ <kbd>F2</kbd>）三个关键设计：

1. **编辑草稿副本**（`S.editDraft`），画布上的原节点不动 —— 取消就是没发生
2. **预览复用画布绘制代码**（`drawNodePreview` 临时替换绘制目标 `ctx`）——
   不另写一份绘制，所以预览与画布**一定一致**。这是 `ctx` 用 `let` 而不是 `const` 的唯一理由
3. 「保存到素材库」写进 `controls`；「导出 JSON」单独下载（`kind: "icar.control/1"`）

> ⚠️ **模板节点会带 `locked`/`visible`**。保存时强制清成 `false`/`true` ——
> 否则"拖出来就是锁住的"，用户会以为工具坏了。

### 2.33 五个矩阵的分工（v2.25.0 / v2.26.0）

这是最容易搞错的一块，单独记一笔。

| 矩阵 | 谁在用 | 语义 |
|---|---|---|
| `deviceMatrix` | 图片内容 / 多选包围盒 | 节点局部 → 画布位图，**每轴独立**（stretch 下会拉伸） |
| `uniformMatrix` | **非图片节点的内容** | 同上但取 `min(sx,sy)` 等比、居中 —— 与 App 的 `min(w,h)` 一致 |
| `selectionMatrix` | **画框 / 手柄位置 / 手柄命中 / toLocal** | 非图片用 `uniformMatrix`，图片用原始矩阵 |

> ⚠️ **框与内容必须用同一个矩阵**。用错的话在 `stretch` 模式下框会比控件
> 宽 1.6 倍（实测 200×200 的表：框 481 vs 内容 301）。
>
> ⚠️ **画框、手柄位置、手柄命中、toLocal 四处必须一起改** ——
> 只改画框不改命中就会出现"框画对了但点不中"。

### 2.34 滚动条隐藏（v2.25.0）

```css
*::-webkit-scrollbar { width: 0; height: 0; }   /* WebKit */
* { scrollbar-width: none; }                     /* Firefox / 标准 */
```

### 2.31 素材悬停大图（v2.24.0）

缩略图 62px → 悬停弹 200×200 大图 + 素材名。

- **靠右边自动翻到左侧**（否则贴着面板边缘的会弹到屏幕外）
- `image-rendering: pixelated`（点阵素材放大后要看清像素）
- `pointer-events: none`（浮层挡鼠标会不停触发 enter/leave，闪个不停）

> **v2.30.0 补充：真懒加载**
>
> `index.html` 只静态加载 `builtin-index.js`（**36 KB**）；
> `js/app.js` 的 `loadAssetData()` 在**首屏之后**串行注入 11 个分类数据
> （`requestIdleCallback`，不卡交互），每到一个刷新一次缩略图。
>
> **首屏要等的东西从 ~700 KB 降到 36 KB。**
>

> 然后在"缩略图能不能解码"上失败。
>
> **改动会波及测试时，改测试的等待条件，不要放弃改动、也不要把测试放宽成"允许没数据"。**

### 2.28 点阵字库与数字刻度（v2.23.0）

`png.js` 新增 **5×7 点阵字库**：`drawText()` / `textWidth()`，47 个字形
（`0-9` + 常用符号 + `A-Z`）。

**为什么是 5×7**：车机刻度数字只有 8~14px 高。5×7 是能同时容纳数字与大写字母的
最小尺寸，**笔画是整像素**，缩到 8px 仍认得出。更大的字在小尺寸下反而糊。

> `scale` **强制取整** —— 非整数会让点阵糊掉，那就失去了点阵字体的意义。

**数字刻度素材**（scale 分类 23 → 54）：

| 类型 | 数量 |
|---|---|
| 单个数字块（`digit-0`~`digit-9` + 点/负号/百分号） | 13 |
| 径向数字刻度弧（0~4 / 0~8 / 0~10） | 3 |
| 横向数字行 / 纵向数字列 | 5 |
| 单位文字（RPM / km/h / °C / V / A / % / bar…） | 10 |

放反了的话 18 个数字控件全落进"图片/底盘"（实测踩到）。

### 2.25 等比缩放锁（v2.21.0）

| 操作 | 行为 |
|---|---|
| 拖角手柄 | 保持比例（**默认**） |
| + **Alt** | 临时自由拉伸 |
| 属性面板取消勾选 | 一直自由拉伸 |
| **组** | **不锁**（布局容器要能拉宽重排） |

**驱动轴的选择**：用「相对变化更大的那一轴」推另一边。
只按宽度驱动的话，鼠标横向拖一点、纵向拖很多时尺寸跟不上手。

### 2.26 控件编辑器预览的异步陷阱（v2.21.0）

**症状**：从控件库新建控件 → 编辑器预览显示**紫色占位 X**。40 个内置控件里 16 个中招。

**链路**：

```
make() → ensureBuiltinAsset() → S.design.assets 有素材了
                                    ↓ 但位图还没解码
syncAssetImages() → loadAssetImage() → img.onload = () => draw()
                                          ↑ 只重绘主画布，没重绘预览
```

**修法**：① 画预览前 `syncAssetImages()` ② `onload` 里补 `redrawEditorPreview()`。

> ⚠️ 用专门的 `redrawEditorPreview()` 而**不是**整个 `renderEditor()` ——
> 后者会重建 DOM，把用户正在输入的焦点弄丢。

### 2.24 素材库规模与「按比例定尺寸」（v2.20.0）

#### ⚠️ 添加素材时**必须按比例定尺寸**

`w` 与 `h` **不能各自独立夹取** —— 那会破坏宽高比，用户看到的是压变形的图。
正确做法：定最长边，另一边按比例算；夹取时两边乘**同一个系数**。

```js
const ar = nat[0] / nat[1];
if (ar >= 1) { w = LONG; h = LONG / ar; } else { h = LONG; w = LONG * ar; }
// 最短边保护：整体缩放，不是单独夹一边
if (w < MIN) { const k = MIN / w; w *= k; h *= k; }
```

> 素材原始尺寸取 `a.w/a.h`；没有就退回 bitmap 的自然尺寸
> （手改过的设计文件可能没记 w/h，那种情况下「变扁」比「没有尺寸」更糟）。

### 2.50 测试的临时目录会攒起来（v2.42.0）

`GaugeThemeTest` **没有 `@After`** —— 36 个测试方法，每次跑泄漏 **36 个**临时目录。
从 10/02 攒到 10/05，`%TEMP%` 里堆了 **2454 个**。

**规律**：`@Before` 里建临时目录的类，必须配 `@After` 删。
漏了不会报错、不会让测试红，**只是安静地占磁盘**。

> ⚠️ **两个清理陷阱**：
> 1. `File.deleteRecursively()` **返回 false 但不抛异常** —— 静默失败
> 2. `File.deleteOnExit()` **对非空目录无效**（Java 只在退出时删空目录）
>
> 还有：**进程被强杀时 `@After` 根本跑不到**，那部分残留只能人工清。

#### 根因：常开文件句柄（v2.42.0 续查）

`BackupTest` 的 `setUp` 调 `AppLog.init(dir)`，而 `AppLog` **为了性能故意保持一个
常开的 `BufferedWriter`** —— **那个句柄占住日志文件，Windows 就删不掉目录**。

`AppLog.clear()` 里的 `closeWriter()` 注释写着"必须先关掉句柄，否则删不掉文件"，
说明代码**早就知道** —— 但它**是异步的**（走 IO 线程），赶不上 `@After`。

补了同步的 `AppLog.shutdown()`。**但还没清零**：残留数会变（3~6），
说明是**和异步 IO 线程的竞态** —— `shutdown()` 关掉之后，队列里没跑完的任务
会把 writer 重新打开。

#### 竞态的解法：清队列 + 屏障（v2.43.0）

只"同步关句柄"还不够 —— 残留数**会在 3~6 之间变**，那就是竞态的信号。

**原因**：常开资源的**生产者是另一个线程**（这里是单线程 `io` 池）。
关掉句柄之后，排在你后面的任务**又会把它打开**。

```kotlin
io.queue.clear()                       // 丢掉没开始跑的
io.execute { closeWriter(); latch.countDown() }   // 屏障
latch.await(2, SECONDS)                // 单线程 → 屏障跑完 = 前面的也结束了
closeWriter()                          // 兜底
```

> **为什么不直接 `io.shutdown()`**：它是**对象级的 `val`，`init()` 不重建** ——
> 关掉之后下一个测试就跑不了了。屏障既不破坏执行器、又能等到队首结束。

## 一、为什么需要一次重构

v1 的格式（`icar.ui/1`）把仪表盘描述成**一个扁平的 `GaugeItem` 列表**：

```
gauges: [ {pid, style, min, max, x, y, w, h, ...}, ... ]
```

`GaugeItem` 是**复合控件** —— 一个「圆表」在渲染层会展开成弧 + 刻度 + 指针 + 标签。
这个模型对"用预设样式搭盘面"很好用，但对**做设计**有四个硬限制：

| 限制 | 后果 |
|---|---|
| 只能放仪表，**不能放图片** | 做不出"碳纤维底 + 车标 + 装饰线"这类真实主题 |
| 没有**层级**概念 | 控件重叠时只能靠添加顺序，无法显式控制谁盖谁 |
| 没有**变换**（旋转/缩放/透明度） | 指针不能斜着装，素材不能半透明 |
| 没有**状态** | 一个故障灯无法表达"正常/警告/严重"三张图 |

再加上编辑器本身缺**撤销**、**控件树**、**素材管理**，导致"做一个主题"实际是
"手写 JSON + 反复推设备看效果"。

所以格式要升到 **`icar.ui/2`**：从「扁平仪表列表」改成「**节点树**」。

## 二、核心模型：节点树

### 2.1 一个节点是什么

```json
{
  "id": "n2",
  "type": "gauge",
  "name": "RPM",
  "parent": null,

  "x": 0, "y": 0, "w": 240, "h": 240,
  "rotation": 0,
  "scale": 1,
  "alpha": 255,
  "z": 10,
  "locked": false,
  "visible": true,

  "children": [ { "id": "n3", "type": "image", "name": "Needle", ... } ],

  "pid": "obd.rpm", "style": 0, "min": 0, "max": 8000, "warnHigh": 6500
}
```

**关键决策：`gauge` 节点的字段与 v1 的 `GaugeItem` 同名同义**，不另起一套。
理由是迁移成本 —— v1 的 `gauges[]` 每一项都能**一对一**变成一个 `type: "gauge"` 的
根节点，不需要字段映射表。`GaugeItem.fromJson` 的逻辑可以原样复用。

### 2.2 四种节点类型

| type | 是什么 | 专属字段 |
|---|---|---|
| `group` | 纯容器。用来给一组控件**统一变换**（转整个表盘） | — |
| `image` | 图片素材 | `assetId` + `states` |
| `gauge` | 仪表（复用 v1 的 `GaugeItem` 全部字段） | `pid` / `style` / `min` / `max` / … |
| `text` | 静态文字（标题、单位说明） | `text` / `fontSize` / `color` |

`group` 存在的意义：**变换要能成组**。想让整个转速表倾斜 15°，不该逐个改子节点。

### 2.3 变换的语义（**必须写死，否则各端实现会分叉**）

| 字段 | 语义 | 范围 |
|---|---|---|
| `x` / `y` | **相对父节点**的左上角（画布单位 0..360） | 可越界（父节点可裁剪） |
| `w` / `h` | 尺寸（画布单位） | ≥ 1 |
| `rotation` | **绕自身中心**顺时针旋转，**在设备空间施加**（见下方⚠️） | 度，任意实数，归一化到 0..360 |
| `scale` | 在 `w/h` 之上的**额外**缩放（绕中心） | > 0，默认 1 |
| `alpha` | 不透明度 | 0..255 |
| `z` | **同一父节点内**的绘制顺序，**大者在上** | 任意整数 |

> ⚠️ `scale` 与 `w/h` 是**乘法关系**，不是替代关系。
> 这样"把素材等比放大 1.5 倍"不需要改 `w/h`（改了会丢原始尺寸信息）。

#### ⚠️ 旋转必须在**设备空间**施加（v2.2.0 的重要修正）

**先排好版、再旋转**，不是"先旋转、再缩放"：

```
盒子矩阵（平移 + 缩放，不含旋转）→ 画布矩阵 → 再在设备空间绕盒子中心转 θ
```

**为什么**：`stretch` 缩放模式下画布矩阵是**每轴独立**的（16:10 屏上是
2.183 × 1.364）。若把旋转写在节点空间（`画布矩阵 · … · R(θ)`），
就成了"先旋转、再非等比拉伸" —— **矩形被拉成平行四边形**。实测：

| 角度 | 外框 | 内容尺度 |
|---|---|---|
| 0° | 矩形 | 1.364 |
| 15° | 平行四边形（相邻边不垂直） | 1.433 |
| 45° | 平行四边形（对角线差 **209px**） | **1.820（+33%）** |
| 90° | 矩形 | 1.364 |

也就是"旋转时外框歪掉、控件还会变大"。

**这与 App 一致**：`view.rotation = θ` 旋转的是**已经排好版的设备盒子**
（`DashRenderer` 先按每轴归一化定位/定尺寸，再设 `rotation`），
所以 App 得到的是旋转矩形、尺寸恒定。编辑器必须照做。

**逐层累积**：每一层的旋转都在设备空间绕**该层自己的盒子中心**施加，
然后子节点在这个已旋转的坐标系里继续排布 —— 所以**分组旋转时子控件跟着转**，
且每一层各自都保持矩形（不被斜切）。

> 实现见 `canvas.js` 的 `withDeviceRotation()` / `deviceMatrix()`。
> **改旋转语义必须同时改这三处**：`deviceMatrix`、`withDeviceRotation`、
> `model.js` 的 `ungroupNode`（取消组合时要在设备空间换算，否则偏 23.7px）。

### 2.5 分组（v2.2.0）

`type: "group"` 的节点就是分组。**它建成时 `rotation=0`、`scale=1`（纯平移）**，
所以把子控件挪进去只差一个平移量，**视觉位置完全不变**。

| 行为 | 说明 |
|---|---|
| 拖动分组 | 子控件**一起动**（因为子坐标相对组） |
| 旋转/缩放分组 | 子控件跟着转/缩放（逐层设备空间旋转） |
| 点分组内部 | 选中**整个分组**（否则"一起拖动"就形同虚设） |
| 双击分组内部 | **下钻**，选中里面最深的那个控件 |
| 取消组合 | 子控件回到组的父级，**保持视觉位置** |

**打组的前提**：选中项的祖先不能带旋转/缩放。因为 `x/y` 是相对父节点的，
换父级时若原父级带变换，视觉位置会变 —— 而"打组不该让东西跳位置"是基本预期。
不满足时工具会拦下并说明原因（**且不往撤销栈里压空操作**）。

**取消组合的位置公式**（推导过程见 `model.js` 的注释）：
子中心要**在设备空间**绕组中心转 φ，然后转回父空间：

```
父空间中心 → 设备空间 → 绕组中心（设备） 转 φ → 回父空间
```

> ⚠️ 不能在父空间直接转：画布矩阵 `C` 非等比，`C(绕 gc 转 φ) ≠ 绕 C(gc) 转 φ`。
> 实测症状很典型：**父空间中心算得完全正确、设备空间只差一个轴（y 差 23.7px）**。

### 2.6 PID 的三种形态（**统一表示，别搞出两套**）

一个 PID 在三个地方有三种写法，必须明确谁是谁：

```
设计文件里            内部（节点上）                画布上
───────────────      ──────────────────────      ──────────────────
"obd.rpm"       →    pid     = "std_0C"      →   标签：发动机转速（友好名）
（语义别名）           rawPid  = "obd.rpm"          🏷 PID：std_0C（解析后的 id）
    或
"std_0C"        →    pid     = "std_0C"      →   同上
（直接写 id）          rawPid  = "std_0C"
```

| 字段 | 是什么 | 谁在用 |
|---|---|---|
| 文件里的 `pid` | 可以是**别名**（`obd.rpm`）或**id**（`std_0C`） | 人写、App 读（`resolvePid` 两者都认） |
| 节点上的 `pid` | **解析后的 id**（`std_0C`） | 内部查表：`BUILTIN_PIDS[pid]` 拿名字/单位/量程/阈值 |
| 节点上的 `rawPid` | **用户写的原样** | 编辑器回显 + 序列化时写回别名。**不写进文件** |
| 画布标签 | `BUILTIN_PIDS[pid].name`（友好名） | 给人看 |
| 🏷 PID 开关 | `pid`（解析后的 id） | 排查"这个表到底绑的哪个 PID" |

**为什么内部只存 id**：查表只能查一次、只有一种 key，不用到处 `resolvePid`。
**为什么还要存 rawPid**：序列化时写回别名（`obd.rpm` 比 `std_0C` 可读得多），
而且 PID 下拉框要能把当前值选中。

> 🔴 **`createNode` 与 `parseNode` 必须用同一套规则。**
> v2.2.1 修过一个 bug：`createNode` 直接把别名当 id 存了，
> 于是"预设建的表画布上写着 `obd.rpm`、导入的表写着发动机转速"，
> 而且预设建的节点**查不到内置库 → 单位丢失**。
>
> `statePid` / `rawStatePid`（状态系统的驱动 PID）同理。

### 2.24 素材库规模与「按比例定尺寸」（v2.20.0）

**11 个分类 / 288 个素材**（v2.19.0 时是 95 个）。

| 分类 | 数量 | | 分类 | 数量 |
|---|---|---|---|---|

| `decor` | 46 | | `scale` | 23 |
| `needle` | 21 | | `bar` | 16（新分类） |
| `brand` | 14（**仅通用形状，无真实车标**） | | `turn` | 12 |
| `frame` | 11（新分类） | | | |

#### ⚠️ 添加素材时**必须按比例定尺寸**

`w` 与 `h` **不能各自独立夹取** —— 那会破坏宽高比，用户看到的是压变形的图。
正确做法：定最长边，另一边按比例算；夹取时两边乘**同一个系数**。

```js
const ar = nat[0] / nat[1];
if (ar >= 1) { w = LONG; h = LONG / ar; } else { h = LONG; w = LONG * ar; }
// 最短边保护：整体缩放，不是单独夹一边
if (w < MIN) { const k = MIN / w; w *= k; h *= k; }
```

> 素材原始尺寸取 `a.w/a.h`；没有就退回 bitmap 的自然尺寸
> （手改过的设计文件可能没记 w/h，那种情况下「变扁」比「没有尺寸」更糟）。

#### 吸附分两种（v2.20.0）

| 按钮 | 状态位 | 对齐的是 |
|---|---|---|
| ▦ 网格吸附 | `S.snap` | **格子**（15 单位） |
| 🧲 对象吸附 | `S.snapGuides` | **邻居**（画布边/中线 + 其它节点的边/中心） |

两者**独立开关、可同时生效**。

> **v2.29.0 补充：名字与归属都能改**
>
> | 改什么 | 存哪 | **不**改什么 |
> |---|---|---|
> | 分类**显示名** | `assetKindNames` 覆盖表 | 不动 `v`（设计文件的契约） |
> | 素材**归属分类** | 素材的 `kind` 字段 | 不动 `path`（移动文件会让老设计文件失效） |
>
> 为什么要分开记：这两件事**看起来都像"重命名/移动"，但都不能真的动底层标识** ——
> `v` 和 `path` 是**已经写进用户设计文件里的**，改了就等于把老文件改坏。

### 2.43 撤销栈坏了会「静默失灵」（v2.37.0）

撤销栈**持久化在 localStorage**，内容可能被截断或写坏。

原来 `restore()` 裸调 `JSON.parse` → 坏一条就抛 → `doUndo()` 抛 →
**点了没反应、没有提示**，只有 console 一行红字。

> **「静默失灵」是这类问题里最糟的形态**：用户会以为是「撤销坏了」，
> 而不是「这一条记录坏了」，于是不会想到清一下重来。

现在 `restore()` 内部 try/catch + 校验结构，**返回成败**，调用方据此提示：

```js
if (!restore(r.state)) { toast("这一步的记录坏了，已跳过：" + r.label); return; }
```

> ⚠️ 遗留：坏的那条**仍留在栈里** —— 每次撤销都会再撞一次，应该摘掉。

### 2.22 子部件嵌套（v2.18.0）
### 2.22 子部件嵌套（v2.18.0）
### 2.22 子部件嵌套（v2.18.0）

```json
{ "kind": "needle", "assetId": "as-needle", "rawPid": "obd.rpm",
  "children": [ { "kind": "decor", "assetId": "as-cap", "x": -12, "y": -12, "w": 24, "h": 24 } ] }
```

**坐标系**：顶层部件相对**仪表节点**；子部件相对**父的 pivot**，并继承父的旋转。

> 为什么以 pivot 为原点：嵌套的典型用法是「指针上挂个装饰」——
> 装饰要跟着指针**绕轴心转**。以 pivot 为原点，子部件写 `(0,0)` 就在轴心上；
> 以左上角为原点的话，每加一个装饰都要手算 pivot 偏移。

**绘制顺序**：数组顺序 = 绘制顺序；**父先画、子后画**（装饰盖在主体之上）。

**深度上限 5 层** —— 三处必须一致：

| 位置 | 函数 |
|---|---|
| 工具 · 规范化 | `normalizePart(o, depth)` |
| 工具 · 绘制 | `drawPartTree(n, part, values, depth)` |
| App · 解析 | `GaugePart.parseAll(..., depth)` |
| App · 绘制 | `GaugePartsView.drawPart(canvas, p, k, depth)` |

> ⚠️ 设上限是防「手改文件写出几千层」把栈打爆 —— JSON 不能成环，
> 但深到几千层一样会崩。

> **v2.28.0 补充**：
> - **`value`（数值部件）也能绑 PID** —— 双针表配两个数字读数
> - **`sweepFollow`** —— 扫描范围跟着**第一个指针**走，双针表不用手填两遍
>
> ⚠️ 绑 PID 的判据是 `kind === "needle" || kind === "value"`；
> 表盘/刻度/装饰绑了没有意义（还会污染序列化，每个部件多两个空字段）。

### 2.21 多指针表（v2.17.0）

`needle` 部件可以绑自己的 PID：

```json

  "pivotX": 0.5, "pivotY": 0.5, "sweepFrom": 135, "sweepTo": 405 }

| 情况 | 取哪个值 | 用哪套量程 |

> ⚠️ **只有 `needle` 能绑 PID**。`dial`/`ticks`/`decor` 绑了没有意义，

### 2.39 headless 里 alert 会阻塞（v2.34.0）

**这条花了最久才查出来，单独记一笔。**

`window.alert()` 在 headless Chrome 里会**阻塞整个渲染进程** ——
而 CDP 的 `Runtime.evaluate` 也就永远等不到响应，表现成"求值超时"。

```

                                                        ↓
                                             渲染进程卡死 → CDP 求值超时

**症状与原因隔了好几层**：报错是"第 3 节的第一个求值超时"，
而那个求值只是读个 `.length`。

> ⚠️ **stub 要在"任何可能触发它的操作之前"，不是"用到之前"。**
> 前者一次搞定，后者迟早漏一个 —— 我就是漏了重名那条。
>
> ```js
> window.alert = function () {};
> window.confirm = function () { return true; };
> window.prompt = function () { return null; };
> ```

**当时试过但没用**（因为都在治"资源/竞态"，而根因是"等一个永远不会点的确定框"）：
`send()` 超时 · 每节 `Page.navigate` 重载 · stub `renderAssets` ·
拆成独立求值 · 隔离脚本对照。

### 2.35 测试偶发失败的治理（v2.26.0）

### 2.18 面板布局与画布尺寸（v2.13.0）

**三条硬约束**（都是踩过坑才定下来的）：

1. **`.canvasWrap` 必须是列向 flex** —— 页签 / 面包屑 / 画布是竖着摞的。
   不是列向 flex 的话页签会被挤成竖条并压在画布上。
2. **画布不能被 flex 拉伸**（`flex: 0 0 auto; margin: auto`）。
   `applyCanvasSize()` 按**设计宽高比**算尺寸；`flex:1 1 auto` 会纵向拉长它，
   于是「位图尺寸」与「CSS 尺寸」不一致 → **坐标换算全错、手柄点不中**。
3. **面板内容必须有自己的滚动容器**（`.panelScroll`）。
   面板本身是 `overflow:hidden` 的 flex 容器，内容直接塞进去会被裁掉且滚不动。

**素材库固定高度**（`46vh`，可拖拽调整并持久化）—— 否则展开分类会把控件树挤出去。

**内置素材内嵌 data URL** —— `file://` 下按 path 加载会**污染画布**，
导致 `getImageData` / `toDataURL` 抛 SecurityError（**导出 PNG 直接坏掉**）。
data URL 同源，不污染。设计文件里写的仍是相对 path（App 靠它找文件）。

### 2.16 多页面（v2.10.0 格式 / v2.11.0 完成）

```json
{ "schema": "icar.ui/2",
  "pages": [ { "id":"p1", "name":"主页面", "nodes":[...] },
             { "id":"p2", "name":"性能页", "nodes":[...] } ] }
```

**核心不变式**：`design.nodes === design.pages[design.pageIndex].nodes`（**同一引用**）。
切页只换引用，所以所有读写 `design.nodes` 的代码都不用改。

**序列化按页数二选一**：

| 页数 | 写什么 |
|---|---|
| 1 页 | **只写 `nodes`**（与 v2.9.0 及以前**逐字节一致**） |
| ≥2 页 | 写 `pages`（不再写 `nodes`） |

> ⚠️ **不能两个都写**。第一版就是两个都写，而解析时 `pages` 优先 ——
> 用户在 JSON 里改 `nodes` 会被**静默忽略**（实测：删掉 `nodes[0].pid` 校验却通过）。
> 两处真相必然分叉。

**兼容**：没有 `pages` 的老文件自动兜成单页「主页面」，行为完全不变。

**工具侧 UI**（v2.11.0）：页签条 —— 点击切换、双击重命名、`＋` 新建、每页 `✕` 删除。
单页时也显示页签条（否则发现不了能加页），但不显示删除按钮。

**App 侧**（v2.11.0）：`DesignFile.pages` + `Store.settings.dashPageIndex`，
渲染时 `design.copy(nodes = pages[idx].nodes)`。索引**越界夹到最后一页**。

> ⚠️ **空页不是错误**。`parseNodeArray` 有 `allowEmpty` 参数：
> 顶层 `nodes` 空要报错（空仪表盘没意义），但 `pages[i].nodes` 空是正常的 ——
> 否则"新建一页"会立刻变成非法状态。

### 2.14 状态系统的阈值（v2.9.0）

图片节点可显式设 `stateWarn` / `stateCritical`（**可选**）：

### 2.15 控件树的同层重排（v2.9.0）

拖拽按行的**垂直位置**分三个区域：上 1/4 插到前面、下 1/4 插到后面、中间成为子节点。

**同层判定**：`canReorderSameLevel` 只允许同一父级内 —— 跨层是 `reparent` 的职责。

> ⚠️ **重排后必须 `normalizeZ`**。画布是按 `z` 画的，而重排改的是**数组顺序**；
> 不归一化就会出现"控件树里动了、画布上没动"。

### 2.12 背景的 w / h（v2.8.0）

`background.w` / `background.h` 是**画布单位**的尺寸，`0` = 铺满（默认）。

**语义**：指定了就按那块矩形画，而不是铺满整屏 —— 用于"这张底图只占中间一块"。

> ⚠️ **App 侧曾经完全忽略这两个字段**，于是电脑上缩在中间的图推到设备上
> 会变成全屏拉伸。这类"字段写了没人读"的缺陷**不会崩、不会报错**，
> 只会看起来不太对 —— 所以 `BackgroundSizeTest` 专门钉住它。

**优先级**：`w`/`h` > `fit`（平铺除外 —— 平铺本身就是"铺满"的语义）。

App 侧实现见 `PositionedBackgroundDrawable`：**必须自己写 Drawable**，
因为 View 每次布局都会用 `setBounds(0,0,viewW,viewH)` 覆盖掉
`BitmapDrawable` 的边界，"固定位置"做不到。

### 2.13 撤销栈的持久化上限（v2.8.0）

存 `localStorage`，上限是**字节预算 1.2 MB**（步数 40 只作兜底）。

为什么不是"20 步"：3 个控件的设计和 200 个控件的设计，单步快照差**两个数量级**，
写死步数要么浪费要么写爆。

配额满了**顺手清掉旧数据** —— 留着只会让下一次也失败。

### 2.10 底框细调（v2.6.0）

`cardStyle` 只有 4 个粗档位，表达不了"半透明 + 大圆角"。再加一个 `card` 对象：

```json
"card": { "show": true, "alpha": 190, "radius": 12 }
```

| 字段 | 含义 |
|---|---|
| `show` | false = 不画底框 |
| `alpha` | 0..255，null = 跟随主题的 `cardAlpha` |
| `radius` | 圆角半径，**画布单位**（不是像素 —— App 侧要乘 density） |

**优先级**：`card` 覆盖 `cardStyle` 的对应项；缺的仍跟随主题。
全为默认时**不写进文件**。

> ⚠️ App 侧**不走 `GaugeTheme.cardBackgroundFor`** —— 那个只认 4 个粗档位。
> `NodeTreeRenderer.cardDrawable()` 自己建 `GradientDrawable`。

### 2.11 默认字号是 6，不是 16（v2.6.0）

**16 是"像素思维"的产物。** 画布只有 360 单位宽，16 单位的字在 180 单位的表上占 **8.9%**，
满屏都是字。6 单位 ≈ 表高的 3.3%，能看清但不抢戏。

这条写进大纲是因为它**不是随手可改的样式值** —— 改了会让所有存量设计的观感变化，
而且工具与 App 必须同时改（跨语言比对查 `DEFAULT_SIZE`）。

### 2.9 背景铺法：平铺（v2.3.0）

`FIT_TILE = 3`（`FIT_NAMES` 第 4 项）。

**规则（工具与 App 必须一致）**：先把图**缩到不超出容器**（只缩不放），再重复铺。

> ⚠️ **不能用 `BitmapDrawable + REPEAT`**：它铺的是原图尺寸，而背景加载时
> 已**下采样到 2048** —— 铺在 2560 宽的屏上只看到 1~2 块，"平铺"根本看不出来。
> App 侧用 `TiledBackgroundDrawable`（`BitmapShader` + 缩放矩阵）。
### 2.7 JSON 文本域的"有错未生效"状态

工具允许**直接编辑 JSON**。解析失败时的规则（v2.2.1 起）：

| 情况 | 行为 |
|---|---|
| 解析失败 | **保留当前设计**（画布不动），文本域标记 `jsonDirty` |
| `jsonDirty` 期间 | `syncJson()` **绝不覆盖文本域** —— 那段文本是"用户的" |
| 视觉提示 | 文本域红框 + 顶部提示条 + 「放弃 JSON 改动」按钮 |
| 修好错误 | 自动生效，标记自动清除 |
| 整体替换设计的操作 | 撤销 / 重做 / 新建 / 套预设 / 打开文件 → 清掉该状态 |

> 🔴 **为什么必须有这条**：v2.2.1 之前，解析失败后只要在画布上动一下，
> `commit()` → `syncJson()` 就会把文本域整个冲掉 ——
> **用户在 JSON 里做的编辑无声无息地消失**。实测复现过。
>
> 遗留：`jsonDirty` 期间画布**仍然可以改**，会出现"画布改了、JSON 没跟上"的分叉。
> 更严格的做法是锁住画布编辑，或做双向合并。

### 2.4 为什么用 `children` 而不是 `parent` 引用

树只有一种表达方式，不会出现"父子指针不一致"的半损坏状态。
`parent` 字段在示例里保留是为了**可读性**（一眼看出层级），解析时以 `children` 为准。

## 三、素材（assets）

### 3.1 只存引用，不内嵌

```json
"assets": [
  { "id": "as1", "name": "碳纤维底", "kind": "background",
    "path": "assets/as1.png", "w": 1920, "h": 1080, "bytes": 240000 }
]
```

**为什么路径是相对的 `assets/as1.png`**：
设计文件与素材一起放在 `files/design/` 下，`design.json` 引用同目录的 `assets/`。
绝对路径换台设备必然失效（v1 已经踩过这个坑 —— `background.path` 只警告不报错）。

### 3.2 素材管理器里的"内置素材"从哪来

工具的分类（背景/仪表盘/指针/刻度/图标/转向灯/警告灯/汽车品牌/装饰/自定义）
只是**标签**，不预置任何图片 —— 因为：

1. 仓库里不放第三方二进制（沿用项目既有约定，见 `LVGL-放弃记录.md` 的同类决策）
2. 版权风险：车标、仪表盘素材绝大多数不是自由许可

工具提供的是**分类 + 拖入即用 + 缩略图**，素材由用户自己导入。
`kind` 字段决定它出现在哪个分类下。

### 3.3 ⚠️ 浏览器存储的硬约束（实测过，别绕）

工具必须**双击即用**，也就是跑在 `file://` 下。实测（无头 Edge）：

| API | `file://` 下 | 结论 |
|---|---|---|
| 经典 `<script src>` | ✅ 可用（含子目录、顺序保持） | 可以拆多文件 |
| `localStorage` | ✅ 可用 | 用来缓存**缩略图**与界面状态 |
| **`IndexedDB`** | ❌ **被拒绝**（`SecurityError`） | **不能**把图片存进浏览器数据库 |
| `fetch` / `XHR` / ES module | ❌ 被 CORS 挡住 | **不许用**（约束 4） |
| `showOpenFilePicker` | 构造函数存在，但 `file://` 是不透明源，实际会抛 | 用 `<input type=file>` |

**所以素材是"按相对路径引用"而不是"存进浏览器"**：

```
design.json  引用 → assets/carbon.png
                    ↑ 用户把图片放到设计文件同目录的 assets/ 下
```

- **预览**：用户选/拖入文件时，把 `File` 留在内存里 → `URL.createObjectURL(file)`
- **跨会话的缩略图**：把小图（约 64px）转成 data URL 存进 `localStorage`
  （几十 KB 量级，不污染设计文件）
- **完整图片不进设计文件**：那会让它变成几 MB 的不可读二进制块（与 §3.1 同一条理由）

> 这条约束的**好处**：工具的素材模型与 App 完全一致（都是 `assets/` 相对路径），
> 不需要"导出时把内嵌图片拆出来"这一步。

## 四、状态系统

### 4.1 为什么它比"多张图"更值得做

一个发动机故障灯在真车上有三种外观（正常/警告/严重）。若用三个独立控件表达：

- 三个控件都要手动摆到**同一个位置**，改一次位置要改三处
- 三个控件的**层级**要各自维护
- 想"严重时闪烁"还要写规则

状态系统把这三件事收进**一个节点**：

```json
{
  "id": "n9", "type": "image", "name": "发动机故障灯",
  "x": 300, "y": 40, "w": 24, "h": 24,
  "statePid": "std_0C",
  "states": {
    "normal":   { "assetId": "as_off",  "alpha": 77,  "blink": false },
    "warn":     { "assetId": "as_warn", "alpha": 255, "blink": false },
    "critical": { "assetId": "as_crit", "alpha": 255, "blink": true, "blinkMs": 200 }
  }
}
```

**位置、尺寸、层级只写一次**，三张图共用。

### 4.2 状态怎么判定

复用 `AlertPulse` 的**迟滞**语义（否则数值在阈值附近抖动会让灯乱闪）：

```
statePid 的值 → 与 warnHigh / criticalHigh 比较（带迟滞）→ normal / warn / critical
```

阈值来源，按优先级：

1. 节点自己的 `stateThresholds`（显式覆盖）
2. 该 PID 在 PID 库里的 `warnHigh` / `criticalOf()`（默认，与仪表报警同一套）

> **为什么复用而不是另起一套**：如果故障灯和仪表盘的报警用不同阈值，
> 会出现"表已经变红了、灯还是绿的"—— 那是必然会被当成 bug 的。

### 4.3 闪烁由谁驱动

`blink: true` 时由 **`GaugeTicker`**（已有的共用动画时钟）驱动，
相位与 `AlertPulse` 共用同一套时间基准 —— 不新增第二个动画驱动。
`blinkMs` 缺省 200ms（与 `AlertPulse.CRITICAL` 的方波周期一致）。

## 五、分辨率与缩放

### 5.1 问题

设计师在 PC 上按某个尺寸做图（比如 2560×1600 平板横屏），
但设备可能是 1600×2560 竖屏、或 1200×1920。

v1 的做法是**每轴独立的归一化坐标**（`x/w` 与屏宽成比例、`y/h` 与屏高成比例）——
好处是"自动铺满"，坏处是**宽高比一变就变形**：圆表被拉成椭圆。

### 5.2 方案：设计分辨率 + 缩放模式

```json
"canvas": {
  "unit": 360,
  "designW": 2560,
  "designH": 1600,
  "scaleMode": "fit"
}
```

| scaleMode | 行为 | 适用 |
|---|---|---|
| `stretch` | 每轴独立拉伸（= **v1 的行为**，默认，保证旧文件不变） | 纯仪表盘，能接受轻微变形 |
| `fit` | **等比缩放**，短边留黑边（letterbox） | 有图片素材/圆形元素，**不能变形** |
| `fill` | 等比缩放铺满，超出部分裁掉 | 背景图，宁可裁也不要黑边 |

**实现方式**：渲染时算一个统一的 `k` 与偏移 `(dx, dy)`，所有节点的像素坐标
都过一遍这个变换。这样"设计分辨率"只影响这一处换算，节点坐标语义不变。

> ⚠️ **默认必须是 `stretch`**。否则存量 `dash.json` / `design.json`
> 导入后观感会变（留黑边），用户会以为是 bug。

## 六、编辑器架构

### 6.1 为什么拆成多文件

单文件在 1500 行时还能读，加上这次 12 项功能会到 **4000+ 行**，没法维护。

**拆分的代价**：需要确认双击 `index.html` 还能用。
已实测（无头 Edge）：经典 `<script src="js/x.js">` 从 `file://` 加载**正常**，
含子目录、执行顺序也保持。只有 `type="module"` / `fetch` / `XHR` 会被 CORS 挡住 ——
所以**不用 ES module、不用 fetch**，全部用经典脚本 + 全局命名空间。

### 6.2 文件划分

```
tools/theme-studio/
  index.html            外壳：布局 + 面板骨架
  css/studio.css        样式
  js/schema.js          ★ 与 App 同源的常量（别名 / 样式 / CARD / FIT / 节点类型 / 状态名）
  js/model.js           节点模型：树操作、变换矩阵、序列化、**撤销栈**
  js/validate.js        ★ 校验与解析（含 v1 → v2 自动升级）
  js/presets.js         预设布局 + 「与 App 规则的差异」清单
  js/canvas.js          画布渲染 + 交互（拖动/缩放/旋转/多选/吸附/框选）
  js/panels.js          控件树 + 属性面板（分组折叠）+ 素材管理器
  js/app.js             装配：撤销集成、命令、实时模拟、文件读写、校验显示
  gen-sample.js         用工具自己的代码生成示例（避免手抄脱节）
  CHANGELOG.md          工具自己的迭代日志
  README.md             用法
  sample.json           **v1** 示例（App 当前版本能直接读，Kotlin 测试的验收对象）
  sample-v2.json        **v2** 示例（展示图片 / 状态 / 分组 / 旋转 / 锁定）
```

★ = **必须与 Kotlin 侧保持一致**，由 `tools/theme-studio/tests/verify-crosslang.js`（跨语言，59+ 项）守着。

> **为什么合并成 7 个 js 而不是原计划的 10 个**：
> 拆得越碎，**加载顺序**与**跨文件引用**出错的机会越多 —— 而这类错误的症状
> 特别有误导性（`Unexpected token ')'` 不说是哪个文件；一个缺失的 DOM id
> 能让所有面板空白）。实际开发中这两类坑都踩到了，所以按**职责**合并：
> 撤销栈跟着模型走（它序列化的就是模型），控件树/属性/素材同属"面板"。
>
> 加载顺序有依赖，见 `index.html` 末尾的注释：
> `schema → model → validate → presets → canvas → panels → app`

### 6.3 面板布局

用户反馈"主题、属性里面太杂乱了"，所以按**职责**分区，而不是把字段堆成一列：

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：打开 保存 校验 │ 撤销 重做 │ 吸附[开] 网格 │ 缩放 − ＋  │
├──────────┬──────────────────────────────┬────────────────────┤
│ 素材库    │                              │ 属性（分组折叠）    │
│ （分类树）  │        画布                   │  ▸ 变换            │
│          │                              │  ▸ 外观            │
│ 控件树    │                              │  ▸ 数据绑定         │
│ (层级树)  │                              │  ▸ 状态            │
│          │                              │  ▸ 图层            │
├──────────┴──────────────────────────────┤                    │
│ 预设布局 │ 实时模拟 [▶] │ 校验结果        │                    │
└─────────────────────────────────────────┴────────────────────┘
```

- **左栏**：素材库 + 控件树（可折叠切换）
- **中栏**：画布
- **右栏**：属性，**按组折叠**（变换/外观/数据/状态/图层）
- **顶栏**：撤销重做与吸附开关放在**显眼位置**（用户明确要求）

## 八、不可妥协的约束

1. **v1 文件必须继续可用**。`schema: "icar.ui/1"` 仍被接受，
   解析后自动升级成 v2 的 gauge 根节点（不改用户观感）。
2. **`stretch` 是默认缩放模式**。改默认会让存量设计变形。
3. **校验规则必须与 `DesignFile.kt` 同源**，由跨语言比对脚本守着。
   两边分叉的后果是"编辑器说没问题、App 加载报错"。
4. **不引入构建步骤**。不用 ES module、不用打包器 ——
   双击 `index.html` 必须能用（这是这个工具的核心价值）。
5. **仓库不放第三方素材**（含车标）。分类只是标签，素材由用户导入。
6. **不新增第二个动画驱动**。状态闪烁复用 `GaugeTicker`。
7. **节点字段与 `GaugeItem` 同名**，避免出现两套词汇表。

# iCarOBD 仪表框架总览

> 梳理「轮询 → 数据总线 → 仪表渲染」的完整链路，以及**全部 8 种仪表**各自画了什么。
> 用来回答「某个仪表为什么是空的」这类问题。

---

## 一、数据从哪来：轮询链路

```
        ┌──────────────────────────────────────────────┐
        │ 数据源（三选一，互斥）                        │
        │  ① ObdEngine   —— 真车，按 pollInterval 轮询  │
        │  ② SignalSimulator —— 合成信号，10Hz          │
        │  ③ 都没有     —— 总线上没有任何值             │
        └───────────────────┬──────────────────────────┘
                            │ 写入
                            ▼
                    ┌───────────────┐
                    │  VehicleBus   │  按 pidId 存最新值 + 历史（150 点）
                    └───────┬───────┘
                            │ 读取（**拉**，不是推）
                            ▼
        ┌──────────────────────────────────────────────┐
        │ 渲染层（5Hz 定时器主动拉）                    │
        │  Android 自绘  DashRenderer                  │
        │  LVGL(C)       LvglDashView                  │
        └──────────────────────────────────────────────┘
```

**关键性质**：

- **写是推、读是拉**。`ObdEngine` 拿到值就写进 `VehicleBus`；
  渲染层自己起 5Hz 定时器去拉。这样**新增数据点不需要改渲染层**。
- **渲染层不认识"数据源"**。它只认 `pidId`。所以模拟信号和真车数据走的是同一条路，
  仪表无法区分 —— 这正是**必须显示「模拟数据」提示**的原因。

## 二、全部 8 种仪表

`GaugeItem.style` 决定用哪种。**LVGL 侧与 Android 侧各有一套实现**，样式编号一致。

| # | style | 名称 | LVGL 构建函数 | 画什么 | 依赖 |
|---|---|---|---|---|---|
| 0 | `CIRCLE` | 圆表 | `make_circle` → `neon_gauge` | 自绘霓虹：10 层辉光扫弧 + 刻度 + 5 层指针 + 中心环 + 数值 | 值（弧长/指针角） |
| 1 | `DIGITAL` | 数字 | `make_digital` | 卡片 + 大号数值 + 单位 | 值 |
| 2 | `BAR` | 条形 | `make_bar` | 卡片 + 数值 + 底部进度条 | 值（条长） |
| 3 | `LINE` | 线型图 | `make_chart` | 卡片 + `lv_chart` 折线（60 点）+ 数值 | **历史**（不是单值） |
| 4 | `DUAL_STACK` | 双数据·上下 | `make_multi` | 主参数大号 + 1 个副参数 | 主值 + 副值 |
| 5 | `QUAD` | 四数据 | `make_multi` | 主参数 + 3 个副参数（2×2） | 主值 + 3 副值 |
| 6 | `SUB_DUAL` | 主+子双数据 | `make_multi` | 主参数大号 + 2 个并排小号 | 主值 + 2 副值 |
| 7 | `GFORCE` | G 力值 | `make_gforce` | G 值大表 + 横/纵分量 | 3 个值（G 三元组） |

### 绑定种类（LVGL 侧）

```c
BIND_METER = 0   圆表（已被 BIND_NEON 取代）
BIND_LABEL = 1   只更新文本
BIND_BAR   = 2   进度条 + 文本
BIND_CHART = 3   折线，按槽位循环写
BIND_DOT   = 4   G 值圆点（需要 gx/gy 两条绑定配合）
BIND_NEON  = 5   霓虹圆表（自定义绘制）
```

## 三、**为什么仪表会是空的** —— 排查顺序

按这个顺序查，能覆盖绝大多数情况：

### 1. 有没有数据源？

```bash
adb logcat | grep '模拟信号'          # 模拟信号开没开
adb logcat | grep 'engineWasRunning'  # 轮询引擎状态
```

**实测最常踩的就是这个**：没连车、模拟信号也没开 → 所有仪表显示 `--`。

> ⚠️ **历史坑**：模拟信号原来在**离开模拟器界面时自动停止**（`SimulatorActivity.onDestroy`），
> 而同一个界面的提示却写着「切到仪表盘页即可看到效果」——
> **用户照着做，数据源就关了，仪表盘立刻变空。**
> 已改为：模拟信号作为**数据源**活过界面，改用**常驻的「模拟数据」横幅**兜底提示。

### 2. 值有没有推到渲染层？

```bash
adb logcat | grep '绑定总数'      # LVGL：绑定条数
adb logcat | grep '布局已下发'    # items / bindings 数量
```

绑定数应当等于该布局里**动态元素**的个数。

### 3. 画面上到底有什么？（**别只看 8×6 粗采样**）

`nativeProbeGrid` 的 8×6 网格每 ~200×340 像素才采一个点，**会整片漏掉文字和小控件**。
判断"画面是不是空的"要看**亮像素统计**（每 4 像素采样，统计 `r,g,b > 150`）：

| 场景 | 亮像素占比 |
|---|---|
| 8 个仪表的正常本地布局 | 0.30% – 0.43% |
| 只有暗色卡片、没有数据 | 0.02% – 0.05% |

**最可靠的还是直接截图**：

```bash
adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png
```

## 四、两条渲染路径

| | Android 自绘 | LVGL（C） |
|---|---|---|
| 开关 | `Store.settings.dashEngine = 0` | `= 1` |
| 入口 | `DashRenderer` | `LvglDashView` |
| 仪表来源 | `GaugeItem`（**组合控件**） | `GaugeItem` **或** `DashElement`（**图元**） |
| 外部主题 | 不支持 | 支持（Sky Gauge） |

**LVGL 路径下还有两条互斥的子路径**：

- **组合控件**：`nativeBuildLayout` —— 一个 `GaugeItem` 展开成圆表/条形/趋势
- **图元**：`nativeBuildElements` —— 一个 `DashElement` 对应一个 `lv_arc`/`lv_label`/`lv_img`

设了 `Store.settings.skyThemePath` 就走图元，否则走组合控件。

**为什么必须分开**：Sky Gauge 的 `arc` 是**图元**，而 `GaugeItem` 是**组合控件**
（一个「圆表」在渲染层展开成弧 + 刻度 + 指针 + 标签）。硬塞会得到一堆「什么都不是」的仪表。

> **多画布（v1.20.0）之后**：`DashRenderer` 是**每一页一个**（一套画布一个），
> 由 `DashFragment.updatePageActivation()` 裁决 —— **只有当前页在跑 5Hz 定时器**。
> 所以查"某个画布不刷新"时先看它是不是当前页；非当前页本来就该是静止的。
> 另外每页渲染的是**自己那一套**（`DashSpec.buildFor(canvas)`），
> 不是"当前画布"（`DashSpec.build`）—— 后者会让所有页显示同一个盘面。

## 五、坐标系

**每轴 0..`GaugeItem.CANVAS`（360）**，即「归一化 × 360」。

- 旧配置（归一化、无 `unit` 字段）读取时自动 ×360
- 新增写入带 `"unit": 360` 标记
- 拖拽网格：`STEP = 360/24 = 15`，`MIN_SIZE = 30`

**外部主题（Sky Gauge）例外**：他们的画布是**正方形** 360×360，所以导入时
**必须统一缩放（取屏幕短边）+ 居中**，不能按两轴各自缩放 ——
否则圆环是正圆、标签却按两轴各自定位，**两者对不上，整个主题看起来"散了"**。

## 1 · 检视器面板加「清除」按钮

**用户原话**：「检视器悬浮窗的按钮旁边加个按钮、按钮功能为 清除记录、按下后清除选中的记录」
**→ 用户已明确选 B**（我给了 A/B/C 三个候选）：

> **B：面板只显示当前检视结果，按钮 = 清空面板内容（回到"点屏幕上任意控件查看信息"的占位）**

**做法**：
- 在「检视 开/暂停」药丸**旁边**加一个小按钮（`清除`）
- 点了 → 面板回到**占位态**（`UiInspectorInfo` 里的提示文案：点屏幕上任意控件查看它的信息 / 搜这个 id 到 UI样式与排版总表.md / 长按复制 · 拖动移动 · 右上角 × 关闭）
- ⚠️ **只清内容，不动检视开关**（该接管还接管、该暂停还暂停）
- ⚠️ **不改布局尺寸的稳定性**：面板从"有内容"变回"占位"会变高/变矮 → 要确认**不会盖住画布**（浮层本身不参与布局，但要确认它自己那一块不会把画布顶开）
- ⚠️ 按钮**自己不能被检视消费掉**（命中判定要先排除浮层自己，与药丸同一套处理）

**判据**：点控件 → 有内容 → 点「清除」→ **回到占位** → 再点别的控件 → 又有内容；且**检视状态不变**。

## 2 · CAN 探测的过滤器预设：补成一整组

**用户原话**：「优化CAN探测的过滤器预设、增加更多预设」

**现状**（`ui/CanSnifferActivity.kt:450` 附近）：只有 **4 个** ——
`ATCM700+ATCF400`(0x400~0x4FF) · `ATCM700+ATCF000`(全部 11 位 ID) · `""`(不过滤) · 还有一两个。

**要补的**：
- **8 个段各一个**：`ATCM700+ATCF000` ~ `ATCF700`（对应 `0x000~0x0FF` … `0x700~0x7FF`）
- **常用段的说明要写"这条能看到什么"**（本项目已有实测知识，别只写段号）：
  - 车身域常见段（如 `0x2xx`/`0x4xx`/`0x6xx`）—— ⚠️ **不要编**，本项目**没实测过各灯在哪个段**，
    所以说明只能写"常见车身域（未在本车实测）"
- **单 ID 快捷**：`ATCRA<ID>`（最省，能看到 20 帧/秒级别）
- ⚠️ **预设名要说人话**：现在叫 `ATCM700+ATCF400` ✗ → 建议 `0x400~0x4FF（车身域？）` 这种
  **"人话 + 命令"** 的形式，命令放次要位置（用户要的是"选哪个能看见什么"，不是 AT 语法）
- ⚠️ **`ATCF000` 是全总线、不是"第 0 段"**（本项目实测结论，见 `CAN-信号库与逆向框架.md`）——
  这条**必须在界面上写清**，否则用户会以为"第 0 段 ID 特别多"

**判据**：预设从 4 个补到 ~12 个；每个预设的说明**能让人判断该选哪个**；选任一个后**状态行显示实际下发的 AT 命令**。

## 3 · 文案优化（与 2、4 一起做）

**用户原话**：「同时看下文案有无优化的空间」

**范围**：CAN 探测页 · 日志页 · 检视器面板（按钮名/提示语/空态/错误文案）。
**原则**（本项目一贯的）：
- **说人话**，不用内部术语（`ATCRA` 要配"只放行这一个 ID"）
- **空态要说清"为什么空" + "下一步做什么"**，不要只写"暂无数据"
- **错误要说清"怎么办"**（如 `NO DATA` → "车没回话：可能这个 PID 不支持 / 模块头不对"）
- 长度受屏幕限制 → 长文案进对话框或提示，别硬塞进一行

## 4 · 日志页观看体验

**用户原话**：「优化日志页面的显示、提升观看体验」

**现状**（`res/layout/fragment_log.xml`）：级别 Spinner · 模块 Spinner · 暂停滚动 · 导出 · 清空 · 一行统计 · RecyclerView。

**要求：先给方案再动手**（不要直接堆控件）。候选方向（**让 agent 判断哪些值、哪些不值**）：
- **等宽 + 对齐**：时间戳/级别/模块列对齐（现在大概率是比例字体，扫读费劲）
- **按级别染色**（V/D/I/W/E 各一色）+ **关键字高亮**（`7F`/`NO DATA`/`原因=`）
- **跟随开关**：现在只有"暂停滚动"；补"回到底部/跟随"（滚上去看历史时自动暂停跟随）
- **长按复制单行**（现在只能导整份）
- **筛选**：级别/模块改成**可多选 chips**（Spinner 一次只能选一个）
- **折叠重复行**（`AppLog` 已有"重复 N 次已抑制"，但那是日志层；列表层可以再折叠相邻同内容行）
- ⚠️ **性能红线**：日志页在**极端突发**时已知会丢显示（UI 派发队列上限 500，见 `迭代清单` P2-3）→
  **不许加重主线程负担**（染色/高亮要在 `onBindViewHolder` 里便宜地做，别每帧重算）

**判据**：能一眼看出"哪行是错误"、"这几行是重复的"；滚上去看历史时不会被自动滚动打断；长按能复制单行。

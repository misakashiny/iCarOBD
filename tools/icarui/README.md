`tools/icarui/` 下有 4 个启动入口，**平时只用第一个**：

| 文件 | 双击后 | 什么时候用 |
|---|---|---|
| **`start-icarui.cmd`** | 用**默认浏览器**打开 `index.html`（`file://` 直开） | ✅ **平时就用它** |

### A · 直开（`start-icarui.cmd`）—— 这是正常用法

**已实测：`file://` 直开功能完整，没有"必须走服务器"的功能。**
证据在 [`tests/probe-file-url.js`](tests/probe-file-url.js)（无头 Edge + CDP，19 条检查全过）：

| 要验的 | `file://` 实测结果 |
|---|---|
| 页面加载 | ✅ `readyState=complete`，`BUILTIN_ASSETS=416` 条、`BUILTIN_CONTROLS=200` 个 |
| 所有 `js/` 加载 | ✅ 24 个 `.js` 请求**全部 200**；87 个子资源**零** `loadingFailed` |
| 两个字库 | ✅ `js/pinyin.js` 368 条；⚠️ 5×7 点阵字库在 `png.js` 里，**浏览器本来就不加载它**（Node 侧素材生成用），与 `file://` 无关 |
| console 报错 | ✅ **0 条** error / JS 异常（0 条 warning） |
| 素材能出来 | ✅ 画布 385,888 个像素与底色不同；11 个 `builtin-data-*.js` 全部注入，416/416 条素材带内嵌 base64 |
| 导出 JSON | ✅ 走 `blob:` + `<a download>` |
| 导出 PNG | ✅ 走 `data:` + `<a download>`（画布没被污染） |
| 导出设计包 `.icarzip` | ✅ 走 `blob:`，**导出后自检通过**（3 条目 / 1 素材 / 0 缺失） |
| 导入（文件对话框） | ✅ 真 `File` + `DataTransfer` + change 事件 → `FileReader` 读到内容并回灌设计 |
| 导入（拖文件进画布） | ✅ 拖一个 png 进去能建出图片控件 |
| `showSaveFilePicker` | ✅ **存在**（`file://` 是 secure context）；真调用会抛 `SecurityError: Must be handling a user gesture` —— 那是**手势限制**，不是 `file://` 限制。⚠️ 工具**根本没用它**（全库 0 处引用），导出走 `<a download>` |
| `localStorage` | ✅ 可用（`file://` 下 OK） |

### ⚠️ `file://` 下**确实**不行的两条（都不影响工具）

| 不行 | 实测 | 影响 |
|---|---|---|
| `fetch` / `XMLHttpRequest` 读本地文件 | `fetch` → `TypeError: Failed to fetch`；XHR → `onerror`（status 0） | **无**。工具全用经典 `<script src>`，不用 fetch/XHR |
| 按**路径**（非 data URL）加载的图画进画布 → **污染画布** | 画进 canvas 后 `toDataURL()` 抛 `SecurityError` | **无**。内置素材走内嵌 data URL；「导出图」已兜住这个异常并给可读提示 |

> 这两条**起本地服务器就能解决**（`http://127.0.0.1` 同源，fetch 可用、不污染画布）——
> 这就是 `serve.cmd` 存在的理由。但**平时不需要它**。

### B · 本地服务器（`serve.cmd`）—— 只在 A 出问题时用

```bat
serve.cmd            :: 默认端口 8765
serve.cmd 9000       :: 指定端口
```

- **不要求装 Node / Python**：服务器是 [`serve.ps1`](serve.ps1)（PowerShell + `HttpListener`，约 100 行）。
  这是**硬约束** —— 用 `python -m http.server` 或 `npx serve` 就等于把"零安装"破掉了。
- **端口可配 + 冲突自动换**：默认 8765，被占就自动往后找（最多 20 个），会明确打印"端口 X 被占，自动改用 Y"。
- **怎么停**：在窗口里按 **Ctrl+C**，或**直接关掉窗口**。
- **只绑 `127.0.0.1`**：局域网里别的机器连不上（临时服务器没必要对外），也不需要管理员权限。
- 走 HTTP 时实测：`fetch` ✅ 200、XHR ✅ 200、画布**不污染**、console **0 报错**（含 favicon 已用 204 兜掉）。

### 常见问题

| 症状 | 原因 / 怎么办 |
|---|---|
| **双击 `.cmd` 什么都没发生** | 看是不是被安全软件拦了；或者直接**双击 `index.html`**（等效）。仍不行就用 `serve.cmd`，它会打印日志 |
| **下载没反应 / 文件没出现** | 浏览器可能拦了"多文件下载"或把文件丢进了下载目录。看地址栏右侧的下载图标；Chrome 里允许本站点下载即可 |
| **点了「打开」没弹文件对话框** | `file://` 下文件对话框**是正常的**（实测通过）。若真的没弹：换个浏览器，或改用 `serve.cmd`。⚠️ 另外「打开」会**替换当前设计**，会先问你一次 |
| **`serve.cmd` 说端口被占** | 正常 —— 它会**自动换**一个端口并打印实际地址。要固定就用 `serve.cmd 9100` |
| **`serve.cmd` 窗口一闪就没了** | 那是它**失败退出**（比如 20 个端口都占了）。脚本会 `pause` 让你看到原因 |
| **改了文件但页面没变** | `serve.cmd` 发了 `Cache-Control: no-store`，刷新即可；`file://` 下按 `Ctrl+F5` |
| **想确认"直开到底行不行"** | 跑 `node tools\icarui\tests\probe-file-url.js` —— 它把上面那张表**重新实测一遍**并打印每条结果 |

## 📦 「设计包（.icarzip）」—— 素材跟着设计文件一起走（v2.79.0）

> 🚨 **App 侧的导入这一轮没做 —— 端到端还不通。**
> 现在导出的包**只有工具自己读得回来**（自检套件 `verify-pack`）。
> 详见下面「App 侧导入待做」那一节。**不要以为已经能用了。**

### 它治的是什么病

设计文件里的素材是**相对路径**（`assets/xx.png`），而 App 侧导入走 SAF **单文件**
—— 拿不到它旁边的 `assets/`，于是 `designBaseDir` 永远是空 →
**所有素材加载失败** → 由控件（素材图片）拼出来的表盘**只剩空卡片**。
用户报的「画布不显示我做好的内容、显示是空的」就是这个
（[`docs/07-CHANGELOG.md`](../../docs/07-CHANGELOG.md) v1.20.3 查明的真凶）。

App 侧 v1.20.3 加了「选素材文件夹」兜底，但那是**两步操作、体验差**。
本工具的解法：**导出一个自包含的包**，App 侧解开这一个文件就能拿到全部素材。

### 怎么用

点顶栏 **`📦 设计包`** → 下载 `<设计名>.icarzip`。

包的结构（**它就是 zip**，换个扩展名是为了让人一眼认出"这是给 App 导入的"）：

```
<设计名>.icarzip
├── design.json          与「保存」写出的逐字节相同
├── assets/…             只打包这份设计**真正引用到的**素材，路径原样保留
└── manifest.json        icar.pack/1：格式版本 / 设计名 / 素材清单（路径+字节数+CRC32）/ 导出时间
```

**包内路径 = 设计里写的相对路径** —— 解压后目录结构与 `design.json` 的引用天然一致，
App 侧把 `designBaseDir` 指到解压目录就行，**不需要任何路径映射**。

**只打引用的，不把 `assets[]` 全打进去**：素材清单里会留着用户试过又删掉的图，
全打包的话一个 5 个表的盘面可能带出 300 多个文件。收集范围包括
图片节点 / **状态系统三态** / **拼装表的子部件（含嵌套）** / **背景图** / **每一页**。

### ⚠️ 两个必须知道的边界

| 边界 | 说明 |
|---|---|
| **导入的素材不跨会话** | 打包含要原始字节，而浏览器**读不到** `assets/xx.png` 这个路径（`file://` 下 fetch 被 CORS 挡住）。所以字节来自**你导入时选的那个 `File`**。刷新页面 / 重开工具后再导包，那些素材会进 `missing` 清单并**明确报出来**（不静默跳过）——**重新导入一次**即可。内置素材不受影响 |
| **包比压缩过的 zip 大** | 只用 store（不压缩），因为工具是零安装形态、**不许引入需要构建的依赖**（与自写 PNG 编码器同一个理由）。里面的 PNG/JPEG 本来就已经压过了，再 deflate 收益常常是负数 |

**导出后自检**：包造出来之后**立刻读回来**核一遍（条目数 / 每个条目的字节数 / CRC），
而且 CRC 是**拿读出来的字节重算**的 —— 不是比"写入时记的那个数"。
自检不过会**明确弹窗说明**（包照样给你，但告诉你它有问题）。

### App 侧导入待做（**唯一缺口**）

| 环节 | 状态 |
|---|---|
| 工具导出 `.icarzip` | ✅ v2.79.0 |
| 工具自己读回来自检 | ✅ `verify-pack`（111 条断言） |
| **App 侧解开这个包并设 `designBaseDir`** | ❌ **未做** |

App 侧要做的事（**给下一个接手的人**）：

1. 选一个 `.icarzip`（SAF 单文件就行 —— 这正是这个方案的意义）
2. 解压到 `files/design/<时间戳>/`
3. 按 `manifest.json` **逐条校验**（`bytes` + `crc32` 对得上才算解压成功）
4. 把 `designBaseDir` 指到解压目录 → 重新应用

App 现在那条「选素材文件夹」的兜底**仍然可用**，两条路不冲突。

## 为什么是"多文件但双击即用"

这个工具的寿命取决于**改起来快不快**。12 项新功能让单文件涨到 4000+ 行，没法维护，
所以拆成了 `index.html` + `css/` + `js/`。

**关键约束：拆了也必须双击能用。** 已实测（无头 Edge + CDP，`file://` 协议）：

| API | `file://` 下 | 所以 |
|---|---|---|
| 经典 `<script src="js/x.js">` | ✅ 可用（含子目录、顺序保持；24 个 `.js` 全部 200） | 拆多文件没问题 |
| `localStorage` | ✅ 可用 | 用来缓存缩略图与面板折叠状态 |
| `IndexedDB` | ✅ 可用（`indexedDB.open()` 成功） | 但**没用它** —— 素材字节走内嵌 base64，不必进浏览器数据库 |
| `fetch` / `XHR` / ES module | ❌ 被 CORS 挡住 | **一律不用** |

> ⚠️ **v2.90.0 把这张表逐条重测了一遍**（`tests/probe-file-url.js`，无头 Edge + CDP）。
>
> **`IndexedDB` 那行原来是错的**：表里写着"❌ 被拒绝 / 不能把图片存进浏览器"，
> 而实测是 `indexedDB.open()` **成功**（`file://` 下可用）。
> 结论不变（工具确实没用它），但**理由要改**：不是"不能用"，
> 而是"素材字节已经内嵌在 `builtin-data-*.js` 里了，没有理由再存一份进浏览器"。
> 留着这段是因为它是个教训 —— **"以前实测过"不等于"现在还对"**，
> 换浏览器版本、换机器都可能变，所以每一条都该能被一条命令重跑。
>
> 这张表只回答"哪些 API 能用"。**"直开到底功能完不完整"**（素材 / 导出 / 导入 / 拖放）
> 见上面「怎么启动」那一节 —— 结论是**完整**。

| 行为 | 说明 |
|---|---|
| 拖动分组 | 里面所有控件**一起动**（位移完全一致） |
| 旋转 / 缩放分组 | 子控件**跟着转/缩放** |
| **单击**分组内部 | 选中**整个分组** |
| **双击**分组内部 | **下钻**，选中里面那个控件（此后拖动只动它自己） |
| 取消组合 | 子控件回到原层级，**视觉位置不变** |

> **为什么单击选的是整个分组**：用户要的是"组合之后拖动为同时拖动"。
> 如果单击直接选中子控件，拖动只会动那一个，分组就形同虚设。
> 想选组里的某个控件，双击下钻，或者直接在**控件树**里点那一行。

**打组有个前提**：选中的控件不能在"旋转或缩放过的分组"里。
因为 `x/y` 是相对父节点的，换父级时若原父级带变换，位置会跳 ——
而"打组不该让东西跳位置"是基本预期。不满足时工具会说明原因并拦下
（**不会往撤销栈里压一条空操作**）。

## 画布的缩放模式与"内容不被拉伸"

`stretch`（默认）模式下，节点坐标 → 屏幕是**每轴独立**的：
16:10 屏上一个 180×180 的方表，盒子会变成 180/360×2560 × 180/360×1600 = **非正方**。

**但内容不会被拉伸** —— 这和 App 一致：App 的 View 盒子按每轴归一化，
而 `CircularGaugeView` 画圆用 `min(w, h) * 0.36`，所以圆还是圆、字不变形。

工具照做（`uniformMatrix`）：**盒子用真实矩阵画（如实显示拉伸），
内容用 `min(sx, sy)` 的等比矩阵画**。字号也按控件尺寸成比例，
所以 90 单位的小表和 240 单位的大表观感一致。

### ⚠️ 旋转是在**设备空间**施加的（v2.2.0 修正）

顺序是**先排好版、再旋转**：`盒子矩阵 → 画布矩阵 → 绕设备空间中心转 θ`。

如果把旋转写在节点空间（"先旋转、再非等比拉伸"），矩形会被拉成**平行四边形**，
而且内容尺度会随角度变 —— 实测 45° 时外框对角线差 209px、内容放大到 **1.82 倍**。
那正是"旋转时外框歪掉、控件还会变大"。

这与 App 一致：`view.rotation = θ` 转的是**已经排好版的设备盒子**。

## 核心概念

### 控件树 = 图层管理器 + 控件管理器

显示顺序**从上到下 = 从上层到下层**（与 Photoshop 一致），同层里 `z` 大的在上。

每个节点行有：
- `▾/▸` 展开折叠
- 类型图标（◉ 仪表 · ▣ 图片 · T 文字 · ▤ 分组）
- `👁/🚫` 可见性 · `🔒/🔓` 锁定
- **拖到另一行 = 成为它的子节点**；拖到列表底部的虚线框 = 移出分组

### 变换的语义（**必须记住，不然会困惑**）

| 字段 | 语义 |
|---|---|
| `x` / `y` | **相对父节点**的左上角 |
| `w` / `h` | 尺寸（画布单位 0..360） |
| `rotation` | 绕**自身中心**顺时针旋转（度） |
| `scale` | 在 `w/h` **之上**的额外倍率（所以放大 1.5× 不会丢原始尺寸） |
| `alpha` | 不透明度 0..255 |
| `z` | **同一父节点内**的绘制顺序，**大者在上** |

**分组的价值**：让一组控件**统一变换**。想把整个转速表倾斜 15°，转分组就行，
不用逐个改子节点。

### 图层顺序

- `置顶` / `置底`：移到同层最上 / 最下
- `上移` / `下移`：与相邻节点**交换 z**（比加减 1 稳，z 可能不连续）
- 属性面板的 `层级 z` 也可以直接填

### 锁定

锁定的节点**不能拖动/缩放/旋转**（画布上手柄画成灰色），但属性仍可改。
用途：摆好背景与装饰线之后锁上，避免误拖。

### 素材（拖进去就能用）

10 个分类：背景 / 仪表盘 / 指针 / 刻度 / 图标 / 转向灯 / 警告灯 / 汽车品牌 / 装饰 / 自定义。

**导入方式**：点分类上的 `＋`，或把图片**直接拖到素材库**或**画布**上。

> ⚠️ **素材是按相对路径引用的，不存进浏览器。**
> 因为 `file://` 下 IndexedDB 不可用（实测）。
>
> 设计文件里只写 `assets/xxx.png`，**图片本身你要放到设计文件同目录的 `assets/` 下**。
> 工具里能看到预览（用内存里的文件 + 缩略图缓存），App 读到路径才显示真图。
>
> 好处：工具的素材模型与 App 完全一致，不需要"导出时把内嵌图片拆出来"。
>
> ⚠️ **导入时工具会把原始 `File` 对象留在内存里**（v2.79.0）——
> 那是「📦 设计包」唯一能拿到你图片字节的途径（浏览器读不到 `assets/xx.png` 这个路径）。
> 它**不跨会话**：重开工具后导包会提示"请重新导入"。见上方「设计包」一节。

**分类里没有预置图片** —— 车标等素材的版权不属于本项目，请自行导入。

### 状态系统

一个故障灯在真车上有三种外观。用状态系统，**位置、尺寸、层级只写一次**：

```json
{
  "type": "image", "name": "发动机故障灯",
  "x": 300, "y": 40, "w": 24, "h": 24,
  "statePid": "obd.coolant",
  "states": {
    "normal":   { "assetId": "as_off",  "alpha": 77,  "blink": false },
    "warn":     { "assetId": "as_warn", "alpha": 255, "blink": false },
    "critical": { "assetId": "as_crit", "alpha": 255, "blink": true, "blinkMs": 200 }
  }
}
```

在属性面板的「状态系统」组里勾「用状态替换单张图」即可启用。
`statePid` 决定用哪个 PID 的值来切状态；留空则恒定 normal。

> **差异**：App 用 `AlertPulse` 的**迟滞**判定（避免阈值附近乱闪），
> 工具里只做简单比较（预览不需要迟滞，而且迟滞会让"改阈值立刻看到效果"变难）。

### 背景图

| 字段 | 说明 |
|---|---|
| `path` | 相对路径（`assets/xxx.png`），写进设计文件 |
| `fit` | 铺满（裁切）/ 完整显示（可能留边）/ 居中原始大小 |
| `w` / `h` | **尺寸**（画布单位，留空 = 按铺法自动）。填了会在画布上画虚线框 |

> ⚠️ **`w`/`h` 目前只有工具在用** —— App 的 `DesignFile.Background` 只读
> `path` 与 `fit`，会忽略尺寸。要等「阶段 2」。

### 设计分辨率与缩放模式

```
canvas: { designW: 2560, designH: 1600, scaleMode: 0 }
```

**画布宽高比 = 设计宽高比** —— 设计时就能看出目标屏幕的形状。

| scaleMode | 行为 | 适用 |
|---|---|---|
| `0` 拉伸 | 每轴独立拉伸（= **v1 行为，默认**） | 纯仪表盘，能接受轻微变形 |
| `1` 等比适应 | 等比缩放，短边留黑边 | 有圆形元素/图片，**不能变形** |
| `2` 等比铺满 | 等比铺满，超出裁掉 | 背景图，宁可裁也不要黑边 |

> ⚠️ **默认必须是「拉伸」**。改成等比会让存量设计留黑边，用户会以为是 bug。

### 实时数据模拟

点顶栏 `▶ 实时模拟`：给所有绑定的 PID 生成**正弦波**（每条错开相位），
指针、条形、状态灯都会动起来。

做主题时最需要看的就是"数值变了会怎样"，但真车不在手边 —— 没有它只能靠想象。

**指针走的是真弹簧，不是"值 → 角度"的直接映射**（v2.81.0）：

- 实时数据每 16ms 变一次，直接映射就是**硬跳**；补间也追不上（每帧重排、互相打断）。
  弹簧是**状态**不是动画 —— 目标怎么跳，它都只是"被拉了一下"。
- 默认 `k=150 / c=19`（阻尼比 ζ≈0.78，**轻微欠阻尼**：到位时过冲一点再回正，
  "像真针"就来自这一点点过冲。理论过冲约 2.1%，`dt=1/60` 的数值阻尼下实测约 0.65%）。
  参数在 `⚙ 设置` 里可调（**本机偏好，不进设计文件**），
  对话框里会实时显示 `k·dt²` / `c·dt` / ζ 的体检结果。
- 弹簧**只驱动会动的东西**（指针 / 盘面进度弧 / 数字鼓）；
  **读数、条形、状态灯、报警判定一律用真值** —— 报警不该"晚到"。
- `⚙ 设置` 里还有一个 `▶ 试一次自检扫表`：所有指针 0 → 满 → 回位。
  它同时是**让位仲裁**的活例子 —— 扫表期间实时数据不写指针角度
  （参考实现就是这里出的问题：主循环每帧覆写角度，扫表在跑却一帧都看不见）。

### 盘面（刻度 / 数字 / 红区）

`圆表` 与 `G力值` 两种样式的刻度、数字、红区都是**按节点字段算出来的**（v2.81.0），
不需要素材：

| 输入 | 影响 |
|---|---|
| `min` / `max` | 刻度范围、大格步长（自动选"好读"的步长）、数字 |
| `warnLow` / `warnHigh` | **红区**（两段都支持：水温低于 60 也是异常） |
| PID | 单位（写进标签） |
| 控件尺寸 | 半径、字号、数字疏密（挤了就隔一个画） |

量程 / 单位 / 红区**任何一项变了都会重建盘面** —— 不会出现
"页脚写着新单位、盘面还标着旧量程"那种串味（参考实现踩过）。
用 `parts` 自己拼装的表**不受影响**：刻度由你的素材决定。

### 吸附

顶栏常驻的 `🧲 吸附 开/关`。

- **开**：移动/缩放对齐到 15 单位网格
- **关**：停在任意坐标 —— 但**边界夹取仍然生效**（不会跑出画布）

**`verify-pack` 是设计包的套件**，它比较特别：分**三段**，

**`verify-spring` 也是这个路子**（v2.81.0）：`js/spring.js` 是**纯函数**
（弹簧 / 盘面几何 / 数字鼓，不碰 DOM），所以它一半的断言直接在 Node 里
`require` 进来跑 —— 稳定性、过冲、收敛、步长换算这类东西用像素指纹去测
既脆又慢；另一半才在浏览器里钉绘制层的接线（真的调了 `setLineDash` 吗？
指针真的读弹簧吗？让位标志真的生效吗？像素上真的是红的吗？）。

### `probe-file-url.js` —— `file://` 直开能力探针（v2.90.0）

```powershell
node tools\icarui\tests\probe-file-url.js
```

它**不是套件**（文件名是 `probe-*`，不匹配 `verify-*`，不进断言基线、不进 CI 的 60 秒），
而且**退出码恒为 0**。理由：它的产出是**事实**，不是门禁 ——

> `showSaveFilePicker` 在 `file://` 下不存在**不是 bug**（工具根本没用它，
> 导出走 `<a download>`）。把它写成断言会让守卫长期红着，

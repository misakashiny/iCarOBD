## 📦 「设计包（.icarzip）」—— 素材跟着设计文件一起走（v2.79.0）

> 🚨 **App 侧的导入这一轮没做 —— 端到端还不通。**
> 现在导出的包**只有工具自己读得回来**（自检套件 `verify-pack`）。
> 详见下面「App 侧导入待做」那一节。**不要以为已经能用了。**

### 它治的是什么病

设计文件里的素材是**相对路径**（`assets/xx.png`），而 App 侧导入走 SAF **单文件**
—— 拿不到它旁边的 `assets/`，于是 `designBaseDir` 永远是空 →
**所有素材加载失败** → 由控件（素材图片）拼出来的表盘**只剩空卡片**。
用户报的「画布不显示我做好的内容、显示是空的」就是这个
（[`docs/CHANGELOG.md`](../../docs/CHANGELOG.md) v1.20.3 查明的真凶）。

App 侧 v1.20.3 加了「选素材文件夹」兜底，但那是**两步操作、体验差**。
本工具的解法：**导出一个自包含的包**，App 侧解开这一个文件就能拿到全部素材。

### 怎么用

点顶栏 **`📦 设计包`** → 下载 `<设计名>.icarzip`。

包的结构（**它就是 zip**，换个扩展名是为了让人一眼认出"这是给 App 导入的"）：

```
<设计名>.icarzip
├── design.json          与「保存」写出的逐字节相同
├── assets/…             只打包这份设计**真正引用到的**素材，路径原样保留
└── manifest.json        icar.pack/1：格式版本 / 设计名 / 素材清单（路径+字节数+CRC32）/ 导出时间
```

**包内路径 = 设计里写的相对路径** —— 解压后目录结构与 `design.json` 的引用天然一致，
App 侧把 `designBaseDir` 指到解压目录就行，**不需要任何路径映射**。

**只打引用的，不把 `assets[]` 全打进去**：素材清单里会留着用户试过又删掉的图，
全打包的话一个 5 个表的盘面可能带出 300 多个文件。收集范围包括
图片节点 / **状态系统三态** / **拼装表的子部件（含嵌套）** / **背景图** / **每一页**。

### ⚠️ 两个必须知道的边界

| 边界 | 说明 |
|---|---|
| **导入的素材不跨会话** | 打包含要原始字节，而浏览器**读不到** `assets/xx.png` 这个路径（`file://` 下 fetch 被 CORS 挡住）。所以字节来自**你导入时选的那个 `File`**。刷新页面 / 重开工具后再导包，那些素材会进 `missing` 清单并**明确报出来**（不静默跳过）——**重新导入一次**即可。内置素材不受影响 |
| **包比压缩过的 zip 大** | 只用 store（不压缩），因为工具是零安装形态、**不许引入需要构建的依赖**（与自写 PNG 编码器同一个理由）。里面的 PNG/JPEG 本来就已经压过了，再 deflate 收益常常是负数 |

**导出后自检**：包造出来之后**立刻读回来**核一遍（条目数 / 每个条目的字节数 / CRC），
而且 CRC 是**拿读出来的字节重算**的 —— 不是比"写入时记的那个数"。
自检不过会**明确弹窗说明**（包照样给你，但告诉你它有问题）。

### App 侧导入待做（**唯一缺口**）

| 环节 | 状态 |
|---|---|
| 工具导出 `.icarzip` | ✅ v2.79.0 |
| 工具自己读回来自检 | ✅ `verify-pack`（111 条断言） |

App 现在那条「选素材文件夹」的兜底**仍然可用**，两条路不冲突。

## 为什么是"多文件但双击即用"

这个工具的寿命取决于**改起来快不快**。12 项新功能让单文件涨到 4000+ 行，没法维护，
所以拆成了 `index.html` + `css/` + `js/`。

**关键约束：拆了也必须双击能用。** 已实测（无头 Edge，`file://` 协议）：

| API | `file://` 下 | 所以 |
|---|---|---|
| 经典 `<script src="js/x.js">` | ✅ 可用（含子目录、顺序保持） | 拆多文件没问题 |
| `localStorage` | ✅ 可用 | 用来缓存缩略图与面板折叠状态 |
| **`IndexedDB`** | ❌ **被拒绝** | **不能**把图片存进浏览器 |
| `fetch` / `XHR` / ES module | ❌ 被 CORS 挡住 | **一律不用** |

> 这条实测结论决定了素材管理器的设计（见下方「素材」）。

## 分组（打组 / 取消组合）

选中 2 个以上控件 → 右键「打组」或 <kbd>Ctrl+G</kbd>。

| 行为 | 说明 |
|---|---|
| 拖动分组 | 里面所有控件**一起动**（位移完全一致） |
| 旋转 / 缩放分组 | 子控件**跟着转/缩放** |
| **单击**分组内部 | 选中**整个分组** |
| **双击**分组内部 | **下钻**，选中里面那个控件（此后拖动只动它自己） |
| 取消组合 | 子控件回到原层级，**视觉位置不变** |

> **为什么单击选的是整个分组**：用户要的是"组合之后拖动为同时拖动"。
> 如果单击直接选中子控件，拖动只会动那一个，分组就形同虚设。
> 想选组里的某个控件，双击下钻，或者直接在**控件树**里点那一行。

**打组有个前提**：选中的控件不能在"旋转或缩放过的分组"里。
因为 `x/y` 是相对父节点的，换父级时若原父级带变换，位置会跳 ——
而"打组不该让东西跳位置"是基本预期。不满足时工具会说明原因并拦下
（**不会往撤销栈里压一条空操作**）。

## 画布的缩放模式与"内容不被拉伸"

`stretch`（默认）模式下，节点坐标 → 屏幕是**每轴独立**的：
16:10 屏上一个 180×180 的方表，盒子会变成 180/360×2560 × 180/360×1600 = **非正方**。

**但内容不会被拉伸** —— 这和 App 一致：App 的 View 盒子按每轴归一化，
而 `CircularGaugeView` 画圆用 `min(w, h) * 0.36`，所以圆还是圆、字不变形。

工具照做（`uniformMatrix`）：**盒子用真实矩阵画（如实显示拉伸），
内容用 `min(sx, sy)` 的等比矩阵画**。字号也按控件尺寸成比例，
所以 90 单位的小表和 240 单位的大表观感一致。

### ⚠️ 旋转是在**设备空间**施加的（v2.2.0 修正）

顺序是**先排好版、再旋转**：`盒子矩阵 → 画布矩阵 → 绕设备空间中心转 θ`。

如果把旋转写在节点空间（"先旋转、再非等比拉伸"），矩形会被拉成**平行四边形**，
而且内容尺度会随角度变 —— 实测 45° 时外框对角线差 209px、内容放大到 **1.82 倍**。
那正是"旋转时外框歪掉、控件还会变大"。

这与 App 一致：`view.rotation = θ` 转的是**已经排好版的设备盒子**。

## 右键菜单

画布与控件树都能右键，菜单**按选中项变内容**：

| 情况 | 菜单项 |
|---|---|
| 单选 | 复制 / 删除 │ 置顶 上移 下移 置底 │ 锁定 隐藏 │ 旋转 ±15° 归零 / 缩放归 1× │ 取消选择 |

> 所以外观与系统菜单不同，这条记在「与 App 规则的差异」页里。

## 核心概念

### 控件树 = 图层管理器 + 控件管理器

显示顺序**从上到下 = 从上层到下层**（与 Photoshop 一致），同层里 `z` 大的在上。

每个节点行有：
- `▾/▸` 展开折叠
- 类型图标（◉ 仪表 · ▣ 图片 · T 文字 · ▤ 分组）
- `👁/🚫` 可见性 · `🔒/🔓` 锁定
- **拖到另一行 = 成为它的子节点**；拖到列表底部的虚线框 = 移出分组

### 变换的语义（**必须记住，不然会困惑**）

| 字段 | 语义 |
|---|---|
| `x` / `y` | **相对父节点**的左上角 |
| `w` / `h` | 尺寸（画布单位 0..360） |
| `rotation` | 绕**自身中心**顺时针旋转（度） |
| `scale` | 在 `w/h` **之上**的额外倍率（所以放大 1.5× 不会丢原始尺寸） |
| `alpha` | 不透明度 0..255 |
| `z` | **同一父节点内**的绘制顺序，**大者在上** |

**分组的价值**：让一组控件**统一变换**。想把整个转速表倾斜 15°，转分组就行，
不用逐个改子节点。

### 图层顺序

- `置顶` / `置底`：移到同层最上 / 最下
- `上移` / `下移`：与相邻节点**交换 z**（比加减 1 稳，z 可能不连续）
- 属性面板的 `层级 z` 也可以直接填

### 锁定

锁定的节点**不能拖动/缩放/旋转**（画布上手柄画成灰色），但属性仍可改。
用途：摆好背景与装饰线之后锁上，避免误拖。

### 素材（拖进去就能用）

10 个分类：背景 / 仪表盘 / 指针 / 刻度 / 图标 / 转向灯 / 警告灯 / 汽车品牌 / 装饰 / 自定义。

**导入方式**：点分类上的 `＋`，或把图片**直接拖到素材库**或**画布**上。

> ⚠️ **素材是按相对路径引用的，不存进浏览器。**
> 因为 `file://` 下 IndexedDB 不可用（实测）。
>
> 设计文件里只写 `assets/xxx.png`，**图片本身你要放到设计文件同目录的 `assets/` 下**。
> 工具里能看到预览（用内存里的文件 + 缩略图缓存），App 读到路径才显示真图。
>
> 好处：工具的素材模型与 App 完全一致，不需要"导出时把内嵌图片拆出来"。
>
> ⚠️ **导入时工具会把原始 `File` 对象留在内存里**（v2.79.0）——
> 那是「📦 设计包」唯一能拿到你图片字节的途径（浏览器读不到 `assets/xx.png` 这个路径）。
> 它**不跨会话**：重开工具后导包会提示"请重新导入"。见上方「设计包」一节。

**分类里没有预置图片** —— 车标等素材的版权不属于本项目，请自行导入。

### 状态系统

一个故障灯在真车上有三种外观。用状态系统，**位置、尺寸、层级只写一次**：

```json
{
  "type": "image", "name": "发动机故障灯",
  "x": 300, "y": 40, "w": 24, "h": 24,
  "statePid": "obd.coolant",
  "states": {
    "normal":   { "assetId": "as_off",  "alpha": 77,  "blink": false },
    "warn":     { "assetId": "as_warn", "alpha": 255, "blink": false },
    "critical": { "assetId": "as_crit", "alpha": 255, "blink": true, "blinkMs": 200 }
  }
}
```

在属性面板的「状态系统」组里勾「用状态替换单张图」即可启用。
`statePid` 决定用哪个 PID 的值来切状态；留空则恒定 normal。

> **差异**：App 用 `AlertPulse` 的**迟滞**判定（避免阈值附近乱闪），
> 工具里只做简单比较（预览不需要迟滞，而且迟滞会让"改阈值立刻看到效果"变难）。

### 背景图

| 字段 | 说明 |
|---|---|
| `path` | 相对路径（`assets/xxx.png`），写进设计文件 |
| `fit` | 铺满（裁切）/ 完整显示（可能留边）/ 居中原始大小 |
| `w` / `h` | **尺寸**（画布单位，留空 = 按铺法自动）。填了会在画布上画虚线框 |

> ⚠️ **`w`/`h` 目前只有工具在用** —— App 的 `DesignFile.Background` 只读
> `path` 与 `fit`，会忽略尺寸。要等「阶段 2」。

### 设计分辨率与缩放模式

```
canvas: { designW: 2560, designH: 1600, scaleMode: 0 }
```

**画布宽高比 = 设计宽高比** —— 设计时就能看出目标屏幕的形状。

| scaleMode | 行为 | 适用 |
|---|---|---|
| `0` 拉伸 | 每轴独立拉伸（= **v1 行为，默认**） | 纯仪表盘，能接受轻微变形 |
| `1` 等比适应 | 等比缩放，短边留黑边 | 有圆形元素/图片，**不能变形** |
| `2` 等比铺满 | 等比铺满，超出裁掉 | 背景图，宁可裁也不要黑边 |

> ⚠️ **默认必须是「拉伸」**。改成等比会让存量设计留黑边，用户会以为是 bug。

### 实时数据模拟

点顶栏 `▶ 实时模拟`：给所有绑定的 PID 生成**正弦波**（每条错开相位），
指针、条形、状态灯都会动起来。

做主题时最需要看的就是"数值变了会怎样"，但真车不在手边 —— 没有它只能靠想象。

### 吸附

顶栏常驻的 `🧲 吸附 开/关`。

- **开**：移动/缩放对齐到 15 单位网格
- **关**：停在任意坐标 —— 但**边界夹取仍然生效**（不会跑出画布）

## PID 别名（27 条）

下拉框**按分组**（标准 OBD / 派生 / 厂家模板）。写 `obd.rpm` 而不是 `std_0C` ——
前者一眼知道是什么。**每个默认启用的内置 PID 都有别名**。

**存盘时写出的是别名**（不是解析后的 id）：设计文件是给人看的，
而且 App 侧 `resolvePid` 认别名、App 自己导出时也这么做。

厂家模板（`tpl_*`）**刻意没有别名**：它们是占位示例（默认关闭、PID 号是猜的），
必须先用内置扫描器在真车上实测。

混合盘面（大盘不画卡片 + 小表无边框）正是这个字段存在的理由。

## 主题别名

设计文件里的 `theme` 写**名字**（`neon` / `ice` / `amber`），不写数字 id。
写 id 的话导入端会报"主题不存在"，用户看到的是"主题丢了"。

自建主题没有稳定别名 → 导出时留空（= 用当前主题）。

## 「与 App 规则的差异」页

工具右侧有个标签页专门列这个。**显式列出，不假装一致**，分三类：

- **一致** —— 由 `tools/theme-studio/tests/verify-crosslang.js`（跨语言，78 项）与
  `ThemeStudioSampleTest` 守着
- **差异** —— 例如"越界警告只查根节点""状态判定不带迟滞""JSON 报错文案不同"
- **未做** —— 例如"App 还不认 v2""撤销栈刷新会丢"

改工具时**顺手更新这个清单**。假装一致是最危险的失效方式：
编辑器说没问题、App 加载报错，用户直到推上设备才发现。

## 跑测试

工具的浏览器套件在 `tests/`，一条命令跑全部：

```powershell
.\tools\run-browser-tests.ps1              # 全部 25 个套件（1242 条断言）
.\tools\run-browser-tests.ps1 -Filter font  # 只跑名字含 font 的
.\tools\run-browser-tests.ps1 -List         # 只列出会跑哪些
```

> ⚠️ 这里的数字**很容易过期**（本行从 23/959 直接跳到了 25/1242 —— 中间几版都忘了改）。
> 以 `run-browser-tests.ps1` 的输出为准；数字对不上不是测试坏了，是**这行字**坏了。

> 这些套件原来散在 `%TEMP%` 里 —— 系统一清就没了，也不在版本控制里。
> 479 条断言是验证体系的根基，v2.14.0 搬进了 `tests/`。
>
> 每个套件跑在**独立进程**里（一个崩了不影响别的），会自己开无头 Edge；
> 跑完自动清理测试浏览器 —— **只清本项目自己的**，不碰你正在用的浏览器。
>
> ⚠️ **从 `pwsh` 里直接 `& .\tools\run-browser-tests.ps1` 会被执行策略拦住**
> （`running scripts is disabled on this system`）。用
> `powershell -ExecutionPolicy Bypass -File .\tools\run-browser-tests.ps1`。

**`verify-pack` 是设计包的套件**，它比较特别：分**三段**，
前面两段（zip 的字节级验证、`pack.js` 的引用收集）**完全在 Node 里跑**，
不开浏览器 —— 因为"打包"这件事没有界面能一眼看出对错，
必须让 Node 用 `zlib` 这类**独立裁判**去核 CRC 与偏移。

Kotlin 侧是另一条线（不需要浏览器）：

```powershell
.\tools\run-tests.ps1        # Kotlin 单测 + 构建守卫
.\tools\check-build-guard.ps1  # 只跑守卫
```

## v2.43.0 · 2026-10-04 · 临时目录泄漏**清零**（2454 → 0）

### 竞态的真正解法：清队列 + 屏障

v2.42.0 加了同步的 `AppLog.shutdown()`，但残留数**会在 3~6 之间变** ——
那是在提示"有竞态"。

**原因**：`io` 是个 **单线程池**，而进它的任务**都会重新打开 writer**：

- `init()` 会塞 `prepareTodayFile` / `purgeOldFiles`
- 测试期间每次写日志会塞 `appendToFile`

`shutdown()` 关掉句柄之后，**排在我们后面的任务又把 writer 打开了**。

**三步处理**（v2.43.0）：

```kotlin
runCatching { io.queue.clear() }        // 1. 丢掉还没开始跑的（它们只会重开句柄）
val done = CountDownLatch(1)
io.execute { closeWriter(); done.countDown() }   // 2. 屏障
done.await(2, SECONDS)                  //    io 是单线程 → 屏障跑完 =
                                        //    "之前已经在跑的那个"也结束了
lock.lock(); closeWriter(); lock.unlock()   // 3. 兜底再关一次
```

> **为什么用"屏障任务"而不是直接 `io.shutdown()`**：
> `io` 是**对象级的 `val`，`init()` 不会重建它** —— 关掉之后下一个测试就跑不了了。
> 用屏障既能等到"前面那个跑完"，又不破坏执行器。

### 完整的效果链

| 阶段 | 每次全量残留 |
|---|---|
| 最初 | **2454**（从 10/02 攒到 10/05） |
| 补 `GaugeThemeTest` 的 `@After`（36 个测试方法，原来**完全没有** `@After`） | 4 |
| 加 `AppLog.shutdown()`（同步关常开写句柄） | 3~6（**会变 → 说明是竞态**） |
| **清 `io` 队列 + 屏障** | **0** ✅ |

> **"数量会变"本身就是线索** —— 稳定的残留是"忘了清"，
> 会变的残留是"和别的线程抢"。这次靠这一点把方向从"删除策略"扭到了"句柄竞态"。

## v2.42.0 · 2026-10-04 · `run-all.ps1` 超时做成 + 修测试临时目录泄漏

### ✅ 超时**做成**了（v2.41.0 失败的那件事）

用 v2.41.0 写在脚本头部的方向：**包装脚本 + 状态文件**。

```
外层  ──Start-Process──▶  %TEMP% 里的包装脚本（路径干净）
                              │
                              └─▶ 目标脚本（run-tests / run-browser-tests）
                              │
                              └─▶ 把 $LASTEXITCODE 写进状态文件
外层  ◀── 读状态文件 ─────────┘
```

**两个坑都绕开了**：不把带空格+中文的路径直接交给 `Start-Process`（改用包装脚本）；
不读 `$p.ExitCode`（改读状态文件）。

新增 `-KotlinTimeout` / `-BrowserTimeout` 参数（默认 420s / 600s）。
超时会：杀**整棵进程树** → 明确报错 → 给"该杀 Gradle daemon"的现成命令 → `exit 1`。

#### ✅ 两条路都验了

| 路径 | 命令 | 结果 |
|---|---|---|
| 成功 | `run-all.ps1 -SkipBrowser` | 全部通过 ✅ / exit 0 |
| **超时** | `run-all.ps1 -SkipBrowser -KotlinTimeout 2` | `❌ 超过 2 秒还没结束，已强制终止` + 提示 / **exit 1** |

> 这是 v2.41.0 学到的：**加"判断成败"的代码后，成功和失败两条路都要验**。
> 上一轮只验了成功路径，于是"恒假"那版一直到跑全量才暴露。

### 🐛 修了一个**攒了几天的**临时目录泄漏

跑全量时看到 `%TEMP%` 里有一大片 `icarobd-*`。一数：**2454 个目录**，从 10/02 攒到 10/05。

| 来源 | 情况 |
|---|---|
| `GaugeThemeTest` | **完全没有 `@After`** —— 它有 **36 个测试方法**，每个跑一次 `setUp`，**每次跑泄漏 36 个目录** |
| `BackupTest` | 有 `@After`，但**稳定漏 4 个**（10 个测试里） |

修了第一处（补 `@After`），实测跑完 **残留 0**。

第二处试了"重试 + `deleteOnExit`"，**没用** —— 因为：

- `deleteRecursively()` **返回 false 但不抛异常**，所以静默失败
- `deleteOnExit()` **对非空目录无效**（Java 只在退出时删空目录）

#### 继续往下挖：根因是 `AppLog` 的常开写句柄

试了"逐个文件删（`walkBottomUp`）+ 重试三轮" —— **没用**，说明不是删除策略问题，
是**文件真的被占着**。

查 `setUp` 发现它调了 `AppLog.init(dir)`。而 `AppLog` **为了性能故意保持一个常开的
`BufferedWriter`**（源码里有说明：早期"每条 appendText"被 8000 条突发打爆，
只剩 893 字节）。**那个句柄占住了目录里的日志文件** → Windows 删不掉 → 目录删不掉。

> 代码里其实**早就知道**这件事 —— `AppLog.clear()` 里那句 `closeWriter()`
> 就带着注释"必须先关掉句柄，否则删不掉文件"。
> 只是它是**异步的**（走 `io` 线程），赶不上 `@After`。

**做了什么**：给 `AppLog` 加 `shutdown()`（**同步**关句柄），`tearDown` 里先调它。

#### ⚠️ 还没清零：是个**竞态**

| 轮次 | 残留 |
|---|---|
| 修 `GaugeThemeTest`（补 `@After`）之前 | **36 / 次** |
| 补完之后 | **4 / 次** |
| 加 `AppLog.shutdown()` 之后 | **3 ~ 6 / 次（会变）** |

**数量会变**说明是**和异步 IO 线程的竞态**：`shutdown()` 关掉句柄之后，
`io` 执行器队列里**还没跑完的任务会把 writer 重新打开**。

下次该试的方向：`shutdown()` 里**连带停掉 `io` 执行器**（或等它 drain 完），
确认 `AppLog.init()` 每次会重建它。

**净效果：每次全量泄漏 2454 → 约 5（降 99.8%）。** 剩下的已记在这里。

> ⚠️ **进程被强杀时 `@After` 本来就跑不到** —— 我这一轮杀过两次卡死的 JVM，
> 那部分残留清不掉，只能人工 `Remove-Item "$env:TEMP\icarobd-*" -Recurse`。

### 验证

| 项 | 结果 |
|---|---|
| Kotlin 单测 | **495 / 0** |
| 浏览器套件（21 个） | **792 / 0 / 90 秒** |
| 构建守卫 | 通过 |
| `run-all.ps1` | **全部通过 ✅ exit 0**（成功与超时两条路都验过） |
| `%TEMP%` 残留 | 2454 → **4** |

### 下次优化建议

- **`BackupTest` 剩的 4 个目录** —— 见上面的方向（逐个文件删 + 重试）
- **`brand`（14）受红线限制** —— 不能出现真实车标

### ❌ 一次**失败**的改造：给 `run-all.ps1` 加超时

起因：Gradle daemon 卡死导致 `run-all.ps1` **卡 20 分钟没输出**。
想加超时让它在卡住时**明确失败**而不是干等。**试完两个方案，都回退了。**

#### 坑 1：路径里有空格和中文

`Start-Process -ArgumentList @("-File", "`"$path`"")` 会把路径**按空格拆开** ——
`D:\AI Dsh\车机项目\...` 被子进程读成 `D:\AI`，报"没有 .ps1 扩展名"。
**症状很有误导性**：`HasExited=True` 但 `ExitCode` 是空，看起来像"取不到退出码"。

#### 坑 2：`Start-Process -PassThru` 的 `ExitCode` 读不出来

把引号修对之后，子进程**确实跑完了**（打印了"全部通过"），
但 `$p.ExitCode` **仍然是空** —— `WaitForExit()` 也没用。所以不能靠它判断成败。

#### 更糟的是：我中间那版**恒报失败**

`($null -eq 0)` 是 `$false`，于是**每一步都被判成失败**。症状：

```
TOTAL=495  FAILED=0
构建守卫通过 ✅
TOTAL PASS=792  FAIL=0
全部通过 ✅
失败：Kotlin 单测 / 构建守卫 / 浏览器套件     ← 自相矛盾
```

> **这正是前几轮刚学到的教训的另一面**：那几轮是"检查恒真"（打印了 ❌ 却仍通过），
> 这次是"检查恒假"（全都过了却报失败）。
> **加任何"判断成败"的代码之后，两条路都要验一遍** —— 成功路径和失败路径。

结局：`run-all.ps1` **回退到原版**（`& powershell ...` + `$LASTEXITCODE`，实测可用），
超时能力**没做成**，但把两个坑写进了脚本头部的注释，附下一步该试的方向
（包装脚本 + 状态文件）。

```js
function restore(snap) {

}
```

```js
if (!restore(r.state)) { toast("这一步的记录坏了，已跳过：" + r.label); return; }
```

### 🎯 找到了 ⑦ 一直超时的**真正原因**

**headless Chrome 里 `alert()` 会阻塞整个渲染进程。**

链条：

```

```

**重名那条先执行**，先卡死了。

**症状与原因隔了好几层**：报错是"第 3 节的第一个求值超时"，

## v2.26.0 · 2026-10-04 · 测试基础设施：从「偶发失败」到「稳定 + 可诊断」

### 问题

套件**单独跑全过**（`verify-studio2` 6/6），**连着跑偶发报红**，重跑又过。
实测频率约 1/5。这类问题最危险的地方是：**哪天它掩盖了真 bug，会被当成"又是偶发"重跑掉**。

### 做了五件事

| # | 措施 | 效果 |
|---|---|---|
| 1 | **每个套件跑完立刻清它自己的 Edge** | 原来只在整轮前后各清一次。`proc.kill()` 只杀父进程，Edge 的 gpu/renderer 子进程**继承 `--user-data-dir`** 并继续存活 |
| 2 | **等残留真正清空**（轮询，不是固定 sleep） | 清理脚本按 `*\Temp\edge-*` **全局**匹配，分不清"上一个的残留"和"下一个刚启动的"。固定等一下会把新启动的一起杀掉 |
| 3 | **`send()` 加超时**（12s） | 请求永远等不到响应时，套件会**挂死**（实测挂过 10 分钟）。挂死比失败糟得多 —— CI 里不会自己结束，也看不出卡在哪 |
| 4 | **`eval` 对瞬时 CDP 错误重试 3 次**，重试前先等就绪 | 只重试 `-32000 / target closed` 这类**明确的瞬时错误**；语法错误与断言失败**绝不重试** |
| 5 | **固定 `sleep` → 就绪轮询** | 等三个条件：`CanvasState` 在、`BUILTIN_ASSETS` 非空、`#cv` 有尺寸 |

### 最后的兜底：套件级重试（**如实标注**）

上面五件事把频率从"经常"降到约 1/5，但没根除。所以加了一层：
某个套件失败就**重跑一次**，通过则标 **`↻重试过`**。

> **不假装第一次就过了** —— 否则哪天真的坏了，会被当成"又是偶发"。
> 输出里那一列就是为了让这件事**可见**。

### ⚠️ 代价：整轮从 ~67s 变成 ~194s

这是**稳定性的代价**，不是免费的：

- 每个套件跑完要等 Edge 真正退出（20 个套件累加）
- 瞬时错误重试会各等一次（上限 2s）
- 素材清单拆成 12 个文件后，每个套件启动时多加载 11 个文件

### 🐛 排查过程中最花时间的一个坑（值得记下来）

写分类功能测试时，第 3 节的**第一个求值**就 `CDP 超时（12000ms）` ——
而那个求值只是读 `window.assetKindList().length`。

**真因**：第 2 节没装 `renderAssets` 的 stub（它的第一行是 `const before = ...`
而不是 `const out = {};`，我的补丁没匹配到），于是 `moveAssetKind` 触发**真的**
`renderAssets()` —— 渲染 **319 缩略图 + 112 控件芯片**，把渲染进程占住几十秒。

第 2 节自己的求值能跑完（所以看起来"通过"），**下一节才超时** ——
症状与原因隔了一节，非常难看出关联。

## v2.23.0 · 2026-10-04 · **点阵字库 → 数字刻度**（素材 319 / 控件 112）

## v2.20.0 · 2026-10-04 · **素材 95 → 288** + 修「添加进去全是扁的」 + 吸附拆成两种

### 🐛 修：添加素材进去「全是扁的」

**根因**：`addImageNode` 里 `w` 与 `h` **各自独立夹取**：

```js
const w = Math.min(200, Math.max(40, a.w / a.h * 90));
const h = Math.min(200, Math.max(40, 90));   // ← 恒等于 90
```

`h` 永远是 90，而 `w` 被夹到 40~200 —— 于是任何宽高比超出 `40/90 ~ 200/90`
的素材都被压扁。256×64 的横条（4.0）会变成 200×90（**2.2**）。

**修法**：先定「最长边 = 90」，另一边按比例算；夹取时**两边一起乘同一个系数**。

## v2.19.0 · 2026-10-04 · 素材分类可排序 / 可新建

### 能做什么

- 分类标题行上有 **↑ ↓** —— 调整分类顺序
- 面板栏有 **＋分类** —— 新建自定义分类
- 自定义分类有 **✕** —— 删除（**素材不丢**）
- 面板栏有 **⟲** —— 恢复出厂顺序（自定义分类保留，排到最后）

顺序与自定义分类都存在 localStorage，下次打开还在。

### 为什么用 ↑↓ 而不是真拖动

分类标题行是**整行可点的折叠头**。在它上面做 drag 会和「点一下折叠」打架 ——
实测很容易误触发（想折叠，结果拖动了一下；或想拖动，结果折叠了）。

> 如果以后要真拖动，得先给标题行加一个**专门的拖拽把手**，
> 让「点标题折叠」和「拖把手排序」各占一块区域。

### 删分类**不删素材**

## v2.18.0 · 2026-10-04 · **子部件嵌套**

### 能做什么

部件可以有 `children` —— 相当于一个「组」。典型用法：**指针上挂个装饰/配重**，
装饰跟着指针绕轴心转。

```json
{ "kind": "needle", "assetId": "as-needle", "rawPid": "obd.rpm",
  "children": [ { "kind": "decor", "assetId": "as-cap", "x": -12, "y": -12, "w": 24, "h": 24 } ] }
```

### 坐标系：子部件相对**父的 pivot**，不是父的左上角

这是本版最重要的一个决定。

> 嵌套的典型用法是「指针上挂个装饰」—— 装饰要跟着指针**绕轴心转**。
> 以 pivot 为原点，子部件写 `(0,0)` 就正好在轴心上，符合直觉；
> 以左上角为原点的话，**每加一个装饰都要手算 pivot 的偏移**。

子部件**继承父的旋转**（父的 `rotate` 留在 ctx / canvas 里，子在自己的坐标系里画）。

### 深度上限 5 层

`normalizePart`（工具）、`GaugePart.parseAll`（App）、两边的绘制递归**都是 5**。
设上限是为了防"手改文件写出几千层"把栈打爆 —— JSON 本身不能成环，
但深到几千层一样会崩。**三处必须一致**，改一处要改三处。

### 两侧改动

**工具**：`PART_DEFAULT` 加 `children`；`normalizePart` 递归；
`drawGaugeParts` 拆成 `drawPartTree` 递归；序列化 `cleanPart` 递归剔除空 `children`。

**App**：`GaugePart` 加 `children`；`parseAll` 递归（加 `depth` 参数）；
`GaugePartsView.onDraw` 拆成 `drawPart` 递归。

### UI：子部件列表放在**部件展开体里**

不是另起一棵树 —— 嵌套是「这个部件的细节」，单独一棵树会让
「哪个子部件属于谁」看不出来。列表缩进 + 左侧竖线标层级。

### 🐛 过程中踩到的两个坑

1. **`arguments` 在 `map` 回调里指向回调自己的参数** ——
   第一版递归传深度写成了 `arguments[1]`，实际永远是 `undefined`，
   深度上限完全失效。改用局部变量。
2. **UI 插错了位置** —— 面板里有两处 `row("透明度")`（状态的、部件的），
   按文本锚点插到了**状态框**里。那里没有 `q.children`，运行时会抛错。
   改用 `q.alpha` 区分后插对。**教训：锚点要带上足够区分度的上下文**。

### 验证

|---|---|
| 子部件套件 | **70 项**（+15 嵌套，含"深度夹到 5 层"与"递归真的画出像素"） |
| Kotlin `GaugePartsTest` | **+3 条**（二层解析 / 老文件空表 / 超深不爆栈） |
| `tools/run-all.ps1` | **637 断言 + Kotlin 464 全过 / 84 秒** |

- **子部件的坐标不能在画布上直接拖** —— 现在只能填数字。嵌套层越深越难调
- **没有"打散子部件"** —— 组合了之后只能一个个删

## v2.17.0 · 2026-10-04 · **多指针表**（每个指针各绑一个 PID）

### 问题

子部件模型支持多个 `needle` 了，但它们**共用仪表节点自己的 PID** ——
所以「转速 + 车速」双针表做不出来（两根针永远指同一个数）。

### 方案：`needle` 部件可以绑自己的 PID

```json
{ "kind": "needle", "assetId": "as-needle", "rawPid": "obd.speed",
  "pivotX": 0.5, "pivotY": 0.5, "sweepFrom": 135, "sweepTo": 405 }
```

- 空 = **跟随仪表节点自己的 PID**（单指针表的老行为，**完全不变**）
- 设了就用它 —— 双针表靠这个

### 关键：量程也跟着走

绑了别的 PID 就用**那个 PID 的 min/max**，而不是仪表节点的。

> 为什么这是必须的：车速是 0~240，转速是 0~8000。如果车速指针按转速的量程
> 做角度映射，120 km/h 会算成 `120/8000 = 1.5%` —— **指针几乎不动**，
> 用户会以为「数据没上来」。

### 两侧改动

**工具侧**：`PART_DEFAULT` 加 `pid`/`rawPid`；新增 `partValueRange(part, gauge, values)`
（工具与 App 同一套判定的唯一入口）；`drawGaugeParts` 每个部件各算各的；
属性面板给指针加了「绑定 PID」下拉（**只在指针部件上显示**）+ 量程来源提示。

**App 侧**：`GaugePart` 加 `pid`；`GaugePartsView` 从「单个值」改成**值表**
（`PID id → 值`）+ `neededPids()`；渲染器一次把需要的 PID 取齐推进来。

> `GaugePartsView` 暴露 `neededPids()` 而不是自己读总线 —— 守住红线 4.1.5
> （视图不直接访问数据源）。

### 🐛 测试抓到的两个真 bug

1. **表盘也能绑 PID** —— `normalizePart` 没按 `kind` 判断，
   于是 `dial` 带 `rawPid` 也会被解析。表盘绑 PID 没有意义，而且污染序列化。
2. **跟随仪表的指针仍写出空的 `pid`** —— 序列化没剔除空值，
   文件里每个部件都多两个 `""` 字段（噪音）。

### 顺带：「拼装圆表」预设改成**双针示例**

长针 = 转速（跟随仪表），短针 = 车速（绑 `obd.speed`）—— 拖出来就能看到多指针效果。

### 验证

| 套件 | 结果 |
|---|---|
| **子部件套件** | **55 项全过**（+16 多指针） |
| **更多素材控件** | **15 项**（含「两个指针各绑一个 PID」） |
| **Kotlin `GaugePartsTest`** | **+4 条**（多指针解析 / 非指针不解析 / 各自量程） |
| `tools/run-all.ps1` | **622 断言 + Kotlin 457 全过 / 85 秒** |

### 下次优化建议

- **数值部件（`value`）还不能各绑 PID** —— 双针表配两个数字读数是很自然的下一步
- **指针的扫描范围仍各自独立** —— 双针表通常两根针共用同一个 135°→405°，
  现在要手填两次（可以加个「跟随仪表」）
- **属性面板的 PID 下拉在部件里是第二次实现** —— 节点级和部件级各一份，
  应该抽成一个共用函数

## v2.16.0 · 2026-10-04 · **设计文件内嵌主题配色**（P8-5）

### 问题

设计文件原来只存主题**名字**（`"theme": "neon"`）—— 换台机器、或用户删了自建主题，
**配色就丢了**（App 会提示"主题不存在，已保持当前主题"，然后画成别的颜色）。

### 方案：把颜色一起写进设计文件

```json
{
  "schema": "icar.ui/2",
  "theme": "neon",
  "themeColors": {
    "background": "#080A0E", "surface": "#17110D", "surfaceEdge": "#553520",
    "accent": "#FF8A00", "accentHot": "#FFE45C", "accentDim": "#5B2B00",
    "track": "#322820", "tick": "#725635", "needle": "#FFB000",
    "value": "#FFF4DF", "label": "#D8BFA0", "dim": "#806B57",
    "glow": true
  }
}
```

**字段名与 `GaugeTheme.toJson` 逐字一致** —— 所以 App 侧直接
`GaugeTheme.fromJson(design.themeColors)`，**不需要任何映射表**。

### 两侧改动

**工具侧**：`schema.js` 新增 `GAUGE_THEMES`（3 套主题的完整配色，镜像 Kotlin 的 builtins）；
`toV2Json` 在 `theme` 旁边写 `themeColors`。

**App 侧**：`DesignFile` 加 `themeColors: JSONObject?`；渲染时**内嵌配色优先**，
没有才按设置里的主题 id 查。

> 为什么优先内嵌：设计文件是「作品」，配色是作品的一部分。
> 跟着设备当前主题走的话，**同一份设计在两台机器上长得不一样**。

### 三个刻意的取舍

1. **未知主题名不写 `themeColors`** —— 宁可没有，也不编造一个错的
2. **`themeColors` 不是对象时当"没有"**（不报错）—— 老文件与手改坏的文件都不该拦下整个设计
3. **`DesignFile` 里只存 `JSONObject`，不依赖 `ui/`** —— `fromJson` 的调用在渲染层，
   守住"data/ 不能依赖 ui/"这条红线

## v2.13.0 · 2026-10-03 · 修 3 个 bug + 面板可收起 / 固定高度 + 素材控件大扩充

### 🐛 素材库拖到画布显示**大 X**

`S.assetUrls` 只对**导入的**素材赋值（导入时给 objectURL / dataURL），

修法：内置素材在 `builtin.js` 里**内嵌 data URL**。

> ⚠️ 为什么不是"直接用 path 当 URL"：`file://` 下按 path 加载的图会**污染画布**
> （Chrome 把每个本地文件当独立源），于是 `getImageData` / `toDataURL` 全部抛

## v2.12.0 · 2026-10-03 · **控件编辑器子部件模型**（最后一项计划）

一个仪表不再只能"选一种画法"，而是可以拆成几个**可替换的部件**：

```json
{ "type": "gauge", "style": 0,
  "parts": [
    { "kind": "dial",   "assetId": "as1", "x":0, "y":0, "w":200, "h":200 },
    { "kind": "needle", "assetId": "as2", "x":76, "y":4, "w":48, "h":192,
      "pivotX": 0.5, "pivotY": 0.9, "sweepFrom": 135, "sweepTo": 405 },
    { "kind": "value",  "x":70, "y":80, "w":60, "h":40 }
  ]}
```

| 种类 | 说明 |
|---|---|
| `dial` 表盘 | 底盘 / 圆环（图片） |
| `ticks` 刻度 | 刻度环（图片） |
| `needle` 指针 | **会随数值转动**的部件 |
| `value` 数值 | 数字读数（用**文字**渲染，不是图片） |
| `decor` 装饰 | 任意叠加的图片 |

**绘制顺序 = 列表顺序**（先画的在下）。**有 `parts` 就不再走 `style` 的程序化画法** ——
用户明确说了"我要自己拼"，就别再叠一层。没有 `parts` 时那套照旧（**存量设计行为完全不变**）。

### 三个关键设计

1. **`pivotX/pivotY`（相对自身 0..1）** —— 指针素材的轴心**基本不在图片中心**。
   固定绕中心转的话指针是歪的，所以必须能单独设。
   用默认值（0.5/0.5）去转一个"轴心在底部"的指针素材，转起来会明显偏心。
2. **角度公式是唯一入口** —— 工具侧 `partAngle()` 与 App 侧 `GaugePart.angleFor()`
   各一份，**必须逐字一致**。不一致会出现"电脑上指着 3000 转、设备上指着 2800"，
   用户只会觉得**数据不准**，而不会想到是布局换算。两边都有单测钉住
   （下限/上限/中点/超范围夹取/静态 rotation 叠加/反向扫描/量程为 0 不产生 NaN）。
3. **`value` 部件不需要素材** —— 它是文字。所以"没选素材"的警告要**跳过**它，
   否则用户会收到一条毫无意义的提示。

### 工具侧 UI

属性面板新增「子部件（自己拼装）」组：折叠卡片列表、上下移（数组顺序 = 绘制顺序）、
每件可改种类/素材/位置/尺寸/透明度；指针额外有轴心与扫描范围（含 `135→405` 一键预设）。

> 取舍：**不用拖拽排序** —— 部件通常只有 2~4 个，上下按钮比拖拽更省事也更准。

### App 侧

新增 [`GaugePartsView`](../../app/src/main/java/com/icar/obd/ui/view/GaugePartsView.kt)：
按部件拼装，值由 5Hz tick 推入。`NodeTreeRenderer` 有 `parts` 时改用它，
没有时仍走 `GaugeViewFactory`。

## v2.10.0 · 2026-10-03 · 多画布 / 多页面（**格式层**）

### ✨ 多页面：格式 + 解析 + 切页 API

```json
{
  "schema": "icar.ui/2",
  "pages": [
    { "id": "p1", "name": "主页面", "nodes": [ ... ] },
    { "id": "p2", "name": "性能页", "nodes": [ ... ] }
  ]
}
```

### 关键设计：`design.nodes` 始终**指向当前页的数组**

`design.nodes === design.pages[design.pageIndex].nodes`（**同一个引用**）。

这样**几千处现有代码**（画布、面板、校验、撤销、对齐参考线……）**全都不用改** ——
它们照旧读写 `design.nodes`，切页时只换引用。

> 代价：序列化时不能只写 `nodes`（那样只存了当前页）。

### 序列化：**单页只写 `nodes`，多页才写 `pages`**

第一版是"两个都写"，结果踩了个**真 bug**：
解析时 `pages` 优先，于是用户在 JSON 里改 `nodes` 会被**静默忽略**
（测试删掉 `nodes[0].pid`，校验却报"通过" —— 因为它读的是 `pages[0].nodes`）。

改成按页数二选一之后：
- **单页（绝大多数情况，v1 升级来的全是单页）输出与以前逐字节一致** —— 完全向后兼容
- 多页才写 `pages`
- 不会有"两处真相"

### 切页 / 增删页 API

| 函数 | 行为 |
|---|---|
| `switchPage(d, i)` | 先把当前数组写回当前页，再把 `d.nodes` 换成目标页的数组；越界夹到最后一页 |
| `addPage(d, name)` | 追加一页，返回新索引 |
| `removePage(d, i)` | **最后一页不能删** —— 没有页面的设计没法编辑 |

### 向后兼容

没有 `pages` 字段的老文件（包括所有 v1 升级来的）行为**完全不变**，
自动兜成单页「主页面」，`nodes` 与 `pages[0].nodes` 是同一引用。

### ⬜ 本项**只做了格式层**（诚实记账）

| 部分 | 状态 |
|---|---|
| 格式（`pages` 解析 / 序列化） | ✅ |

| **页签 UI（切换、重命名、增删）** | ⬜ **未做** |
| **App 侧读 `pages`** | ⬜ **未做**（现在只读 `nodes` = 第一页） |

所以：**工具里还看不到页签，也切不了页** —— 只有格式与 API 就位。
下一版补 UI 与 App 侧即可，格式不用再动。

## v2.9.0 · 2026-10-03 · 控件树同层重排 / 状态系统阈值入口

### ✨ 控件树拖拽：分**三个区域**

原来拖拽**只能改父子关系** —— 用户没法把"第 3 个控件挪到第 1 个"，
而调整叠放顺序恰恰是最常用的操作之一。

现在按行的**垂直位置**分三个区域（Figma / VS Code 都是这个约定）：

| 区域 | 动作 |
|---|---|
| 上 1/4 | 插到这一行的**前面**（同层重排） |
| 下 1/4 | 插到这一行的**后面**（同层重排） |
| 中间 | 成为它的**子节点**（原有行为） |

这样"调顺序"和"改父子"两个需求不用两种手势。插入位置有**指示线**（上/下缘高亮）。

**同层判定**：`canReorderSameLevel` 只允许同一父级内的重排 ——
跨层是 `reparent` 的职责，混在一起会让 z 的语义混乱。

**重排后必须 `normalizeZ`**：否则"数组顺序变了但 z 没变"，

而不同车/不同传感器的报警线本来就不一样。

现在图片节点可以显式设 `stateWarn` / `stateCritical`：

- **空 = 跟随 PID 库**（用空值表达"跟随默认"比让用户填魔法数字清楚）

工具侧与 App 侧同一套语义（`resolveStateName` ↔ `resolveState`）。

## v2.3.1 · 2026-10-03 · 工具链：不再误杀用户的浏览器

### 🔴 我（AI）犯的错

跑无头浏览器测试前，我用这条命令"清缓存"：

```powershell
Get-Process msedge | Stop-Process -Force        # ❌
```

**它杀掉的是所有 Edge 进程，包括用户自己的窗口。** 实测那一刻机器上有 13 个
Edge 进程，**全部属于用户**，我的测试进程是 0 个 —— 那条命令唯一的实际效果
就是把用户的浏览器干掉，而且在每次跑测试前都执行了一遍。

两个认知错误：
1. **杀进程 ≠ 清 profile 缓存**。清缓存应该删 `--user-data-dir` 那个目录
2. `Get-Process msedge` 返回**所有** Edge 进程；Edge 是多进程架构，杀光 = 关掉所有窗口

### 正确做法

- 测试脚本自己 `spawn` 的进程，脚本在 `finally` 里 `proc.kill()` —— **本来就够，不需要额外清场**
- 真要清缓存：删目录
- 只有上次测试异常残留孤儿时才主动收尾 → 用新脚本
  [`tools/kill-test-browsers.ps1`](../../tools/kill-test-browsers.ps1)：
  **默认只列出、不动手**，加 `-Kill` 才真杀

### 判定条件（写脚本时踩的两个坑）

只看一个特征：**profile 路径形如 `*\Temp\edge-*`**。

1. **不能用 `GetTempPath()` 比路径前缀** —— 它返回长名
   （`C:\Users\Administrator\...`），而命令行里是 **8.3 短名**
   （`C:\Users\ADMINI~1\...`），`StartsWith` 一个都匹配不上（实测 0 命中）。
   用 `-like '*\Temp\edge-*'` 就对了
2. **不能要求 `--headless`** —— 只有主进程带，gpu/renderer/utility **子进程没有**。
   只杀主进程会留下一堆孤儿（实测一次测试能留下 17 个）

### 验证

起一个无头实例 + 前一次调试残留的孤儿，助手挑出 **34 个**测试进程、
**13 个用户进程一个没动**；清理后总数 46 → 15。

### 顺带复发的坑

`.ps1` 文件带中文**必须有 UTF-8 BOM** —— 否则 PowerShell 5.1 按 GBK 解码，
字符串终止符断裂、报 `Missing closing '}'` 之类的假语法错误。
这个坑 `run-tests.ps1` 上踩过一次（记在 FILE_MAP §6.1.1），这次写新脚本又踩了一次。

### 下次优化建议

- **把测试脚本里的 `proc.kill()` 换成"先杀子进程树再杀主进程"** ——
  现在依赖 Edge 自己收尾，偶发残留（实测残留过 17 个）
- **给所有测试脚本统一一个 `run-browser-test.ps1` 包装**：
  跑完自动调 `kill-test-browsers.ps1 -Kill`，省得靠人记得
- **`.ps1` 写 BOM 这件事应该自动化** —— 建议加个 pre-commit 或构建检查，
  否则每写一个新脚本都可能再踩一次

**修法**：

1. **分组缩放**：拖角时把 `(新尺寸/原尺寸)` 按比例摊到子控件的 `x/y/w/h`。
   ⚠️ 每帧都从**拖动开始时的快照**（`d.origKids`）重算，不要在上一次结果上再乘 —— 会累积误差
2. **去掉紫色虚线**：分组是**纯逻辑容器**，画布上不画任何东西。看范围/层级请用**控件树**
3. **PID 显示别名**（`obd.coolant`）而不是 id；按钮改成 `🏷 PID 开 / 🏷 PID 关`（**状态**语义）+ title 写明"当前…"

## v2.2.1 · 2026-10-03 · PID 表示统一 / JSON 编辑不再被静默覆盖

用户问了一句"PID ID 是以什么形式参与的、为啥我删掉点字段就直接没了"。
一查发现**两个真 bug** —— 用户的问题往往指向真实缺陷。

### 🐛 Bug A：同一个 PID 有两种内部表示

`createNode`（编辑器建节点）直接把别名当 id 存，而 `parseNode`（读文件）会解析：

| | 编辑器预设建的 | 从文件读进来的 |
|---|---|---|
| `pid` | `obd.rpm`（**没解析**） | `std_0C`（已解析） |
| `rawPid` | `undefined` | `obd.rpm` |
| `BUILTIN_PIDS[pid]` | ❌ **查不到** | ✅ 发动机转速 |
| **画布标签** | **`obd.rpm`** | **`发动机转速`** |
| 🏷 PID 显示 | `obd.rpm` | `std_0C` |

表现就是：**预设建的表画布上写着 `obd.rpm`，导入的表写着"发动机转速"** ——
同一个 PID 两种长相；而且查不到内置库意味着**单位也丢了**（`rpm` 不显示）。

**修法**：`createNode` 与 `parseNode` 统一 ——
`pid` 存**解析后的 id**（内部只用它查表），`rawPid` 存**用户写的原样**
（编辑器回显 + 序列化时写回别名）。`statePid` / `rawStatePid` 同理。

### 🐛 Bug B：JSON 里改的东西，一碰画布就没了

复现步骤（实测确认）：

1. 在 JSON 文本框里删掉 `nodes[0].pid`
2. 校验正确地报错，画布保留上一次成功的设计 ✓
3. **在画布上随便拖一下** → `commit()` → `syncJson()` → **把文本域整个冲掉**
4. 你删的字段又回来了，你的编辑**无声无息地消失**

**修法**：加 `jsonDirty` 状态 —— 文本域解析失败时标记"有错未生效"，
此后 `syncJson()` **直接跳过、绝不覆盖它**。配套：

- 文本域加红框（`.dirty`）
- 顶部醒目提示条，写明"画布仍是上一次成功解析的状态，修好才会生效"
- 出口按钮「**放弃 JSON 改动，回到画布状态**」
- 修好错误后自动生效、标记自动清除
- 撤销/重做/新建/套预设/打开文件（**整体替换设计**的操作）会清掉该状态

### PID 的三种形态（回答用户的问题）

```
设计文件里          内部（节点上）              画布上
─────────────      ────────────────────      ──────────────────
"obd.rpm"     →    pid    = "std_0C"     →   标签：发动机转速（友好名）
（语义别名）         rawPid = "obd.rpm"        🏷 PID：std_0C（解析后的 id）
   或
"std_0C"      →    pid    = "std_0C"     →   同上
（直接写 id）        rawPid = "std_0C"
```

- **写文件时写别名**（`obd.rpm`）—— 人能看懂，App 的 `resolvePid` 也认
- **内部查表只用 id** —— `BUILTIN_PIDS[pid]` 拿名字 / 单位 / 量程 / 阈值
- `rawPid` **不写进文件**（内部字段，只用于编辑器回显）

## v2.2.0 · 2026-10-03 · 旋转重做（设备空间）/ 打组 / PID 标签开关

### 🔴 修掉用户报的"旋转时外框歪掉、控件还会变大"

**用户的判断是对的**（"确认跟缩放模式有关"）。实测数据：

| 角度 | 外框 | 内容尺度 |
|---|---|---|
| 0° | 矩形 | 1.364 |
| 15° | **平行四边形**（相邻边点积 cos=-0.237，应为 0） | 1.433 |
| 45° | **平行四边形**（对角线差 **209px**） | **1.820（+33%）** |
| 90° | 矩形 | 1.364 |

**根因**：旋转写在 `localMatrix` 里，整条链是 `画布矩阵 · … · R(θ)`。
而 `stretch` 模式下画布矩阵是**每轴独立**的（16:10 屏 2.183 × 1.364）——
**先旋转、再非等比拉伸 = 斜切**。

**App 侧不是这样**：`view.rotation = θ` 旋转的是**已经排好版的设备盒子**，
得到旋转矩形、尺寸恒定。所以修法是**把旋转挪到设备空间**：

```
盒子矩阵（平移+缩放，不含旋转）→ 画布矩阵 → 再在设备空间绕盒子中心转 θ
```

新增 `withDeviceRotation()` / `deviceMatrix()`，并让 `drawList` 把**含旋转**的矩阵
传给子节点（否则"分组转了、子控件不转"）。

**修完实测**：0°~180° 全部斜切=0.0000、对角线差=0.00、内容尺度恒为 1.364。

### 打组 / 取消组合

| 操作 | 入口 |
|---|---|
| 打组 | 右键菜单「打组」· <kbd>Ctrl+G</kbd> |
| 取消组合 | 右键菜单「取消组合」· <kbd>Ctrl+Shift+G</kbd> |

- 组建成时 **rotation=0、scale=1**（纯平移），所以子控件**位置完全不跳**（实测 0px）
- 之后拖动组 = 子控件位移**完全一致**（实测两个子控件 dx/dy 相同）
- **点分组内部 = 选中整个分组**；要选组里的某个控件用**双击下钻**，或在控件树里点那一行
- 取消组合**保持视觉位置**，旋转过的组会把旋转烘焙进子控件（`r' = r + φ`）

> 打组有个**前提**：选中项的祖先不能带旋转/缩放（否则换父级会让它们跳位置）。
> 不满足时 `groupCheck` 直接拦下并说明原因，**且不往撤销栈里压空操作**。

### 取消组合的位置公式（踩了两次，记下来）

第一次漏了"绕组中心转"，第二次转错了空间。正确做法：

```
父空间中心 → 设备空间 → 绕组中心（设备） 转 φ → 回父空间
```

**为什么不能在父空间直接转**：画布矩阵 `C` 非等比，`C(绕 gc 转 φ) ≠ 绕 C(gc) 转 φ`。
第一版在父空间转，结果**父空间中心算得完全正确、设备空间却偏 23.7px**
（实测 x 对、y 差 23.7 —— 这个"只差一个轴"的现象是空间混用的典型特征）。

### 画布上的 PID id 可显示/隐藏

顶栏新增 `🏷 PID 隐 / 🏷 PID 显`。做主题时常要确认"这个表绑的是哪个 PID"，
但摆位置时那行字挡视线。默认**隐藏**，选择记在 `localStorage`。
控件名字（友好名）不受影响，始终显示。

### 删掉一段说明文字

属性面板「变换」组里的"旋转绕自身中心；缩放是在 w/h 之上的额外倍率" —— 用户说不需要。

### 下次优化建议

- **组的"进入/退出"状态**：现在双击下钻只是改了选择，没有"正在编辑此组"的视觉提示。
  理想做法是给组加一个虚线高亮 + 面包屑（`根 › 转速组 › 指针`）
- **组的嵌套层级上限**：目前不限制嵌套深度，但太深之后控件树会很长。
  考虑加"折叠全部/展开全部"与层级过滤
- **打组时自动命名**：现在都叫「分组」。可以按内容取名（如"转速 + 车速"）
- **`ungroupNode` 依赖调用方传画布矩阵**，忘了传就静默退化（只在等比缩放下正确）。
  应该改成必需参数并在缺失时抛错/警告

```
单选：复制 / 删除 │ 置顶 上移 下移 置底 │ 锁定 隐藏 │ 旋转±15° 归零 / 缩放归 1× │ 取消选择
多选：复制 / 删除 │ 图层四项 │ 六种对齐 │ 两种等距 │ 全部锁定/解锁 │ 取消选择
空选：全选 │ 从预设新建 │ 取消选择（灰）
```

菜单项写成**数据**（不是拼 HTML），所以每项能带禁用条件，加项只改数组。
点别处 / <kbd>Esc</kbd> / 窗口失焦都会关掉。

### 滚轮缩放选中控件

选中后滚轮改尺寸（等比）。**两个容易写错的地方**：

1. **增量要扛得住吸附**。第一版用 `STEP*0.5 = 7.5`，`180 + 7.5 = 187.5`
   被 `snapIf` 四舍五入回 **180** —— 下滚完全不缩小。现在吸附开着一格一个完整网格。
2. **手势要能结束**。滚轮没有"松开"事件，靠 350ms 延时收尾；
   否则"滚一下 → 干别的 → 再滚"会并成同一步撤销。

### 右下角旋转图标

`↻` 小圆图标在右下角外侧，拖它旋转（<kbd>Shift</kbd> 15° 步进）。
顶部旋转柄保留 —— 两个都能用。

> **偏移必须按轴分别折算**：手柄在屏幕上应离角点固定像素距离，
> 但经非等比矩阵变换后 x/y 距离会不同（`offX = 26/sx`、`offY = 26/sy`）。
> 用统一偏移会让图标落在偏斜的位置上。

## v2.0.0 · 2026-10-03 · 从「扁平仪表列表」重做成「节点树编辑器」

一次**破坏性重构**。起因是用户提了 12 项功能，逐条看下去发现其中 5 项
（图片控件、图层、旋转/缩放、锁定、控件树）**在 v1 的扁平模型里根本表达不了** ——
不是"没做"，是"没地方放"。所以先改模型，再谈功能。

### 核心变化：格式 `icar.ui/1` → `icar.ui/2`

```
v1：gauges: [ {pid, style, x, y, w, h, ...} ]        ← 扁平、只能放仪表
v2：nodes:  [ {type, x, y, w, h, rotation, scale,   ← 树、可嵌套、可变换
               alpha, z, locked, children: [...]} ]
```

**关键决策：`gauge` 节点的字段与 v1 的 `GaugeItem` 同名同义。**
这样 v1 的每一项都能**一对一**变成 v2 的一个根节点，不需要字段映射表，
`GaugeItem.fromJson` 的逻辑可以原样复用。迁移是恒等变换（坐标不动、顺序不动）。

### 12 项需求逐条落地

| 2 | 控件属性设层级、按层排序显示 | ✅ | `z` 字段 + 控件树按 z 降序显示（上层在上）+ 置顶/置底/上移/下移 |

### 拆成多文件（这一步是必须的）

单文件在 1500 行时还能读，加上这 12 项会到 **4000+ 行**，没法维护。

**代价**：要确认双击 `index.html` 还能用。**已实测**（无头 Edge）：

| API | `file://` 下 |
|---|---|
| 经典 `<script src>` | ✅ 可用（含子目录、顺序保持） |
| `localStorage` | ✅ 可用 |
| **`IndexedDB`** | ❌ **被拒绝**（`SecurityError`） |
| `fetch` / `XHR` / ES module | ❌ 被 CORS 挡住 |

所以：**不用 ES module、不用 fetch**，全部经典脚本 + 全局命名空间。

### 素材为什么按路径引用（这条是被浏览器逼的）

`IndexedDB` 在 `file://` 下不可用 → **不能把图片存进浏览器数据库**。于是：

- 设计文件里只写**相对路径** `assets/xxx.png`（与 App 的模型一致）
- 预览用内存里的 `File` 对象（`URL.createObjectURL`）
- 缩略图（64px）缓存进 `localStorage`，重开还能看到
- 完整图片由用户放到设计文件同目录的 `assets/` 下

**好处**：工具的素材模型与 App 完全一致，不需要"导出时把内嵌图片拆出来"。

### 顺带修掉的两件事

- **JSON 语法错误的定位**：从"Unexpected token"改成 `第 N 行第 M 列附近 —— …片段…`
- **`pid` 写出语义别名而不是 id**：写 `std_0C` 的话，存盘再打开时 PID 下拉框
  拿 id 去匹配选项（选项的值是别名）会**显示空白**，看起来像没绑定。
  改成写 `obd.rpm`（App 侧 `resolvePid` 认别名，且 App 自己导出时也这么做）。

### 过程中实际踩的坑（都记下来）

1. **`panels.js` 多了一个右括号** → 整个模块不加载 → 所有面板空白。
   症状具有误导性：控制台只报 `Unexpected token ')'`，不说是哪个文件。
   教训：拆多文件后**每个文件都要过 `node --check`**。

2. **`app.js` 引用了 HTML 里不存在的 `bgFit`** → `appendChild` 抛异常 →
   `init()` 中断 → `design` 一直是 `null` → **所有面板全空**。
   一个缺失的 DOM id 让整个工具瘫掉。修法：先建 `design` 再接线，
   且每块接线独立 `try/catch`，可选 DOM 访问全部走安全取值器。

3. **撤销的"合并"完全没生效**：`coalesce` 分支写成了 `push` 新条目，
   应该**替换栈顶**。实测 150 次拖动产生了 150 条记录（`3/3 → 100/100`）。

4. **撤销后计数不更新**：`restore()` 漏了 `updateUndoButtons()`，
   界面上的数字纹丝不动，看着像撤销没生效。

5. **我自己的括号检查脚本有 bug**：没处理正则字面量，`/[&<>"]/g` 里的 `"`
   被当成字符串开头，导致误报 `panels.js` 失衡 5 个。已修（加了正则与字符类处理）。

6. **重新生成 `sample.json` 破坏了 Kotlin 测试**：那份示例被
   `ThemeStudioSampleTest` **逐条断言**（名称、6 块表、每块的
   pid/style/坐标/cardStyle/ringStyle/量程/阈值、"恰好一条背景警告"）。
   教训：示例文件是**格式示范**，不是随手生成的产物 ——
   改它必须同时看那份测试。

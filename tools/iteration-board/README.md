# 迭代看板

项目根目录双击「打开迭代看板.cmd」，自动重新生成快照并用默认浏览器打开。需要现有 Node.js 和 Git；无需安装依赖、启动服务或连接网络。

看板集中显示改进前后、当前任务、审查结论、验证层级、协作计划、最近版本日志和工作区改动。点击原文在同一页面阅读，可搜索文档。历史版本仅提取标题与原文，不把旧验证计入当前任务。Git 改动列表包括未跟踪文件；diff 统计只含已跟踪的未暂存改动，不代表全部工作量或验收结果。

## 2026-10-17 功能增强（T-Mgr-P002-BOARD-02）

在可读性修正之后，继续补了六项**功能**：

| # | 功能 | 解决什么 |
|---|---|---|
| 1 | **待办与优先级** | 用户问"接下来做什么"时看板给不了答案 —— `02_开发计划.md` 只是索引，**真正的待办表在 `docs/03_开发进度与问题清单.md`**。现在自动解析那张表，按 **P0 → P1 → P2 → P3 → 后置** 分组 |
| 2 | **大文档目录 + 搜索高亮** | 最长文档 100KB+，塞进一个 `<pre>` 没法定位。现在按 `##`/`###` 生成目录可跳转；搜索词在正文**高亮并自动滚到第一处** |
| 3 | **文档按用途分类** | 47 份平铺找不到重点。现在分「协作文件 / 现行规范与专题 / 验证记录 / 项目文档 / 工具文档 / 历史归档」六组 |
| 4 | **自上次生成以来的变化** | 每次打开都要重新理解进展。用 `localStorage` 记上次生成时间，显示期间新增提交数与未提交改动数 |
| 5 | **当前构建卡片** | 看板此前不展示"装的是哪个包"。现在显示版本 / 构建时间 / 大小 / SHA256；**APK 比最后一次提交还新时给出提示** |
| 6 | **小优化** | `1`-`5` 切页签、`/` 聚焦搜索、`Esc` 清空；文档页「复制全文」；**文档正文里的 `.md` 链接可点**（原来只是死文本）；最近打开过的文档加粗 |

### 待办解析的口径

只扫 `docs/03_开发进度与问题清单.md` 里 `## BUG与后续优先级` 之后的表格行，
匹配 `| ID/优先级 | 未完成内容 | 下一步/阻塞 |` 三列；优先级取 ID 里 `/` 之后那段。
表格格式变了会导致解析不到 —— 页面会提示"没有解析到待办行"，不会静默留白。

### 关于构建卡片的一个提醒

`newerThanHead` 判断是「APK 修改时间 > 最后一次提交时间」。它只说明**构建发生在提交之后**，
**不代表构建用的是当前未提交的代码** —— 以实际构建来源为准，别把它当"包是新的"的证明。

## 每轮如何更新

详细记录仍写 04_交接状态.md，任务、计划和专题仍以原有权威文档为准。04_交接状态.md 顶部只保留一个 `iteration-summary` 代码块，提供简洁摘要；新一轮替换该块，历史完整报告保留。Codex 维护最新审查结论，DeepSeekHarness 更新实施变化和运行证据，保持“待审查”或已记录的返工结论，不自行宣布通过。

代码块内容为 JSON：

```json
{
  "updated": "2026-10-11（Asia/Shanghai）",
  "taskId": "必须等于 03_当前任务.md 中的任务 ID",
  "title": "这轮改善什么",
  "review": "待审查 / 未通过 / 审查通过",
  "before": "原来的用户体验或问题",
  "after": "当前已经实现的变化；未实现须说清楚",
  "remaining": "剩余验收缺口与下一步",
  "verification": [{"name": "单元测试", "state": "未运行", "detail": "命令、退出码及证据位置"}],
  "docs": [{"file": "04_交接状态.md", "change": "更新了什么"}]
}
```

生成器会检查任务 ID 和必填字段。摘要仍是人工提炼的阅读辅助，不自动证明代码、测试、真车验证或审查通过。更新后运行生成器，再运行项目文档守卫。生成的 index.html 含本地文档快照，不提交、不上传；模板和生成器可以纳入 Git。

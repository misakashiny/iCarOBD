# 迭代看板

项目根目录双击「打开迭代看板.cmd」，自动重新生成快照并用默认浏览器打开。需要现有 Node.js 和 Git；无需安装依赖、启动服务或连接网络。

看板集中显示改进前后、当前任务、审查结论、验证层级、协作计划、最近版本日志和工作区改动。点击原文在同一页面阅读，可搜索文档。历史版本仅提取标题与原文，不把旧验证计入当前任务。Git 改动列表包括未跟踪文件；diff 统计只含已跟踪的未暂存改动，不代表全部工作量或验收结果。

## 每轮如何更新

详细记录仍写 04_交接状态.md，任务、计划和专题仍以原有权威文档为准。04_交接状态.md 顶部只保留一个 `iteration-summary` 代码块，提供简洁摘要；新一轮替换该块，历史完整报告保留。Codex 维护最新审查结论，DeepSeekHarness 更新实施变化和运行证据，保持“待审查”或已记录的返工结论，不自行宣布通过。

代码块内容为 JSON：

```json
{
  "updated": "2026-10-11（Asia/Shanghai）",
  "taskId": "必须等于 03_当前任务.md 中的任务 ID",
  "title": "这轮改善什么",
  "review": "待审查 / 未通过 / 审查通过",
  "before": "原来的用户体验或问题",
  "after": "当前已经实现的变化；未实现须说清楚",
  "remaining": "剩余验收缺口与下一步",
  "verification": [{"name": "单元测试", "state": "未运行", "detail": "命令、退出码及证据位置"}],
  "docs": [{"file": "04_交接状态.md", "change": "更新了什么"}]
}
```

生成器会检查任务 ID 和必填字段。摘要仍是人工提炼的阅读辅助，不自动证明代码、测试、真车验证或审查通过。更新后运行生成器，再运行项目文档守卫。生成的 index.html 含本地文档快照，不提交、不上传；模板和生成器可以纳入 Git。
